# 分割して進める試験（dev・inv の 6 回）の結果

再実行の手順は [[room-split-test-procedure]]。反映先は `workflow-kit/project-structure.md` の「複数回に分けて進める」。

## いま

- 6R → 論点出し → 判断と承認 → 工程 → 工程 → 終える、の 6 回の新しいセッション（`claude -p` を毎回起動し直す）を、依頼「続きです。次は <工程> まで。」だけで、`dev` `inv` とも同じ観点（置き場、範囲、記録、裏取り）で進められた。
- 引き継ぎの正本は `ai/docs/log.md`・`ai/docs/decisions.md`・`ai/work/plan/` の 3 つ。会話の記憶には頼らない。
- 見つかった不具合 7 点のうち、1〜5 は手順書に反映済み（成果物名は Project 名、6R の変更先は type の構成要素の名前、承認後は 6R を書き換えない、論点出しだけの回でも `log.md` を更新、並行しない）。再試験で 1〜3 の解消を確認した（3 回目まで）。
- 未解決: 回収後にマウントが残る件（並行しなくても起きる。Zed の remote server がつかむ場合があり、Zed を再起動して `room umount` すると外れる）。4 回目以降は再試験していない。

## 明細（2026-11-05〜06）

部屋 `room-myenv`（internal）、Project は `sample_splitdev` と `sample_splitinv`。人の役は、エージェントが判断・承認の文を書いて演じた。

### 流れ（6 回）

| 回 | 依頼（要旨） | dev（csvinfo） | inv（uv と pip-tools） |
|---|---|---|---|
| 1 | 計画を立てて。今回は 6R まで | 6R。論点出しは省略 | 6R + 末尾に選択式の質問 |
| 2 | 続きです。論点出し | 11 件の論点表（`work/plan/issues.md`） | 11 件の論点表 |
| 3 | 判断を返す・承認・最初の工程まで | 書き戻し・承認・環境（`pyproject.toml` `uv.lock`）。「確」の項目を使い捨てで実施 | 書き戻し・承認・`question.md` `sources/`。「確」（`uvx` が動くか）を実施 |
| 4 | 次は src／findings まで | 本体。6R にない 2 点を決めて `decisions.md` に記録 | `findings/` と代表例 2 本の実測 |
| 5 | 次は tests／checks まで | テスト 13 件 | 突合表・未確認。**前回の自分の計測値（30 秒）が再現せず撤回**し、`findings.md` は触らず `checks.md` に訂正 |
| 6 | 最後。報告まで、終える前にやることも | README・報告・`close.md` | 報告・`close.md` |

### 同じ観点で動けたか: 動けた

- 引き継ぎ: 前の回を再説明させずに続いた。
- 範囲: 「その先にはまだ進まない」を 6 回とも守った。
- 記録: 判断は `decisions.md`、状態は `log.md`、承認は `6r.md`。判断の来歴（誰が決め、AI が何を決めたか）も区別して書かれた。
- 裏取り: 事実と推測の分離、未確認の明記、実測の撤回が、分割しても保たれた。
- 終わり方: 依頼文に書かなくても `ai/out/close.md`（完了条件の照合、未解決の振り分け、【汎用】候補、人が行うこと）を書いた。

### 足りなかった点と対応

| # | 点 | 原因 | 対応 |

| 2 | inv の試験用スクリプトが `out/…/src/`（inv に `src/` は無い。正は `ai/work/scripts/`） | 6R の「変更先の洗い出し」に `src/` が書かれ、引き継がれた | 同上（6R の変更先は type の構成要素の名前で書く） |
| 3 | dev の 6R が承認後に `仮` へ戻った | AI が 6R に進捗を書き、次の `start` が `仮` に戻す仕様に当たった | 同上（承認後は 6R を書き換えない。進捗は `log.md`） |

### 修正の再試験

新しい Project（`sample_split2inv` `sample_split2dev`）で 1〜3 回目を再実行した。

- 成果物名: 両方とも Project 名。点 1 は解消。
- inv の試験用スクリプト: `ai/work/scripts/`、計算出力は `findings/` と `work/raw/`。`src/` は作られなかった。点 2 は解消。
- 6R: 承認後も `正式` のまま（3 回目まで）。点 3 は解消。
- 回収の不具合: 前の回の後にマウントが残り、dev の 3 回目が起動しなかった（`room umount --area myenv` で外して再実行）。点 5 は並行しなくても起きる。
- 副作用: inv の部屋の `ai/work/.venv/` に依存が入った（回収で `ai/work/` ごと戻るので容量だけの問題）。
- 未試験: 4 回目以降。
