# 同じ部屋で Project を並行して開くとき何が共有されるか

## 冒頭
同じ Area の複数の Project を、同じ部屋（WSL のディストリビューション）で並行して `room start` したときに、何が共有され、何が Project ごとに分かれ、どこで衝突するかを、自分で説明できるようにする。前提: 部屋は Area ごとに1つ（`room-<Area>`）で、同じ Area は同じ境界（`boundary:`）の単位。確認状況: コードの読み取りと単体テストのみ。実機の並行 start は未確認。
近いノート: [[ai-isolated-work-room]]。

## ダイジェスト
- 状況: 同じ Area の Project A を動かしている間に、Project B も触りたい。後から start した B が「マウントがすでにある」で止まっていた。
- 原因: start が「部屋のどんなマウントも残っていてはいけない」という確認をしていた。部屋は Area ごとなので、残っているのは常に同じ Area の別 Project だった。
- 解決: 確認を「自分の Project のマウントが残っていないか」に変え、並行を既定で許可した。部屋の共有ファイルは、動いている AI に空の状態を見せない置き換え方式で更新する。

## 基礎知識
- 部屋は Area ごとに1つで、Project はその中の `/mnt/room/<Project>` にマウントされる。マウントされるのは、その Project の `ai/` だけ。
- 並行すると、部屋の AI は `/mnt/room/` の下で、ほかの Project の `ai/` を読める・書ける。同じ Area は同じ境界という前提なので、見えても越境ではない。Area をまたぐ共有は、ディストリビューションが別なので起きない。
- 何が共有され、何が分かれるか。

| 対象 | 範囲 | 並行したときの注意 |
|---|---|---|
| `/mnt/room/<Project>`（`ai/`） | Project ごと | 衝突しない |
| `/home/ai/gitdirs/<Project>`（部屋のローカル git） | Project ごと | 衝突しない |
| `ai/ctx/`、`ai/records/` | Project ごと | 衝突しない |
| `~/shared`（共有知の写し） | 部屋に1つ | 後続の start が入れ替える |
| `/usr/local/bin/git`（git のラッパー） | 部屋に1つ | 後続の start が置き換える |
| `~/.claude.json`、`~/.claude/settings.json`、`~/.claude/CLAUDE.md` | 部屋に1つ | 動いている Claude も書く |
| Windows 側のリポジトリのコミット | 1つ | 同時に終わると `index.lock` でぶつかる |

- 共有ファイルは、横で完成させてから置き換える（`~/shared` は `~/shared.new` に展開して入れ替える）。削除してから作り直すと、動いている AI が無い瞬間を読む。
- 自分で説明するときの一言: 「部屋は Area で1つ。Project のデータは分かれているが、部屋の道具と設定は全員で共有する。だから start は自分のマウントだけを見て、共有ファイルは置き換えで更新する」

## チェックリスト
| 症状 | 原因 | 対処 |
|---|---|---|
| 後から start が「この Project のマウントが残っている」で止まる | 同じ Project の前回の終了で、マウントが残っている | `room umount --area <Area>` で外す。ただし部屋の全マウントが外れるので、並行中は使わない |
| 動いている AI が `~/shared` の手順書を読めなかった | 後続の start が入れ替える最中だった | 読み直す。start は同じタイミングで行う |
| 先に終わった Project が「マウントが残っている」で失敗する | 部屋の全マウントを確認していた（修正済み） | 自分のマウント点だけを確認する |
| コミットが `index.lock` で失敗する | 2つの start が同時に終わった | 回収は済んでいるので、あとでコミットし直す |
| `ls /mnt/room` にほかの Project 名が見える | 並行の仕様 | 同じ Area の Project だけを並行する |

## 補足
| 案 | 内容 | 判断 |
|---|---|---|
| 1つの Project にまとめる | 並行が要らない | 入力と終了時期が揃わず、使えなかった |
| Project ごとにディストリビューション | 分離が強い | 導入が Project の数だけ要る。今回は選ばない |
| 同じ部屋で並行（採用） | 手間が少ない | 同じ Area の Project に限る。運用の約束: `~/shared` は最新に揃え、start は同じタイミングで行い、足すときは動いているセッションを止める |

## 要確認事項
- 実機で2つの start を並行したときの動作（`~/shared` の更新中に動いている AI が止まらないか）。
- 動いている Claude が書く `~/.claude.json` と、start の更新が実際にぶつかるか（仮説）。
- Windows 側のコミットの `index.lock` の衝突が、どれくらいの頻度で起きるか。
