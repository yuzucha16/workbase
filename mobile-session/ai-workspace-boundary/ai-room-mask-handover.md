## PC で確認すること（この順）

1. **単体テスト**: PC の Python 3.13 で全件通るか。
2. **Excel で開く**: 実際の xlsx（顧客名入りの小さなもの）を `_noai/raw/` に置き、`room mask <Project>` → `ai/in/` のファイルを Excel で開く。壊れた警告が出ないか。プリンタ設定の削除、プロパティの空、複数 run の統合（書式が1つになる）で崩れないか。
3. **ピボット**: マスク後のブックのピボットが開くか。復元後のブックで「すべて更新」が通るか。通らなければ、ピボットキャッシュ（`pivotCacheRecords`）の扱いを直す。
4. **複数 run の漏れ**: Excel で、1つのセルの途中だけ太字にした顧客名（例: 「アクメ」を通常、「商事」を太字）を作り、マスク後に残らないか。警告に統合の件数が出るか。
5. **実機の通し**: 実際の部屋で `room start`（マスク → AI → 復元）。`_noai/final/` に実データ入りの成果物が出て、`ai/out/` はマスクのままか。
6. **文字コード**: cp932 の csv が、マスク後に `utf-8-sig` で Excel に文字化けなく開くか。
7. **候補の警告**: 実データで、警告が多すぎないか（多ければ形の絞り込み）。

## 既知の制限・気をつけること

- 対応は csv と xlsx だけ。それ以外が `_noai/raw/` にあると止まる。`ai/out/` の未知の形式（pdf など）も復元で止まる。
- シート名・定義名が語と同じとき、本文の同じ語も `SHEET_` / `NAME_` になる。復元は元の文字列に戻るので、往復は一致する。
- 数値セル（金額など）は列指定でマスクできない。既定でマスクしない方針のまま。
- 語を検査できない part（画像、埋め込み）は警告だけ。中身は人が確認する。
- `mapping.json` は追跡されない。失うと復元できない（ロードマップ5番のバックアップ）。
- 正規表現は語の数だけ長くなる。数千語では遅くなるかもしれない（未測定）。

## PC での確認の結果（2026-10-14）

実機（Windows、Excel）で、架空のダミー（実在の名前なし）を使って確認した。ダミーは、実際のピボットテーブル、コメント、定義名、プロパティ、シート名に語、通常+太字の run をまたぐ語を含む xlsx と、cp932 の csv。

| 確認 | 結果 |
|---|---|
| 1 単体テスト | 45件が通った（Python 3.13、uv） |
| 2 Excel で開く | マスク後の xlsx が、警告なしで開いた |
| 3 ピボット | マスク後が開き、復元後の「すべて更新」が通った |
| 4 複数 run の漏れ | 「アクメ」+太字「商事」が `⟦CUST_001⟧` にまとまり、全 part に語が残らない。統合の警告が 1 件出た |
| 6 文字コード | cp932 の csv が `utf-8-sig` に直り、Excel で文字化けなく開いた。全角・半角カナの表記ゆれも置換され、復元で正式名に戻った |
| 5 実機の部屋での通し | **未確認**（ダミーは `mask` / `restore` を直接呼んだだけ。`room start` の通しはまだ） |
| 7 実データでの候補の警告量 | **未確認**（実データは roadmap の 8 で） |

分かったこと（直さなくてよい。仕様どおり）:
- 表記ゆれは、復元で正式名に正規化される（「ＡＣＭＥ　Ｔrading」→「アクメ商事株式会社」）。往復で元の表記には戻らない。
- 同じ種類に別の形（社名とメールアドレス）を入れると、メールも社名に戻る。メールを元の形で戻したいなら、別の語として登録する。
- 辞書にも列指定にもない人名（例: 「山田」）は、マスクされずに残る。
- プリンタ設定（`printerSettings*.bin`）は、ダミーに含めていない。実機のブックで別に確認が要る。

ダミーの原本と生成スクリプトは、確認用の Project としてローカルの Vault に置いた（共有されない）。次回も使うなら、生成スクリプトを `room/tests/` に入れるかを、ユーザーに確認する（kit の変更は承認制）。
