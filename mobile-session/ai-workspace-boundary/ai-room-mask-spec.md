# マスク・復元の仕様（`room.py`）

- 作成: 2026-10-13（モバイルのセッション）。状態: **設計の確定（実装前）**。ロードマップの1番（[[ai-room-roadmap]]）。
- 根拠: ユーザーの決定（未決9の決定6。2026-10-12）と、2026-10-13 の確認6項目。「ユーザー」は決定、「既定」は私の提案でユーザーの異論がなければ採用。
- 前提: [[ai-room-next-steps]]（実測 S5: xlsx のマスク）、[[ai-room-hook-taxonomy]]。

## 目的と範囲

顧客データ・社外秘を、AI に渡す前にプレースホルダーへ置換し（マスク）、AI の出力に出てきたプレースホルダーを正式名に戻す（復元）。実行するのは **人（`room.py`）。AI には実行させない**（原本と対応表を読むため）。対象は csv と xlsx（docx・pptx は、同じ zip 方式で後から足す）。

## 置き場

| パス | 中身 | 追跡 |
|---|---|---|
| `_noai/raw/` | 原本 | しない |
| `_noai/mask.toml` | 何をマスクするかの指定（人が書く） | しない |
| `_noai/map/mapping.json` | 対応表（`room.py` が書く。追記専用） | しない |
| `ai/in/` | マスク済みの入力（読み取り専用でマウント） | する |
| `ai/out/` | AI の出力（プレースホルダーのまま） | する |
| `_noai/final/` | 復元済みの成果物（実データ入り） | しない |
| `ai/records/` | manifest（ハッシュ、版）。**対応表の中身は入れない** | する |

## `mask.toml`（ユーザー: 自動採番）

```toml
# 種類ごとに、同じものの表記ゆれを1つの配列にまとめる。先頭が正式名（復元で使う）
[terms.CUST]
acme = ["ACME株式会社", "ACME", "アクメ"]   # → ⟦CUST_001⟧
foo  = ["フー商事"]                          # → ⟦CUST_002⟧

[terms.PERSON]
tanaka = ["田中太郎", "田中"]                # → ⟦PERSON_001⟧

# 列の中身を、まるごと同じ種類で置き換える（語の一覧に書ききれない列）
[columns]
"売上!顧客名" = "CUST"
"担当!氏名"   = "PERSON"
```

- 数値は既定でマスクしない（ユーザー、未決9）。マスクしたい列は `[columns]` に書く。
- 番号は `room.py` が振り、`mapping.json` に記録する。**一度振った番号は変えない**。同じ語は、何回マスクしても同じ番号になる。語を足すと、末尾の番号が増える。

## プレースホルダー（ユーザー、未決9）

- セルの値・本文: `⟦CUST_001⟧`（種類の接頭辞つき）。
- シート名・定義名: ASCII の `SHEET_001`、`NAME_001`（実測: `⟦⟧` は、シート名には使えるが定義名には使えない。シート名は31文字までで `[]:*?/\` が使えない）。

## 置換の規則

- **一致は広く拾う**（ユーザー）: 部分一致。大小文字と全半角を区別しない。理由: 漏れ（機密が AI に渡る）のほうが、余分なマスクより重い失敗。余分なマスクは、復元で正式名に戻る。
- **1回の走査でまとめて置換する**（既定）: 全ての語を、長い語を優先して1つの正規表現にまとめる。順番に置換すると、置換後のプレースホルダーの中の文字（`CUST` など）を、別の語が拾う事故が起きる。
- xlsx は **zip レベルの置換**（実測 S5）: 中の `.xml` `.rels` `.vml` などの全 part に、対応表の語を置換する。XML では `&` `<` などがエスケープされているので、語もエスケープした形でも置換する。
  - 作成者・会社名のプロパティ（`docProps/core.xml`、`app.xml`）は無条件に空にする。
  - `printerSettings*.bin` は削除する（`[Content_Types].xml` と `.rels` も直す）。
  - **要確認（テストで確かめる）**: Excel は同じセルの文字を、書式の違いごとに複数の run（`<r><t>AC</t></r><r><t>ME</t></r>`）に分けて保存することがある。そのとき語が run をまたぐと、part の文字列置換では漏れる。点検は、`<si>` ごとに `<t>` の文字を連結した文字列でも行う。
- csv: 文字コードは `utf-8-sig`、だめなら `cp932` で読み、`utf-8-sig` で書く（既定）。

## 点検（マスク後。漏れがあれば止める）

1. 対応表の語（全ての表記ゆれ）が、`ai/in/` の全ファイル（xlsx は全 part と、run を連結した文字列）に 0 件であること。残っていれば、引き渡しを止めて一覧を出す。
2. **対応表に無い固有名詞の候補を一覧にする**（ユーザー: 候補を一覧にする。止めない）: 法人格（株式会社、有限会社、（株））、敬称（様、御中、殿）、メールアドレス、電話番号、URL とドメイン、郵便番号の形に当てはまるもの。警告として出し、人が見て、必要なら `mask.toml` に足す。

## 復元（回収のとき）

- 対象は、`ai/out/` の既知の形式だけ（ユーザー）: csv、md、txt、bas（VBA）、json、html はテキストとして、xlsx は zip の置換で復元する。**それ以外の形式が `ai/out/` にあれば、復元せずに止めて一覧を出す**。
- 復元した結果は `_noai/final/` に出す。`ai/out/` はマスクのまま（追跡する）。
- 復元後に、**戻らなかったプレースホルダー**（対応表に無い、改変された）を一覧にする。1件でもあれば、成果物を確定せずに止める。
- ピボットのキャッシュは、復元後に Excel で「すべて更新」をする（人。PC での確認）。

## `room start` への組み込み（既定）

1. チェック（`area:` とディストロ名、`boundary:`、マウントの有無）。
2. **マスク**: `_noai/raw/` の新しいファイル・変わったファイルだけを、`ai/in/` へ（ハッシュで判定）。`mask.toml` が変わっていたら、`ai/in/` の全ファイルを作り直す（作り直す前に確認する）。点検に通らなければ、ここで止める。
3. manifest に記録する: 原本のハッシュ、マスク後のハッシュ、`mask.toml` のハッシュ、対応表の版。
4. マウント → AI の起動 →（終了後）アンマウント。
5. **復元**: `ai/out/` を復元して `_noai/final/` へ。未復元・戻らなかったものを一覧にして、あれば止める。
6. 回収の一覧とコミット（今までどおり）。

単独でも使えるように、`room mask <Project>` と `room restore <Project>` も用意する（テストと手作業の確認用）。

## 実装メモ（2026-10-13）

実装は `workflow-kit/room/maskkit.py` と `room.py`（`mask` / `restore` / `start` への組み込み）。仕様から変えた点・足した点:

- シート名・定義名が語と同じ・語を含むときは、名前全体を `SHEET_` / `NAME_` にして、本文の同じ語もそちらに置換する（名前に `⟦ ⟧` を入れないため）。
- 語が複数 run にまたがる文字列は、1つの run にまとめて置換する（書式が1つになる。警告に件数を出す）。
- 1文字の語は `mask.toml` の読み込みで拒否する。
- 画像・埋め込みなど、語を検査できない part は警告に出す。
- 数値セルは `[columns]` の対象にできない（警告）。

## 完了の目安（1番）

- 合成データ（csv と、ピボット・コメント・定義名・プロパティ・複数 run の語を含む xlsx）で、マスク → 部屋での作業（模擬）→ 復元の往復が一致し、マスク後に対応表の語が 0 件。単体テストで確かめる（モバイルのセッション）。
- PC で、実際の Excel がマスク後のファイルを開き、復元後に「すべて更新」が通る。
