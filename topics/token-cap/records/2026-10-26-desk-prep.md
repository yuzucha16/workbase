## 1. 土台のうち、workbase が載せる分（Next Actions 6 の机上分）

マクロの作業は AI 作業部屋で行う前提で、開始時に読むもの（`room-context.md`）の大きさを、ファイルの字数から推定した。推定の式は「日本語 1 字 ≒ 1 トークン、それ以外は 3.5 字 ≒ 1 トークン」（誤差 ±3 割の目安。実トークンは `/context` で確かめる）。

| 開始時に載るもの | 字数 | 推定トークン | 備考 |
|---|---|---|---|
| 部屋の `~/.claude/CLAUDE.md` の案内（`room.py` の `POINTER_TEXT`） | 約 440 | 約 0.3k | 自動で載る |

| `ai/ctx/area-README.md`（Area の README） | 不明 | 0.5〜1k? | PC1 の実物しだい |
| `ai/docs/log.md`（予算 4KB） | 〜4,000 | 〜1.5〜2.5k | |
| **計** | | **約 4〜5k** | 土台約 2.4万の 2 割前後 |

残りの約 1.9〜2万は、ハーネス側（Claude Code の指示、ツール定義、MCP、skills、plugins）と見る。ここは `/context` でないと内訳が出ない。**削る余地の大半はハーネス側**で、workbase の常駐分を削っても、土台は 1 割程度しか減らない見込み。

### 見落としやすい分: フックの読み込みが、土台と同じくらい載る

| 合言葉 | 読むもの | 推定トークン |
|---|---|---|
| `brief` | `hooks.md`（3.3k）+ `hook-common.md`（4.4k）+ `brief-hook.md`（3.9k） | 約 11.6k |
| `wrap` | `hooks.md` + `hook-common.md` + `wrap-hook.md`（1.7k）+ `docs-rules.md`（全文なら 8.1k） | 約 9〜17k |

60k で切る運用では、**開始時に `brief` を言うと、土台 2.4万 + 1.2万 = 3.6万になり、作業に使えるのは残り 2.4万だけ**になる。`wrap` は会話の最後なので、それを抱えて走る応答は少なく、影響は小さい。

案（実測の後に決める）:

- B1. マクロの会話は `brief` を使わず、「<名前> の続き」（`log.md` だけ読む）で始める。運用だけで済む。
- B2. `script-guide.md` は節だけ読むことを ROOM.md に明記する（今は「の『実行の方針』」と書いてあるが、全文を読む余地がある）。
- B3. `hooks.md` の呼び出し表だけを小さなファイルに分ける（合言葉のたびに 3.3k 読むのを 1k 未満に）。kit の変更なので、効果を測ってから。

## 3. 削減量の見積もりの式（Next Actions 2 の受け皿）

記号: b = 土台、X = 切る大きさ、R = 応答数。会話の大きさが応答ごとにほぼ一定の幅で増えるとみなすと、1 応答の平均の大きさは (b + X) / 2、量は R × (b + X) / 2。

| 角度 | 式 | b = 24k の例 |
|---|---|---|
| 切る（X を下げる） | 減る割合 = 1 − (b + X新) / (b + X旧) | 100k → 60k で 1 − 84/124 = **約 32%**。PC1 で「60k を超えた応答の割合」が小さければ、効果も小さい |
| 土台を d 減らす（切る大きさは同じ） | 減る割合 = d / (b + X) | X = 60k で d = 5k なら **約 6%**。d = 10k（MCP などを外す）で約 12% |
| 土台を d 減らす（X も d 下げる。会話の長さを保つ） | 減る割合 = d / ((b + X) / 2) | X = 60k で d = 5k なら約 12% |
| `brief` を使わない（開始時の + 約 12k をやめる） | 開始時に足す分 h について、h / (b + h + X) 程度 | X = 60k で約 12%（その会話が 60k まで行く場合） |
| マクロの部品化（D） | 会話の平均の大きさ × 応答数の両方が変わる。式でなく、上位の会話の実数で見る | PC1 の `heavy_sessions.py` の上位がマクロなら、その合計 × 3〜5 割を目安の上限に |

PC1 の数値が届いたら、`cap_meter.py` の「当月の合計」「60k 超の応答の割合」「土台の分布」を b・X・R に入れて、角度ごとの量（トークン/月）にする。
