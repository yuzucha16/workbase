## 1. 実測（`cap_meter.py --month`）

| 項目 | 10-26（PC2、70 会話） | 2026-10 全体（203 会話） | 2026-11（15 会話。少数） |

- 土台は 10-26 から約 1.0k 減っただけ。skills の整理で 2.3k 減ったが、System tools が +2.3k（9.0k → 9.9k）で打ち消した（`2026-10-27-skills-trim.md`）。
- 土台の割合が上がったのは、60k 超の応答が減って、全体が小さくなったため。土台そのものは動いていない。11 月は 15 会話しかなく、47% は暫定。

### 追記: 新しい Zed のスレッドの `/context`（11-01、ee 提供）

合計 20.2k。System prompt 2.5k、System tools 9.9k（ほかに遅延 12.8k は合計の外）、MCP tools 0.66k + 指示 0.72k（遅延 1.6k は外）、Memory 2.8k、Skills 3.6k、Messages 10。

- Memory 2.8k の中身は `resources/AGENTS.md` が 2.7k（7.1KB。0.38 トークン/バイト）。`works/AGENTS.md` は載っていない。Memory は 10-26 の 2.1k から +0.7k。
- Skills は 3.6k（組み込み 13 件で約 2.2k、claude.ai 同期 5 件で約 1.4k。`built-in-browser` 約 0.29k が残っている）。
- 仮説 (a)「`works/AGENTS.md` が土台に乗る」は否定。`cap_meter` の土台 26.9k との差は約 6.7k に縮んだだけで、残る。
- 残る仮説: (b) 最初の応答に、フックの出力（作業の言葉の索引など）、環境の注記（git 状態、遅延ツールの一覧など）、最初の依頼が入る。(c) `cap_meter` が数える「最初の応答」の入力は、`/context` が数えない分（ツール結果、遅延ツールの名前一覧など）を含む。
- 動かせる量の見直し: AGENTS 連鎖は `resources/AGENTS.md` の 2.7k が対象（`works/AGENTS.md` は土台に乗らない）。縮小案 2 のうち `works` 側は効かない。上の表の「約 4KB 減」は、`resources` 側の約 2KB（0.7〜0.8k）に下がる。skills は組み込みが約 2.2k で外せない。外せる同期の 5 件は約 1.4k。

## 3. 動かせる量の見積もり

換算: 土台 1k 減 ≒ 2026-10 の応答数 5,003 × 1k ≒ 5.0M（385.0M の 1.3%）。

| 候補 | 見込み | 月の効き（10 月の量で） |
|---|---|---|
| `AGENTS.md` の連鎖を縮める（`2026-10-26-base-trim.md` の案 2。両方で約 4KB 減） | 1.3〜1.9k | 6.5〜9.5M（1.7〜2.5%） |
| 残りの skills 4 件を外す | 約 1.1k | 5.5M（1.4%） |
| 合計の上限 | 約 2.4〜3.0k | 12〜15M（3〜4%） |

- 「100k で切る」を 60k にした場合の差し引き（`2026-10-26` の式で 64k → 44k）は 1 応答あたり約 20k で、土台の整理（最大 3k）の約 7 倍。土台の整理は、切る運用の代わりにならない。
- 土台を動かすと、全応答に乗るので確実に効くが、AGENTS.md の縮小は規則の置き場の変更を伴う（`works/AGENTS.md` の安全規則は縮小の対象外）。
