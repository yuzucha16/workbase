# 案Y: AI 作業部屋（WSL に fork して exec する）

- 作成: 2026-10-12。前の設計 [[ai-boundary-design]] の「別案」を、ユーザーの選んだ方向で深掘りしたもの。
- 状態: **叩き台**。決定ではない。workbase とワークスペースには、何も反映していない。
- 「要確認」は、公式文書で確かめていない、または実機で試していない項目。

## 一言で

人の作業場（Vault）を正本にしたまま、作業のたびに「AI 作業部屋」を WSL 側に作る。マスクしながら部屋へ書き出し（fork）、部屋の中で AI を起動し（exec）、AI の出力を復元しながら Vault へ取り込む（wait / 回収）。終わったら部屋は捨てる。

```
Vault（Windows, $HOME\works）                     AI 作業部屋（WSL）
projects/<名>/                                    ~/rooms/<名>-<日付>/
  _noai/raw/   原本 ──┐                             in/    マスク済みの入力（読み取り専用）
  _noai/map/   対応表 ─┼─ 書き出し（fork + マスク）─▶ ctx/   README・docs の写し（読み取り専用）
  README.md, docs/ ───┘                             work/  AI の作業場（スクリプトなど）
                                                    out/   AI の成果物
  docs/, 成果物（マスク済み）◀─ 取り込み ─────────┤
  _noai/final/ 実データ入りの成果物 ◀─ 復元 ──────┘
                                                    （回収後、部屋を捨てる）
```

## 発想の転換（前の案との違い）

| | 前の案（`_noai/` 方式） | 案Y（作業部屋） |
|---|---|---|
| 既定 | 全部見える。`_noai/` だけ隠す（禁止リスト） | 何も見えない。書き出したものだけ見える（許可リスト） |
| 忘れたとき | 見える側に倒れる | 見えない側に倒れる |
| 境界の強さ | Claude Code の設定と規約。スクリプトは抜ける | 物理的に別の場所。スクリプトも、どの AI ツールも抜けない |
| マスク | 人が別に行う | 書き出しの手順そのもの |
| サンドボックス | Windows では効かない | 部屋が WSL なので、そのまま使える |

## 部屋の作り（3段階。どこまでやるかは未決）

| 段階 | 内容 | 守れること | コスト |
|---|---|---|---|
| L1 | いつもの WSL に部屋を作る。Claude Code のサンドボックスで `/mnt/c` の読み取りを塞ぐ（`sandbox.filesystem.denyRead`）、`Read(//mnt/c/**)` の deny | AI のシェルとファイル操作から Vault が見えない | 小 |
| L2（推奨） | **部屋専用の WSL ディストリビューション**を作り、`/etc/wsl.conf` で `[automount] enabled=false`（C: をマウントしない）と `[interop] enabled=false`（Windows のプログラムを起動しない）にする | Vault がそもそも存在しない。サンドボックスの設定ミスや、Windows の exe 経由の抜け道も無くなる。Codex / Copilot でも同じ | 中: ディストリビューションの準備と、Claude Code の導入・ログインを1回 |
| L3 | L2 に加えて、ネットワークを Anthropic の API と必要なサイトだけにする（サンドボックスの network allowlist） | 部屋の外への持ち出し | 中: 使うたびに許可の追加が起きる |

根拠（Microsoft の wsl-config の文書）: `wsl.conf` はディストリビューションごとの設定。`automount.enabled=false` で C: などを `/mnt` にマウントしない。`interop.enabled=false` で WSL から Windows のプロセスを起動しない。Windows 側からは `\\wsl.localhost\<ディストリビューション名>\` で部屋のファイルを読み書きできる。

L2 では、書き出しと取り込みは Windows 側（または、いつもの WSL）から `\\wsl.localhost\<部屋の名前>\...` に対して行う。部屋の中から Vault へは手が届かない。これが「fork したら親のメモリは見えない」に当たる。

## 部屋の中身

| パス | 中身 | AI の権限 |
|---|---|---|
| `in/` | マスク済みの入力（xlsx、csv、md など） | 読み取りだけ（`chmod a-w`） |
| `ctx/` | Project の `README.md` と `docs/` の写し。必要なら workbase（`resources/`） | 読み取りだけ |
| `work/` | AI の作業場。スクリプト、途中のファイル | 読み書き |
| `out/` | 取り込んでほしい成果物。`out/notes/` に作業ログや決定の下書き | 読み書き |
| `AGENTS.md` / `CLAUDE.md` | 部屋の規約（生成する）: 出力は `out/` へ、`in/` `ctx/` は変えない、プレースホルダーはそのまま残す | 読み取りだけ |
| `.claude/settings.json` | サンドボックスと deny（生成する） | — |
| `manifest` | 書き出したファイルの一覧とハッシュ、元の Project、日時、マスクの版。**対応表そのものは入れない** | 読み取りだけ |

workbase は公開されうる前提で書かれているので、部屋に入れてよい。部屋の中で GitHub から clone すれば、`ctx/` に写す必要も無い（ネットワークを絞る L3 では許可が要る）。

## 流れ（workflow-kit のフックとの対応）

1. **open**（Vault 側、今までどおり）: Project を作る。機密を扱う Project なら `_noai/`（`raw/` `map/` `final/`）も作る。
2. **書き出し（fork）**: 新しいフック。入力を選び、マスクして `in/` へ。`ctx/` に README と docs を写す。部屋の規約と設定を生成する。マスクの点検（対応表の語が `in/` に残っていないか）をここで行う。**人が実行する。AI には実行させない**（原本と対応表を読むため）。
3. **exec**: 部屋で AI を起動する。部屋の中では、今までの `start` / `wrap` がそのまま使える（対象の `docs/` は `out/notes/`）。
4. **取り込み（回収）**: 新しいフック。`out/` を Vault へ。マスク済みの成果物は Project の通常の場所へ（git で追跡）。復元した実データ入りの成果物は `_noai/final/` へ。`out/notes/` は Project の `docs/` に統合する。manifest のハッシュで、書き出した後に Vault 側が変わっていないかを確かめる。
5. **部屋を捨てる**: 取り込みのあとで削除する。続けるなら残してもよいが、`close` で必ず捨てる。
6. **close**（Vault 側）: 今までどおり。加えて、残っている部屋が無いかを点検する。

合言葉の案（未決）: 書き出し = `fork`（別名「部屋に出して」）、取り込み = `collect`（別名「部屋から戻して」）。

## マスクの設計

- プレースホルダーは、AI が書き換えにくく、検索しやすい形にする。例: `⟦CUST_001⟧`。種類ごとに接頭辞（`CUST` 顧客、`PERSON` 人名、`AMT` 金額 など）。
- 対応表は `_noai/map/` に置き、部屋には出さない。復元は、取り込みのスクリプトが対応表で置換する。
- **xlsx は、セルの値以外にも情報がある**。シート名、コメント、ヘッダー・フッター、隠しシート、名前の定義、ピボットのキャッシュ、外部リンク、ファイルのプロパティ（作成者、会社名）。書き出しで、これらを消すか置換する。できれば **csv など平らな形に変換して渡す**のが安全（xlsx が要る作業だけ xlsx で渡す）。
- 金額などの数値をマスクするか（集計の作業では、数値が要ることが多い）。マスクしない列を書き出しの設定で明示する。
- AI の出力に、対応表に無い新しい固有名詞が混ざることは、構造上ほぼ無い（AI は実データを知らない）。取り込みでは、プレースホルダーの欠落・改変を点検する（`⟦CUST_001⟧` が `CUST_001` になっているなど）。

## エディタと AI の使い分け

- **Zed**: WSL のフォルダを直接開ける（Zed の Windows の文書: "Zed supports remote development on Windows through both SSH and WSL"）。部屋を Zed で開き、Claude Agent を部屋の中で動かす想定。**Claude Agent が WSL 側で動くか、Windows 側で動くかは要確認**（文書に記述なし）。Windows 側で動くなら、ターミナルで `wsl -d <部屋> claude` を使う。
- **Obsidian**: 人が Vault を見る道具のまま。Obsidian から使う AI は Vault 側にいるので、機密を扱う作業には使わない。機密の無い Project では、今までどおり Vault で AI を使ってよい（前の `_noai/` 方式を安全網として併用）。
- つまり **AI の使い場所は2つ**になる。ふつうの Project は Vault、機密を扱う Project は部屋。

## 点在について

- 正本は常に Vault の1か所。部屋は作業中だけ存在する写しで、回収したら消える。前に問題になった「正本が複数の場所に散る」とは性質が違う。
- 散らかりを防ぐ決まり: 部屋の置き場は `~/rooms/` だけ。部屋の名前は `<Project 名>-<日付>`。`close` で残りを点検する。

## 決定と提案（2026-10-12 追記）

- **決定: 部屋は最初から L2（専用ディストリビューション）**。ユーザーが決定。
- **提案: 部屋の単位は Project ごと**。部屋の数 = 進行中の Project の数（上限3）で、open で作り close で捨てる。書き出しと回収は、Project の途中で何度でも追加で行える。作業ごとの使い捨ては、毎回の書き出しと、部屋の中の docs の引き継ぎが要り、管理が増える。代わりに、長く続く部屋では Y1（二重編集）と Y3（古いマスク済みデータの蓄積）が増えるので、回収のたびに manifest を更新し、不要になった `in/` を消す。
- **提案: スクリプトは Windows 側の Python 1本**（`room.py fork` / `room.py collect`。pwsh は呼び出すだけ）。理由: (1) L2 の部屋は C: をマウントしないので、部屋の側から Vault を吸い込めない。Vault と部屋の両方が見えるのは Windows 側だけ（`\\wsl.localhost\<部屋>\`）。(2) 対応表は Vault（Windows）にある。(3) xlsx の加工は Python（openpyxl）が最も扱いやすい。pwsh の ImportExcel モジュールでもできるが、隠しシートやプロパティの処理は弱い（推測）。(4) 両方向を同じ言語、同じ対応表の読み書きで揃えられる。Windows に Python（uv など）が要る。いつもの WSL で動かす案は、`/mnt/c` と別ディストリビューションの両方をまたぐので部品が増える。
- **決定: 1パターンに揃える**（ユーザーがカードで決定）。projects / areas の AI 作業は、機密の有無にかかわらず全部屋で行う。機密が無ければ、マスクなしで写すだけ。Vault 側で AI を使うのは workbase（`resources/`）の作業だけにする。これで `_noai/` の deny 設定（前の案）は、安全網としてだけ残すか、不要にできる。代わりに、Obsidian から Project の作業に AI を使うことはなくなる。

## 共有フォルダ（shared memory）と Excel（2026-10-12 追記）

ユーザーの前提: Excel のままやり取りしたい。ピボットテーブルの既定の作成を頼む。まれに Excel VBA の作成も頼む。
ユーザーの案: Windows の一部の領域だけを WSL（部屋）にマウントし、Windows 専用のアプリやフォーマットの作業場にする。fork のときに shared memory も渡すイメージ。

- **構成（提案）**: 部屋の `in/` `out/` など、受け渡しのファイルは、Vault の外の Windows のフォルダ `$HOME\rooms\<Project>\` に置く。部屋のディストリビューションでは、C: の自動マウントを切ったまま（`automount.enabled=false`）、`/etc/fstab` でこのフォルダだけを drvfs でマウントする。部屋の中のスクリプトや Python の環境など、受け渡さないものは WSL 側（ext4）に置く。
- **要実機確認**: drvfs で、ドライブ全体でなくフォルダだけをマウントできるか。`automount.enabled=false` のとき `/etc/fstab` が処理されるか（`automount.mountFsTab`）。マウント後に `ls /mnt` などで、C: 全体が見えていないことを確かめる。
- **よくなる点**: Excel で、人と AI が同じファイルを見られる。書き出し・取り込みが Windows のフォルダ間のコピーになり、`\\wsl.localhost` を使わない。
- **ピボットテーブル**: openpyxl は既存のピボットを保持できるが、新しく作れない（要確認）。部屋から Excel は起動しない（`interop` を有効にすると、Excel 経由で C: 全体に届く）。そこで、AI はデータの xlsx と、ピボットを作る VBA を書き、人が Windows の Excel で実行する。人が中身を見てから実行するので、マクロの安全面でも都合がよい。
- **復元とピボット**: 復元はピボットの元データを置換するが、ピボットのキャッシュにはマスクしたままの値が残る。取り込みの最後に Excel で「すべて更新」をする（VBA に `RefreshAll` を入れる案もある）。キャッシュの扱いは、マスクの点検の対象にもする。
- **xlsx の扱い（決定に近い）**: csv に平らにするのではなく、Excel のまま渡す。そのため、シート名、コメント、プロパティ、隠しシート、名前の定義などのマスクを、書き出しのスクリプトで行う必要がある。
- **追加のリスク**: 共有フォルダは Windows のアプリ（Excel の Copilot など）からも見える。中身はマスク済みなので許容。fstab の書き間違いで C: 全体をマウントするおそれ → 部屋の起動時に `/mnt` を点検する。

## プロセスのたとえで見たライフサイクルとフック（2026-10-12 追記）

ユーザーの捉え方: fork（部屋を作る）→ exec（AI を動かす）→ wait（回収）→ zombie → reap（後処理で `archives/` へ）。
要望: 手数の少ないフック。作業記録がわかる。再現できる。projects の成果と作業記録を areas に戻して同期できる（同期の時機は wait でなくてよい）。

### 共有フォルダの置き場の見直し（提案）

前の追記では共有フォルダを Vault の外（`$HOME\rooms\<Project>\`）に置いたが、**Vault の中の `projects/<名>/ai/` を部屋にマウントする**ほうが手数が少ない。

```
projects/<名>/
  README.md        Vault の索引（frontmatter、Bases、Area の一覧から参照）。部屋には ai/ctx/ に写しを置く
  ai/              ← このフォルダだけを部屋にマウントする（git で追跡）
    docs/          log.md, decisions.md（AI が書く）
    in/            マスク済みの入力
    work/          AI のスクリプト（再現に要るので追跡する）
    out/           成果物（マスク済み）
    records/       manifest、セッションの記録
  _noai/           マウントしない。git で追跡しない
    raw/ map/ final/
```

- 写して戻す処理が要らない。AI が書いたものが、そのまま Vault にあり、Obsidian でもすぐ見える。点在しない。
- drvfs はフォルダ単位でマウントするので、`_noai/` を `ai/` の外に置けば、部屋からは見えない。
- 部屋の側からは Vault の `.git` が見えないので、コミットはスクリプトが Windows 側で行う。
- 部屋の WSL 側（ext4）には、Python の環境と Claude Code のセッション履歴だけが残る。これが zombie の実体になる。
- 変わる点: Project の `docs/` が `ai/docs/` に移る。workflow-kit の open / close / wrap の「`docs/` の場所」を直す必要がある。

### フック（人が言うのは3つ。部屋の中は今までどおり）

人が Windows で実行するコマンド（スクリプト `room`）。原本と対応表に触るので、AI には実行させない。

| コマンド | プロセスのたとえ | すること |
|---|---|---|
| `room open <名> [--area <Area>]` | プロセスを用意 | Project のひな形（`README.md`、`ai/`、`_noai/`）を作り、Area の一覧に足し、コミットする |
| `room start <名>` | **fork → exec → wait** | (1) `_noai/raw/` の新しいファイルをマスクして `ai/in/` へ（fork）。(2) `ai/` をマウントし、部屋で Claude Code を起動（exec）。(3) Claude Code を閉じたら、続けて回収する（wait）: `ai/out/` の成果物を復元して `_noai/final/` へ、Area へ同期、manifest を更新してコミット |
| `room close <名>` | exit → zombie → reap | 下の「終了処理」 |

部屋の中（AI）: `start` と `wrap` は今までどおり。`close` は、部屋の中で AI が判断の部分（完了条件の確認、暫定の見直し、未解決の振り分け）を行い、結果を `ai/out/close.md` に書く。Vault への移動などの副作用は `room close` が行う。判断は AI、副作用はスクリプトと分ける。

1セッション = `room start` 1回。シェルが子プロセスを fork して exec し、終わるのを wait するのと同じ形で、回収の手順を忘れない。

### 作業記録と再現性

| 記録 | 中身 | 置き場 |
|---|---|---|
| 作業ログ | `log.md`、`decisions.md`（AI が `wrap` で書く） | `ai/docs/` |
| 変更の履歴 | `room start` の回収ごとのコミット（メッセージにセッションの識別子） | Vault の git |
| manifest | 入力のハッシュ（原本とマスク後）、マスクの規則の版（対応表の中身は入れない）、スクリプトと workflow-kit の版、Claude Code の版、モデル | `ai/records/` |
| スクリプト | AI が書いた集計や VBA | `ai/work/` |
| セッションの記録 | Claude Code の会話の履歴（部屋は原本を見ていないので、マスク済みの内容だけ） | reap のときに `ai/records/sessions/` へ写す（追跡するかは未決。大きい） |

- 再現の範囲は、**マスク済みの段階までなら常に再現できる**（入力、スクリプト、記録がすべて `ai/` にある）。実データ入りの成果物まで再現するには、`_noai/raw/` と `_noai/map/` が残っている必要がある。ここが、保持の方針（下の K2）とのトレードオフ。

### Area との同期（郵便受け方式）

- AI は `wrap` のとき、`decisions.md` の項目に【この件】【案件】【汎用】のラベルを付ける（既存の規則の延長）。
- `room start` の回収で、【案件】の項目を、Area の `ai/docs/inbox.md` に追記する（Project 名と項目の識別子つき。同じ項目を二度送らない）。
- Area の `decisions.md` に直接書かないのは、Area の部屋が同時に開いていると書き込みがぶつかるため。Area の AI が次の `start` で `inbox.md` を読み、取り込む。
- これで、同期は毎セッションの回収のたびに少しずつ進み、`close` に集中しない。

### 終了処理（`room close`）の手順案

1. **最後の回収**: `room start` の回収と同じことを行う。部屋の中の `close` の結果（`ai/out/close.md`）が無ければ止める。
2. **Excel の仕上げの確認**: 実データ入りの成果物（`_noai/final/`）で、ピボットの「すべて更新」を済ませたかを人に確認する（キャッシュにマスクした値が残るため）。
3. **Area へ渡す**: 未解決の振り分け（`close.md`）を Area の `inbox.md` へ。Area の一覧を「完了した Project」に移す。
4. **exit**: `README.md` を `status: done` に。部屋の `ai/` をアンマウントする。
5. **archives へ移す**: `projects/<名>/` → `archives/<名>/`。git で追跡する部分はファイル単位の `git mv`（既知の `Permission denied` の対策。アンマウントを先に行う）。追跡しない `_noai/` は、スクリプトが`archives/<名>/_noai/` へ移す（K2）。コミットする。
6. **zombie**: 部屋の WSL 側（Python の環境、セッションの履歴）は、まだ消さない。成果物を納品して問題が無いと分かるまでの、やり直しの余地として残す。`README.md` に `reap_after: <日付>` を書く。
7. **reap**: `room close` を次に実行したとき（または `room reap`）、期限を過ぎた zombie を一覧にし、承認を得て、セッションの記録を `ai/records/` に写してから、WSL 側を消す。

### 終了処理の検討事項

| # | 検討事項 | 案 |
|---|---|---|
| K1 | zombie をいつ reap するか | 納品の確認後。既定は close から14日（仮）。`room close` のたびに期限切れを一覧にする |
| K2 | `_noai/`（原本、対応表、実データ入りの成果物）の保持 | **決定（2026-10-12、ユーザー）: 当面は残す**。archives へ一緒に移す。Vault は private 領域なので、対応表の漏えいは AI 分離とは別の論点として扱う。これで実データ入りの成果物まで再現できる |
| K3 | マスク済みの記録（セッションの履歴、`ai/in/`）の扱い | 対応表が残る間は、組み合わせると実データに戻せる。Vault は remote なし（前提8）なので、Vault の中に置くのは許容。外へ出さない |
| K4 | Area への同期の重複と衝突 | 郵便受け（`inbox.md`）と項目の識別子で防ぐ |
| K5 | 【汎用】のナレッジ化 | 今までどおり、ユーザーが言ったときだけ。部屋の AI が `ai/out/stock/` に下書きし、人が確認して workbase の `exmem/inbox/` へ。会社固有の内容が混ざっていないかを人が見る |
| K6 | 回収の失敗（復元できないプレースホルダーなど） | 失敗したら archives に移さず、zombie のまま残して再実行できるようにする |
| K7 | マウントの消し忘れ、部屋の残り | `room close` の最後に、マウントと WSL 側の残りを点検して報告する |
| K8 | workflow-kit の既存のフックとの関係 | `open` / `close` の副作用をスクリプトに移すので、手順書は「AI が判断する部分」だけに縮める。`docs/` の場所が `ai/docs/` になる |
