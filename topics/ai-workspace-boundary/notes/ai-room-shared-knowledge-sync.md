# 部屋と共有知（workbase）の同期: 一般化と rebase の担当

- 作成: 2026-10-13（モバイルのセッションでの議論）。状態: **方向と、入る方向の方式 A に合意。細部は未決**。ユーザーの発言: 「gitのrebaseだよね。これをいつ誰がやるかが問題」「この方向が良い」。
- 前提: [[ai-room-handover]]、`docs/log.md`（決定は `docs/decisions.md`、経緯は `docs/log-history.md`）。

## 問題

部屋は `ai/` しか見えない閉じた世界なので、workbase（共有知）との行き来がすべて切れている。

| 方向 | 切れているもの | 危険 |
|---|---|---|
| 入る（部屋の AI が読む） | フックの手順書（`start` `wrap` `close` の本文。ワークスペースの `AGENTS.md` は `resources/workflow-kit` を指すが部屋から見えない）、`exmem/lessons/`、`guides/`、共通規約、道具（`find-knowledge.ps1` などは `pwsh` が部屋に無い） | 小（workbase は公開されうる前提で機密を入れない規約） |
| 出る（部屋の知見を共有知へ） | `stock`（運び先 `exmem/inbox/` が見えない） | 大（公開されうる workbase に入る）。人の確認が必須 |
| 影響なし | `integrate`（`exmem/` 側の作業） | — |
| 未確認 | `review` が読む記録（`events` など）の置き場 | — |

加えて、workbase は常に育つので、部屋が見ている版と最新の版がずれる。`stock` の下書きを `integrate` するとき、到着順と発生順がずれて、時系列が壊れるおそれがある。

## 類似の問題と解き方（アナロジー）

| 世界 | 解き方 | こちらへの対応 |
|---|---|---|
| fork と環境変数 | 子は写しで動く。子から親へは終了コードとパイプだけ | 部屋は写しで動く。戻す出口は `stock` の下書き1種類 |
| Docker のイメージ層 | ベースは不変で、ダイジェストで固定。書くのは上の層だけ | workbase の写しは読み取り専用。書くのは `ai/` だけ |
| DB のスナップショット分離（MVCC） | 取引の始めに版を固定し、コミット時に変化を検査 | 1セッション = 1取引。始めに版を固定し、戻すときに検査 |
| git の rebase と3-way マージ | 変更に基準コミットを持たせ、基準・自分・最新の3点で比べる | 下書きに基準コミットを書く |
| Linux カーネルのパッチ運用 | パッチは基準コミットを持ち、メンテナが当てる。当たらなければ差し戻し | `integrate` が当てる人。当たらなければ Open Questions |
| ログ、分散システム | 発生時刻で並べる。ID で二重適用を防ぐ | 日付は「観測した日」で並べる。`転記済` が二重適用の防止 |

## 方向（合意）

1. **入る方向**: 起動のたびに、Windows 側が workbase の写しを部屋の内部（`~/shared`、読み取り専用）へ送る（方式 A。**ユーザーが決定、2026-10-13**。代替: B = `resources/` を2つ目の読み取り専用マウント、C = 部屋の中で clone（認証情報が要るので避ける））。セッションの途中では更新しない。送った写しの workbase のコミットと kit の版を manifest に記録する（再現性）。
2. **出る方向**: 下書きだけ。部屋の AI が `stock` 形式の下書きを `ai/out/stock/` に書き、人の門を通して `exmem/inbox/` へ運ぶ（既存の「隔離ソース」方式に寄せる）。下書きのヘッダーに、**基準コミット**（写しの workbase のコミット）と**観測日**を持たせる。
3. **rebase の「いつ・誰が」**: 検出と解決を分ける。
   - 検出（機械的）: **回収のとき**、`room.py` が、下書きの基準コミットと最新を比べ、統合先の `lessons/` が基準以降に変わっていれば「基準が古い」の印を付ける（変わっていなければ印なし）。
   - 解決（意味の判断）: **`integrate` のとき**、workbase 側の作業として、基準の版・下書き・最新の版の3点で食い違いを確認する。担当は workbase 側の AI と人（承認は人）。食い違いは Open Questions に書く（`stock-hook.md` の「他のメモとの食い違い」の延長）。印が無ければ今までどおり統合する。
   - 並べる順序は、到着順でなく観測日。
   - 部屋の AI は rebase しない（閉じた世界で、最新の版が見えない）。下書きが長く待つ場合だけ、次の `room start` で写しを取り直し、「基準が古い下書きを、新しい版に照らして見直す」と頼めるようにする（任意）。
