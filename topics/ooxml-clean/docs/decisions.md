# 判断の記録（decisions）

## Decisions

### 【この件】点検と掃除の方式は A（元ファイルは変えない）（2026-10-26）
- 決めたこと（ユーザー、カードで A を選択）: 点検（読むだけ）と掃除（別ファイルを出す）の 2 段。作り直し（見えるセルの値だけで新しいブックを作る）は見送り。
- 根拠: 完成済みのブック・資料を AI に見せる用途では、数式・書式が残らないと意味が減る。知らない残り方は、掃除の後の再点検で警告に出す。足りなければ作り直しを後から足す。

### 【この件】点検を先に作り、実ファイルの結果で掃除の既定を決める（2026-10-26）
- 決めたこと（推奨どおり進行、ユーザーが実ファイルで点検・掃除を回した）。根拠: 実ファイルでどこに残っていたかを見ずに、既定を決めない。

### 【この件】外部リンクは不要、非表示の行の値は消してよい（2026-10-27）
- ユーザーの発言: 「不要です。良いです。」（外部リンクを切る案、非表示の行を空にする案への回答）。
- 決めたこと: 外部リンクを切る動作を既定に入れた。非表示の行・列を空にするのは既定にせず `--also hidden-rows,hidden-cols`（表の中身を変えるため）。

### 【この件】出力と報告を、このリポジトリの中に書かない（2026-10-27）
- 経緯: 出力先に `./`（`workflow-kit\room\`）を指定し、実データの抜粋入りの報告が公開リポジトリの作業ツリーに出た。
- 決めたこと: `cleankit.py` が、このリポジトリ内への出力・報告で止まる。`*.check-report.md` `*.clean-report.md` を `.gitignore` に追加。根拠: AGENTS.md の共有の範囲（公開、機密を入れない）。

### 【この件】掃除を `room` のマスクの前段に組み込む。pptx の確認が先（2026-10-30）
- ユーザーの発言: 方針は「よいです」。pptx は「さきに確認します。PC1 環境が必要なので後日」。報告は「直下はやめてほしい。ファイルがたくさんできるし名前が長く見通しが悪い。どこかのディレクトリにまとめてほしい」。
- 決めたこと: `raw` → 掃除 → マスク → `ai/in` の順にする。既定は `standard`、`strict` は Project ごとの選択（`strict` はピボット・グラフを外し、復元の前提と合わない）。掃除の設定のハッシュを差分判定（今の `mask_sha256` の隣）に足す。掃除の報告は `_noai/` の中の専用ディレクトリ（例 `_noai/clean-reports/`）にまとめ、`raw` の直下には置かない。
- 順序: 組み込みは、pptx を PC1 の実ファイルで 1 回通した後。
