# OOXML（xlsx・pptx）に情報が残る仕組みと、クリーン化スクリプトの方針案

2026-10-26。探索型の相談の叩き台（仮ゴール: 仕組みを理解する → AI に渡す前のクリーン化スクリプトを作る）。kit は未変更。検証はすべてダミーデータ。

## 1. 結論（消したシートが見えた理由）

xlsx・pptx は「画面に見えるもの」ではなく、**zip に入った部品（part）の集まり**。シートを消しても、そのシートの値の**写し**を別の部品が持っていれば、zip の中に残る。AI は画面ではなく zip の中の XML を読むので、写しがそのまま見える。

写しを持つ代表は、グラフのキャッシュ、ピボットのキャッシュ、外部リンクのキャッシュ、定義名、文書プロパティ。どれが残ったかはファイルしだいなので、実ファイルを検出スクリプトにかけると特定できる（下の 6 の 1 段目）。

## 2. 仕組み

- xlsx は zip。中身は `xl/workbook.xml`（シートの一覧）、`xl/worksheets/sheetN.xml`（各シートのセル）、`xl/sharedStrings.xml`（文字列の共有表。セルは番号で指す）、`xl/charts/` `xl/pivotCache/` `docProps/` など。
- 部品どうしは `_rels/*.rels`（関係）で結ばれる。Excel は関係をたどって表示する。**関係から外れた部品や、表示に使わない部品も、zip には入ったままになりうる。**
- 「見えない」と「入っていない」は別。非表示シート（`state="hidden"` / `"veryHidden"`）、非表示の行・列、白い文字、スライドの外に置いた図形は、画面から消えても XML にはそのまま入っている。
- 「削除」も、Excel が消すのは**その部品**だけ。ほかの部品が持っている写し（キャッシュ）は、Excel が作り直さない限り残る。

## 3. 残り方の一覧

確度: **実測** = この環境でダミーを作って確認（LibreOffice 26 と openpyxl / python-pptx。Excel 本体ではない）、**仕様** = ECMA-376 の構造上そこに入る（Excel での残り方は版と操作しだい。検出スクリプトで実ファイルを見て確かめる）。

### xlsx

| 場所 | 残るもの | よくある経緯 | 確度 |
|---|---|---|---|
| `xl/charts/chartN.xml` の `c:strCache` `c:numCache` | グラフの元データの写し（項目名・値）と、参照先のシート名（`c:f`） | 元データのシートを消しても、グラフが写しで描かれ続ける | 実測（写しが入る）。削除後の残り方は仕様 |
| `xl/pivotCache/pivotCacheRecords*.xml`・`Definition` の `sharedItems` | ピボットの元データ**全件**の写し | 元データのシートを消しても、ピボットは「データを保存」で動き続ける | 仕様 |
| `xl/externalLinks/` | 他のブックのパス（ユーザー名入りのことがある）、シート名、セル値のキャッシュ（`sheetDataSet`） | 別ブックから値をコピー・参照した | 仕様 |
| `xl/workbook.xml` の `definedNames` | 名前と参照先のシート名。参照先を消すと `#REF!` になるが、名前は残る | 名前の定義・印刷範囲・フィルター | 実測（`#REF!` で残った） |
| 非表示シート（`state="hidden"` / `veryHidden`） | シートの全部 | 「消したつもり」で非表示にしていた。`veryHidden` は Excel の画面から再表示できない | 仕様 |
| 非表示の行・列、白文字、グループの折りたたみ | セルの値 | 見せない列を隠した | 仕様 |
| `xl/sharedStrings.xml` | 文字列。使っていない文字列が残る場合がある | 他のツールで編集した | 仕様（Excel は保存で作り直すことが多い） |
| `xl/comments*.xml`・`threadedComments/`・`persons/person.xml` | コメント本文、作成者名、（新しいコメントは）利用者 ID | コメントを付けた | 実測（作成者名が残った） |

| `xl/workbook.xml` の `x15ac:absPath` | 保存した場所の絶対パス（`C:\Users\<名前>\...`） | 自動で入る | 仕様 |
| `xl/connections.xml`・`queryTables/`・`customXml/`（Power Query）・`xl/model/`（データモデル） | 接続文字列（サーバー名、ユーザー名）、クエリ、取り込んだデータ全件 | 外部データの取り込み | 仕様 |
| `xl/revisions/` | 変更履歴（消した値を含む） | 共有ブック・変更履歴の記録 | 仕様 |
| `xl/calcChain.xml` | 計算順の一覧（シート番号とセル番地） | 自動 | 仕様（値は持たない。手がかり程度） |
| `xl/printerSettings/*.bin` | プリンター名、共有パス | 印刷設定 | 仕様（room のマスクは削除済み） |
| `xl/vbaProject.bin`（xlsm） | マクロのコード、作成者 | マクロ | 仕様 |
| `xl/media/`・`embeddings/` | 画像（写った文字、EXIF）、埋め込みのブック・文書の全部 | 図の貼り付け、オブジェクトの挿入 | 仕様 |
| zip の構造 | 関係から外れた部品、同名の重複エントリー | Excel 以外のツールで編集した | 仕様 |

## 4. 実測の記録（ダミー）

- xlsx: 「公開」「社外秘」の 2 シート、社外秘を参照するグラフ・数式・定義名・コメントを作り、LibreOffice で保存 → 社外秘を削除 → 保存。
  - 削除前: グラフの `chart1.xml` に、元データの写し（ダミー氏名 2 件）とシート名 `社外秘!...` が入っていた。
  - 削除後: 定義名 `担当一覧` は `#REF!` で残った。コメントの作成者名と `docProps` の作成者が残った。グラフは LibreOffice が別のセルに付け替えたため、写しは消えた（Excel は付け替えず、写しを残す動きをすることがある。版で違うので、実ファイルで確かめる）。
- pptx: グラフ付きのスライドを作ると、`ppt/embeddings/Microsoft_Excel_Sheet1.xlsx` にブック全体が入った。ノートと非表示スライドも、そのまま XML に入った。

## 5. 既存の room のマスクとの関係

`workflow-kit/room/maskkit.py`（`room mask`）は、**`mask.toml` に書いた語**を、zip の全部品で置換する（キャッシュの中の語も置換される）。作成者・会社名を空にし、プリンター設定と縮小画像を消す。

穴は 2 つ。

1. **書いていない語は残る。** 消したシートにあった氏名は、`mask.toml` に無ければそのまま。候補の警告（法人格・敬称・メールなど）は、氏名を拾わない。
2. **構造は残る。** 非表示シート、ノート、コメント、埋め込みブック（検査できない部品として警告だけ）、外部リンク、接続、`absPath` などは、語が当たらない限り手を付けない。

つまり、クリーン化は**マスクの前段**（構造を減らす）として足すと、互いに穴を埋める。

## 6. スクリプトの方針案

### 段の分け方（推奨）

1. **点検（読むだけ）**: 上の一覧を全部調べ、どの部品に何が残っているかを報告する。元ファイルは変えない。ee さんの実ファイルの「なぜ見えたか」は、これで特定できる。
2. **掃除（新しいファイルを出す）**: 点検で見つけたものを、決めた範囲で取り除いた別ファイルを出す。出力をもう一度点検し、残りが無いことを確かめる。
3. （任意）**作り直し**: 見えているシートのセルの値だけで、新しいブックを作る（許可リスト方式）。構造を一切持ち込まないので最も安全。数式・書式・グラフは失う。

### 方式の選択（ee さんに決めてほしい点）

| 案 | 中身 | 良い | 悪い |
|---|---|---|---|
| A. 点検 + 掃除（推奨） | 1 と 2 | ファイルの形（数式・書式・レイアウト）を残したまま AI に渡せる | 消し方の一覧が「知っている残り方」に限られる（拒否リスト方式） |
| B. 点検 + 作り直し | 1 と 3 | 知らない残り方にも強い | 数式・グラフ・書式が消える。pptx には向かない |
| C. 両方 | 1・2・3 | 用途で選べる | 作る量が増える |

推奨は A。理由: 今の用途（完成済みのブック・資料を AI に見せる）では、形が残らないと AI に見せる意味が減る。点検が掃除の後にも走るので、知らない残り方は「検査できない部品」「関係から外れた部品」として警告に出る。B は、A を使って足りなかったときに足す。

### 掃除の既定（案。点検の報告を見て調整する）

- **消す（既定）**: 非表示シート（`hidden` / `veryHidden`）、非表示スライド、ノート、コメントと作成者、`docProps` の個人情報（作成者・最終更新者・会社・管理者・`TitlesOfParts` を残すシートに合わせる・秘密度ラベル）、`absPath`、プリンター設定、縮小画像、`calcChain`（Excel が作り直す）、変更履歴、関係から外れた部品、使っていない共有文字列。
- **値に置き換える**: 消したシートを参照する数式は `#REF!` のキャッシュ値に、定義名の `#REF!` は削除。
- **報告だけ（既定では消さない）**: グラフ・ピボットのキャッシュ（消すとグラフが壊れる。語は `mask.toml` のマスクで消す）、外部リンク・接続・Power Query・データモデル（消すと数式・更新が壊れる。消す設定を用意する）、画像・埋め込み（中身を人が見る）、非表示の行・列と白文字（消すと表の形が変わる）、VBA。
- 消す・残すは、設定ファイル（`mask.toml` に `[clean]` の節を足す案）で変えられるようにする。

### 実装の方針

- **言語: Python の標準ライブラリだけ**（`zipfile` と `xml.etree`）。`script-guide.md` の順（Python が既定）に従い、PC1 のオフラインでも依存を取りに行かずに動く。`maskkit.py` が同じ作り（標準ライブラリで zip の部品を直接書き換える）なので、zip の読み書きとプリンター設定・縮小画像の処理を流用する。
- **置き場: `workflow-kit/room/` に `cleankit.py` を足す**。使い方は 2 通り。
  - room の中: `room mask` / `room start` のマスクの前に掃除を挟む（`_noai/raw/` → 掃除 → マスク → `ai/in/`）。
  - room の外（ブラウザの AI に渡すときなど）: `uv run --script cleankit.py check <ファイル>` と `clean <ファイル> <出力先>`。人が実行する。
- **報告は AI に見せない場所に出す**（`_noai/` の下、room の外なら出力の隣の `*.clean-report.md`）。報告には残っていた実データ（氏名など）が載るため。AI に渡すのは掃除済みのファイルだけ。マスク・復元を AI にやらせない、という既存の境界と同じ線。
- **元ファイルは開くだけ**（書き込まない）。出力は別名。
- **テスト**: `workflow-kit/room/tests/` に、ダミーの xlsx・pptx を標準ライブラリで組み立てる fixture を足し（`dummy_fixture.py` の流儀）、残り方ごとに「点検で見つかる」「掃除で消える」「掃除後に Excel の必須部品の整合（関係・`[Content_Types].xml`）が保たれる」を確かめる。開けるかどうかは、部屋の LibreOffice で開き直して確かめ、Excel・PowerPoint での確認は人（PC1 / PC2）。
- docx は今回は対象外（maskkit と同じく、後から同じ方式で足せる）。

### 実装の前に確かめたいこと

1. 方式は A（点検 + 掃除）でよいか。
2. 最初に、点検だけを先に作って実ファイル（PC1）にかけ、どこに残っていたかを見てから掃除の既定を決める順でよいか（推奨）。
