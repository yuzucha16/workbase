# Quarto の見た目を社内の雛形に合わせる手順の設計（叩き台）

状態: 叩き台（2026-11-04）。試験前で、Pandoc の pptx の仕様は記憶と公式文書による。試験で確かめてから確定する。

## 前提

- 持っているもの: 基準のマスタースライドとサンプルレイアウト（社内の `.pptx` / `.potx`）。
- 目的: Quarto が出す pptx を、後から手で直さずに、雛形の見た目で出す（手離れ）。
- **雛形そのものはこのリポジトリ（公開）に入れない。** 置き場はローカル（Vault の外か、部屋の `ai/` の外の read only）。ここには手順と、雛形に依らない試験用の `.qmd` だけ置く。

## 仕組み（要点）

- `format: pptx: reference-doc: <雛形>.pptx` で、マスター（背景・フォント・色・ロゴ）とレイアウトを借りる。スライドの中身は雛形から使わない。
- Pandoc はレイアウトを **名前で** 選ぶ: `Title Slide` `Title and Content` `Section Header` `Two Content` `Comparison` `Content with Caption` `Blank`。雛形にこの名前のレイアウトがないと、既定のレイアウトに落ちる（見た目が崩れる原因の第一候補）。
- 上の名前以外のレイアウトは、Quarto のスライドの属性 `{layout="レイアウト名"}` で指定できる（版の対応は試験で確認）。
- フォントは雛形のテーマに指定する（`records/reference-biz-udpgothic.pptx` の方法。フォールバックは pptx で不可）。

## 手順

1. **棚卸し**（AI。読み取りだけ）: python-pptx で雛形のレイアウト一覧と、各レイアウトのプレースホルダー（種類・idx・名前）を表にする。
2. **対応づけ**（AI が案、ee が確認）: Pandoc の 7 つの名前に、雛形のどのレイアウトを当てるかを決める。無い型（比較など）は、使わないと決めるか、近いレイアウトを複製して名前を付ける。残りのレイアウトは `layout=` で呼ぶ名前の一覧にする。
3. **雛形の整形**（ee が PowerPoint で、または AI が python-pptx で）: 2 の通りに名前を付け、プレースホルダーを標準の種類（タイトル・本文・コンテンツ）にする。独自のテキストボックスで作った部分は、Pandoc が埋められないので、プレースホルダーに直す。整形後の雛形を `reference-company.pptx`（ローカル）とする。
4. **全要素の試験**（AI）: 要素を全部入れた `.qmd`（タイトル、章扉、箇条書き 3 階層、2 段組、表、画像、コード、mermaid の図、発表者ノート、`layout=` 指定）を雛形で出力し、PDF → 画像にして見る（部屋の `convert` 段で変換）。
5. **差の一覧**（AI → ee）: 雛形の見本と出力を並べ、差を 3 種に分ける。(a) 雛形を直せば消える、(b) Quarto の書き方（`.qmd`）で消える、(c) Quarto では表せない（フッター、スライド番号、日付、ロゴの位置など）。
6. **直す**: (a) は雛形、(b) は `.qmd` の書き方の規則、(c) は後処理（python-pptx の短いスクリプト）か、人が直す前提として記録。4〜6 を差が許容内になるまで回す。
7. **固定**: 雛形の置き場と版（ファイル名に日付）、`.qmd` の書き方の規則（使うレイアウト名の表）、後処理の有無、合格の基準（見本との差の許容）を 1 枚にまとめ、`init` した部屋で AI が使える形にする。PC1 の PowerPoint で開いて、フォントとレイアウトを確かめる（これは `office-output-types` の NA 5）。

## 決めたこと（2026-11-04 ユーザーの回答）

- 雛形は固有名詞を含むので、AI の部屋に渡さない。手順 1〜6 は匿名化した雛形（固有名詞を除いた複製）で行い、実物の雛形での確認は ee が行う。
- (c) の必須の要素: 番号（スライド番号）、フッター、ヘッダー、ロゴ。Quarto では表せない可能性が高いので、雛形のレイアウトに置く方法を先に試し、だめなら後処理（python-pptx）にする。
- 見本との差の許容: フォントと色は一致させる。余白などは多少ずれてよい。
