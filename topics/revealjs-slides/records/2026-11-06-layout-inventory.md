# 型の棚卸し（2026-11-06）

12 個のレイアウト（A〜J、T、split）を、重なり・管理のしやすさ・組み合わせの拡充のしやすさで見た。台帳は `gen_layouts.py` の `LAYOUTS`（番号・名前の正）。

## 運用（ユーザーの決定。2026-11-06）

- 型の最終判断はユーザー。AI は型と lead/notes の位置を**提案**し、スライドの右上に**レイアウト番号**を表示する（例 `H+notes`、`split(J+T)+lead`）。ユーザーは「p5 を J に」のように番号で指示する。
- 無いレイアウトは、近い型で代用し、spec に `"want": "欲しい形"` を書く。番号に `※要新設` が付き、生成時に stderr へ一覧が出る。溜まったものを逐次、型にする。
- 完成版は `--no-id`（または spec の `"show_id": false`）で番号を消す。

## 重なりと管理・拡充の見立て

| 番号 | 実装 | 重なり | 管理 | 拡充 | 案 |
|---|---|---|---|---|---|
| A E F | `box_slide`（cell を N 個） | 同じ部品の個数違い（2・1・4） | 型ごとに CSS が別（`.lay-a` など） | 新しい並びは CSS + `BOX_COUNT` + 分岐の 3 か所 | P1 |
| B D G | 同上（`wide` `tall` `link` の分岐） | 「結合したセルのある箱」の 3 例 | 同上。分岐が `box_slide` に増える | 同上 | P1 |
| H I | `grid()`（chevron の有無だけ違う） | H と I は同じ関数 | 1 関数で済んでおり良い | 列・行は文言の数で増える | 現状維持 |
| J | `table_slide`（`<table>`） | H と見た目が近い（行ラベル付き表） | 表は意味的に table が望ましい | 列の寄せ・強調・番号はある | 現状維持 |
| C | `toc_slide` | 重なりなし | 独立 | 章の再掲（current） | 現状維持 |
| T | `text_slide` | 重なりなし | 独立。`side` が付属 | 右側は code / img | 現状維持 |
| split | `slide()` で 2 部品を左右 | 型を選ばず組める | 部品は `body()` 経由で再利用 | 2 つまで。3 つ目は `cols` と個数制限の変更だけ | P2 |
| lead notes | `summary()` | 型と直交（全型に付く） | 1 か所 | 位置（上・下）は固定の 2 枠 | 現状維持 |

階段（pptx の 9）と 3 要素（28）は、ユーザーの判断で H・I で足りるとし、型にしない（11-06）。

## 提案（ユーザーの確認待ち。実装はまだしない）

- **P1: A〜G を 1 つの `box` にし、並びを `areas`（CSS の grid-template-areas）の preset にする。** A〜G の記号は preset 名として残る（番号は変わらない）。新しい並び（例: 左 2 + 右 1、3 列）は、台帳に preset を 1 行足すだけで作れ、CSS と分岐を触らない。管理する場所が 3 か所から 1 か所になる。リスクは、既存の見本 7 枚（A〜G）の見た目が変わらないことの再確認（目視）。
- **P2: split を 3 部品まで許す。** `cols` に 3 つ書けば足りる。需要が出てからでよい（`want` に溜める）。
- **P3: 台帳に「使いどころ」の 1 行を足す。** AI が提案するとき、番号と理由を一緒に言えるようにする（今は `LAYOUTS` が名前だけ）。

## 提案のしかた（AI の動き）

1. 内容から型を選び、スライドに番号を出して返す。2. 選んだ理由を 1 行で添える（比較なら A・F、手順なら I、一覧なら J、など）。3. ユーザーが番号で直す。4. 欲しい形が無ければ `want` を書いて近い型で出す。
