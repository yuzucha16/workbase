# DADS × 現行 v1 の取捨選択表（叩き台）

作成 2026-11-06。AI の叩き台で、採否はユーザーが決める（空欄の「決定」列）。DADS の値は `2026-11-06-dads-summary.md`、v1 の値は `revealjs-diagram-theme.scss`。評価軸: ①目線の迷い、②文字の少なさ（情報量が少ない）、③使い分けの分かりにくさ。方針（ユーザー、11-06）: 色は黒・グレー・強調色（濃青系）のモノトーン。カラフルにしない。

## 見本の作り方（何度でも作り直せる）

`records/build_dads_sample.py` が、v1 の SCSS を色（`PALETTE`）と余白（`SPACING`）で置換した DADS 案を作り、v1 と並べて render する。微修正は `PALETTE` の値を直して再実行する。

```
cd topics/revealjs-slides/records
python -I build_dads_sample.py            # 余白も 8 の倍数にする。--no-spacing で色だけ
```

出力: `records/dads-sample/v1/v1.html`（現行）と `records/dads-sample/dads/dads.html`（DADS 案）。17 枚、同じ qmd。`dads-sample/` は一時扱いでコミットしない。v1 の SCSS は変えない。既知の差: 画面左下のメニューと下の進捗バーは Quarto 既定の青のまま（DADS 案に未反映）。

## 1. 色（重要。先に決める）

コントラスト比は WCAG の式で計算した（白は `#fff`）。DADS の基準: 文字 4.5:1 以上、非文字（枠線・アイコン）3:1 以上。

| 強調の濃い側（`.em` の見出し） | `#174aa3`（8.25） | Blue-1000 `#00118f` | 変更: Blue-1000 | 強調色との差が出る | |

## 3. 余白・レイアウト

| 項目 | DADS | v1 | 提案 | 理由 | 決定 |
|---|---|---|---|---|---|
| 余白の単位 | 8px 基準、3〜5 段階 | `--gap: 0.5em`、`--pad: 0.7em 0.9em`、`--ind: 40px`（em は文字により変わる） | **変更: px の 8 の倍数に寄せる**（`--gap` 8px、`--pad` 16px 24px、`--ind` 40px はそのまま。段は 8・16・24・40・64 程度） | 余白の統一（11-06 ユーザーの決定）と DADS が一致。H・I・J で em 由来の余白がサイズでずれるのを防ぐ | |
| 余白の原則 | 関連が強いほど近づけ、階層が下がるほど小さく | 箱の行間 1.1em、見出しの下 0.8em | 維持（原則を設計の言葉にする） | 目線の迷い（①）に効く | |
| ガター | 本文の文字サイズの 2 倍 | 0.5em（約 14px） | **不採用** | 28px の 2 倍は 56px。スライドでは箱が狭くなり、文字が減らせない（②）。DADS はウェブページ向けの値 | |
| 12 カラムとカラム割り | 6+6、4+4+4、3+9 など | A=1:1、B=1:矢印:1、行・列は自由 | 一部採用: **2 分割は 6+6、3 分割は 4+4+4 を既定にする**（H・I・J の列は数に応じた等分） | 列幅の目安だけ借りる。「行・列が自由」は残す | |
| ブレークポイント 768px | モバイルとデスクトップ | 固定 1280×720 | **不採用** | スライドは画面サイズ固定 | |
| 角の形状・エレベーション | 角丸 / 影の規定あり（未取得） | 角丸 10px（箱）、4px（格子）。影なし | 保留 | 該当ページは未取得。必要なら次に取る | |

## 5. 決めてほしいこと（差分ごと）

1. 色: 強調を Blue-900 `#0017c1` にしてよいか（v1 の `#1f5fd1` からかなり濃く・紫寄りに変わる）。最大の差分。
2. 色: 青みのグレー（`#1f2933` 系）を、純グレー（DADS の solid-gray）に置き換えてよいか。
3. 色: 箱の 3 種を「青 1・濃灰 1・灰 1」に整理し、クラス名を改めてよいか。
4. 余白: 単位を px の 8 の倍数に寄せてよいか（em の `--gap` `--pad` をやめる）。
5. 行高の 1.5 化と字間の 1〜2%（任意。実スライドで試してから決めてもよい）。
