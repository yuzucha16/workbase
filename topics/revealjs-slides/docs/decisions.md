# 判断の記録（decisions）

## Decisions

### 【この件】トピック `revealjs-slides` を Project 型で起こす（2026-11-06）
- ユーザーの発言: 「トピックを起こしましょう。pc1でも初めての試みでまだ立ち上げ状態です。」「進んでください。」
- 決めたこと: 簡易スライド（Quarto → revealjs）の図解レイアウトを、新しいトピックで育てる。完了条件は、inv 型の成果物に revealjs の HTML スライドを作る土台ができること。正式な pptx は `office-output-types` で別に扱う。
- 根拠: 確定ではなく拡張していく土台で、経緯と部品（見本・CSS）を置く場所が要るため。

### 【この件】置き場: 型・原則は lessons、見本と CSS はトピックの records（2026-11-06）
- ユーザーの発言: 「その案にします。」「コミットします。」
- 決めたこと: 型・原則・落とし穴を `exmem/lessons/revealjs-diagram-layout-output.md` に統合し、見本と CSS は `records/` に置いたままにする。写真フォルダはユーザーが削除した。
- 根拠: 部品（約 20KB の見本）を lessons に入れると読み込みが重くなる。


### 【この件】改善案は 1・2 を優先し、いまは大枠に絞る（2026-11-06）
- ユーザーの発言: 「1,2が重要ですね。pc1では生成スクリプトをpythonで作って内部で叩くようにしていました。」「現時点では特にないです。細部を見始めたら直すようにします。いまは大枠に絞ります。」
- 決めたこと: 改善案 1（アイコン定義を `include-before-body` の別ファイルへ）と 2（生成スクリプト。Python）を優先する。フォント、余白、手順書は、ユーザーが細部を見始めたら直す（保留）。
- 根拠: 見本の手書き SVG は約 20KB で、スライド化を簡単にするには生成が要る。PC1 では Python の生成スクリプトで実績がある。

### 【この件】pptx のレイアウト例を revealjs に使い回す（2026-11-06）
- ユーザーの発言: 「レイアウト例はpptxベースのものを私がたくさん持っています。それをrevealjsにも使いまわせるようにしたいです。」「わたしがpptxを渡します。」
- 決めたこと: pptx ベースのレイアウト例を、現在の 6 型（A・B・D・E・F・G）への当てはめと、足す型の材料にする。pptx はユーザーが渡す。
- 根拠: レイアウトの資産が pptx に多くあり、revealjs でも同じ型で使えるようにするため。

### 【この件】pptx の例から H・I・J を足す。表現は「行・列の数が自由」と「余白の統一」を押さえる（2026-11-06）
- ユーザーの発言: 「良いです。ここでのポイントは表現方法として、行列を増やすとか余白をきれいに使うとかそういう点を抑えてほしいです。」「良いです。」
- 決めたこと: 型 H（行ラベル × 列）、I（工程 × 行。シェブロンの見出し）、J（表）を足す。順は、生成スクリプトを先に作り、その上に H・I・J を載せる。行・列の数は文言の数で決め、余白は `--gap` と `--pad` の 2 つに集約し、高さ `--h` を等分して下を空けない。
- 根拠: pptx の例 33 枚の多くが、行ラベルと工程見出しを軸にした格子で、行・列の数だけが違う。階段と 3 要素は、H・I で足りるか見てから決める。

### 【この件】実スライドは PC1 で作る。H・I・J は先に room で確かめる（2026-11-06）
- ユーザーの発言: 「未確認はnext actionに積んでください。roomでHIJを見たいです。使いたい題材はあるのですが、pc1で作りたい。」
- 決めたこと: 未確認（room・PC1・ほかのブラウザ、PC1 のスクリプトとの見比べ、階段・3 要素の判断）を Next Actions に積む。H・I・J は room で見る。実スライド（NA の完了条件）は、題材が PC1 側にあるため、PC1 で作る。
- 根拠: 題材が PC1 の環境にあり、このリポジトリには置けない（共有の範囲）。

### 【この件】見本を基本形にする: 文字 28px、固定のインデント、行は 3 つまで（2026-11-06）
- ユーザーの発言: 「読めます。これで fix」「4 行で OK」「これをまずは基本形としていきましょう。」「構造化は 3 要素以上あれば再分割するので、実用途としては 3 程度が上限になるはず」
- 決めたこと: `records/` の見本を基本形とする。基準の文字サイズ 28px、インデント `--ind: 40px`、タイトル下 0.8em、H・I・J の高さ 560px。見本の行は 3 つまで。
- 根拠: 実用では、3 要素を超える内容は再分割して別のスライドにするため、行数の多い型を作り込まない。

### 【この件】図解なしの型 T を型に含め、10 型にする（2026-11-06）
- ユーザーの発言: 「全部レイアウトはむりがあるので、p13 まとめ のような質素だけど、文字が箇条書きで並ぶものもレイアウトに含めます。」
- 決めたこと: T（見出し + 段落 + 箇条書き）を正式な型にする。A〜G に spec の `"height"` を足し（下の空きを埋める。図が無い箱は文字 0.9em）、実スライド（room 導入 LT、一時扱い・未コミット）で確かめた。ユーザーは `gen_layouts.py` と scss の変更を承認した。
- 根拠: 実スライドの 12 枚のうち、まとめ・前置きは図解にしづらく T で足りた。
