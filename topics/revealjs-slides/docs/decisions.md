- ユーザーの発言: 「デジタル庁のデザインシステムの情報を言語化・取捨選択して取り込みたい」「目線が迷う、文字が少ない、使い分けがわかりにくいです」「カジュアル、簡易スライドで良いです。フォーマルは別の型でpptxに仕上げます。ただ、markdown -> {quarto/revealjs, pptx}のパスは変わらないので共通構成として使えるものは流用したい」「1.からいきましょう」
- 決めたこと（仮）: ①取り込みは原則とトークンを言語化した要約と出典リンクだけで、原文は転載しない（公開リポジトリ）。②用途はカジュアルな簡易スライドのまま。pptx 側と共通にできる構成（情報設計・文章の規則・トークンの値）は、revealjs 専用の CSS と分けて持つ。③順序は、一次情報の取得 → 取捨選択表 → 土台の更新 → 型の再設計。型の再設計は取捨選択表が固まるまで着手しない。④型の評価軸は、目線の迷い、情報量の少なさ（文字が少ない）、使い分けの分かりにくさ。
- 取り下げ・見直し: 11-06 の「基本形を確定」（28px、青 1 色、`--ind` など）は、取捨選択表で差分ごとに採否を決める。それまでは維持する。
- 根拠: 型が土台（トークン・骨格）の組み合わせなので、土台が動くと全型が動く。

### 【この件】表・工程・箱を罫線だけにし、図表の上下に総評を置く（2026-11-06）

- 根拠: 参考画像（ユーザーが貼付）と、`gen_layouts.py` の SAMPLE の p10・p12。

- 決めたこと（2026-11-06、見出し・T の軽量化）: h2 を 1.5em、h3 を 1.1em（いずれも太字・墨色 #1a1a1a・行高 1.4）、本文と箇条書きを 0.9em・行高 1.5 にした。装飾は足さない。
- 根拠: DADS の階層で大きさを下げる原則と行高の下限。ユーザーの目視で戻せる（scss の末尾 1 節）。


- 決めたこと（2026-11-06、ユーザー）: ①h3 も他と同じ 1 段（--ind）インデントする（軽量化の margin 指定が左余白を消していたのを直した）。全スライド共通。②T の段落と箇条書きの開始位置を揃える（箇条書きの行頭記号を段落の左端に合わせた。2.5 段は廃止）。③箇条書きは 2 段（入れ子 1 回）まで。`gen_layouts.py` が 3 段目で止まる。④スライドタイトル(h2)の先頭に濃青の細い縦棒（6px）。

- 決めたこと（2026-11-06、ユーザー）: ①T は spec の `side`（`code`+`lang` か `img`+`alt`）で右側にコード・画像を置ける（左＝文章、右＝図物）。②A〜G も表と同じく `lead`（上）と `notes`（下）の箇条書きを持てる（`slide()` が全型で処理しており、新しい実装は要らない。二重管理を避け、仕様は `gen_layouts.py` の docstring を正とする）。③目次の型は DADS に見本があるか未確認のため保留。

- 決めたこと（2026-11-06、ユーザーが目視して確定）: 【この件】目次は型 C（DADS の「目次」コンポーネントは web ページ内ナビで、点線の箱 + 入れ子の箇条書き）。スライドでは DADS の表の流儀（背景なし・罫線だけ）に合わせ、番号 + 章名 + ひとこと + 小項目の罫線一覧にした。current で章の区切りに再掲するときの表示中の章だけ薄青の地。DADS の「見出しを消さない」「見出しの文言をそのまま使う」は、章名をスライドタイトルと揃える運用で守る。
