# 憲章・WBS・マイルストーン: 会議録のナレッジ化

元は [[private-knowledge-6r]]。作り方のメモは [[private-knowledge-plan-notes]]。手順は `workflow-kit/start-plan.md`。日付と予算は推測。

## 憲章

| 欄 | 内容 |
|---|---|
| 名前 | 会議録のナレッジ化（`private-knowledge`） |
| 更新日 | 2026-10-21 |
| 使命（What） | 顧客を含む打合せ内容を、Area 内に1ファイル2層（冒頭の数行＝人向け、本文＝AI 向け）で残し、Project を跨いで引ける型と流れを決める |
| ビジネスの目的（Why） | 打合せの決定・ToDo が Project に閉じず、Area 全体に効く知識になる。AI 向けと私向けを、周りと同じ仕組みで管理する |
| 完了時期 | 2026-10-28（バッファは 10-29 以降に別に置く） |
| 予算 | ユーザーの判断 5 回、3 セッション（推測） |
| 品質 | 型・タグ・索引・昇格の流れが、既存（`lessons` / `explain`）と同じ。ファイル分割は最小。公開リポジトリに顧客情報が入らない。`ai/in` に渡す写しがマスク後の語だけになる |
| 指標 | 実例1件で、冒頭の数行に収まった決定・ToDo の数と、人が直した箇所の数 |
| 承認が要る変更先 | `workflow-kit/`（`stock-hook.md`、`integrate-hook.md`、`methods.md` ほか）。ユーザーの承認なしに書き換えない。works 側の雛形はこのリポジトリの外 |
| 出力の機微 | 型・規則・マスク済みの見本は公開してよい。実例（顧客名・案件の内容）は works 側だけ。通し試験の結果は、数字だけをこのリポジトリに書く |

全員がユーザーの題材なので、メンバー・リーダー・オーナーの欄と、必要なマイルストーンの欄は省いた。
