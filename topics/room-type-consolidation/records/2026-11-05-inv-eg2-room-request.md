# inv の工程別構造の実験 2（room 版）: 依頼文と手順（2026-11-05）

同じ CSV を、部屋なしの実験（`2026-11-05-inv-eg2-population-csv.md`）と部屋ありで比べる。部屋は `myenv`（internal）、Project は `sample_inveg2`（`open` 済み、README はひな形のまま）。決定は `docs/decisions.md`、状態は `docs/log.md`。

## 比べる観点（結果を見るとき）

1. 聞き返し: 用途・読者を聞かれたか。部屋なしでは聞かずに「仮定」と書いた。
2. 置き場: `ai/in/`（読み取り専用）、`ai/work/raw/`、`ai/work/scripts/`、`ai/out/<成果物名>/` で迷ったか。
3. 落とし穴: 0A・0B の二重計上、沖縄 1945 の「-」、末尾の注 2 行、cp932、コードの先頭 0 を、同じように見つけたか。
4. 道具: Python と表計算ライブラリ（部屋の `init` が入れたもの）で足りたか。部屋なしは標準ライブラリだけだった。
5. internal の流れ: `mask`（cp932 の CSV が通るか）→ `start --adopt` → 作業 → `restore`・`close` の手間と止まった点。
6. 結論の数字: 部屋なしと一致するか（2010 年が最大、2010→2015 に 39 県が減る、東京圏 28.4%）。

## 人の手順

1. 原本を `projects/sample_inveg2/_noai/raw/c01.csv` に置く（元の cp932 のまま。加工しない）。
2. `uv run room.py mask sample_inveg2`（`mask.toml` は語を書かない。語が無いのでマスクは空のはず。cp932 が通るかが見どころ。通らなければ、そのメッセージを記録し、`ai/in/` に直接置いて `start --adopt` する）。
3. `ai/in/` の中身を読んで `uv run room.py start sample_inveg2 --adopt`（初回の `start` は止まるので、案内に従う）。
4. 部屋の AI に、下の依頼文を渡す。
5. 終わったら `restore` → `close`。止まった点を記録する。
6. 部屋の返答と `ai/docs/inv-log.md` を、別のセッションでこちらに見せる。

## 依頼文

````
これは inv(調査)の工程別構造の実験です。調査の中身と、構造が使えたかの両方を見ます。同じお題を、部屋なしでも別に行っています(結果は見せません)。

【お題】社内の Excel を想定して、ai/in/ の c01.csv を分析し、示唆を出すところまで一周してください。c01.csv は「男女別人口－全国，都道府県(大正9年～平成27年)」で、政府統計(国勢調査)の一次データです。
【用途】読者は依頼した本人です。用途は、あなたが必要と思うなら聞いてください。聞かずに進めるなら、仮定を question.md の冒頭に書いてください。

【進め方】ROOM.md を読んでから始めてください。成果物名は sample_inveg2(Project 名と同じ)。置き場は ai/out/sample_inveg2/ で、次の構成要素から、必要になったものを、最初のファイルが来たときに作ります。構成の正本は ~/shared/workflow-kit/project-structure.md の inv の節です。
- question.md: 問い、読者、範囲、完了条件、品質条件
- sources/sources.md: 情報源台帳
- findings/: 問いごとの事実表(行 ID を付ける)
- checks/checks.md: 突合表、未確認の一覧(表データのときは、取り込みの落とし穴も)
- report.md: 結論、示唆(1 章)、根拠の番号、確認できなかった点
- publish/: 清書。今回は頼みません(作らない)

【工程】問いを立てる → 情報源を決める → 集める・集約する → 裏取りする → 示唆を出す。各工程の終わりで、ai/docs/ の inv-log.md に、所要の目安、迷った点、構造が合わなかった点を 2〜3 行書いてください。最後に、構造への改善提案(足す・減らす・名前を変える)を 5 行以内で書いてください。

【品質条件】事実(計算)と推測を分ける。確認できなかった点を report.md に書く。データを読み込むときの落とし穴(欠損の表記、集計行、注、文字コードなど)は、checks に出す。

【確認なしで進めてよい範囲】問いの細部、分析の切り口。聞き返すのは、読者や範囲を変えるときだけ。
````
