# 分割して進める試験の結果（2026-11-05〜06）

1 回のプロンプトで終わらせず、新しいセッション（`claude -p` を毎回起動し直す）で工程ごとに進める基本形を、`dev` と `inv` で試した。部屋 `room-myenv`（internal）、Project は `sample_splitdev` と `sample_splitinv`。人の役は、エージェント（こちら）が判断・承認の文を書いて演じた。起動は `records/run-split.sh <Project> <番号>`（プロンプトは各 Project の `ai/records/p/p<番号>.txt`）。

## 流れ（6 回）

| 回 | 依頼（要旨） | dev（csvinfo） | inv（uv と pip-tools） |
|---|---|---|---|
| 1 | 計画を立てて。今回は 6R まで | 6R。論点出しは省略 | 6R + 末尾に選択式の質問 |
| 2 | 続きです。論点出し | 11 件の論点表（`work/plan/issues.md`） | 11 件の論点表 |
| 3 | 判断を返す・承認・最初の工程まで | 書き戻し・承認・環境（`pyproject.toml` `uv.lock`）。「確」の項目を使い捨てで実施 | 書き戻し・承認・`question.md` `sources/`。「確」（`uvx` が動くか）を実施 |
| 4 | 次は src／findings まで | 本体。6R にない 2 点を決めて `decisions.md` に記録 | `findings/` と代表例 2 本の実測 |
| 5 | 次は tests／checks まで | テスト 13 件 | 突合表・未確認。**前回の自分の計測値（30 秒）が再現せず撤回**し、`findings.md` は触らず `checks.md` に訂正 |
| 6 | 最後。報告まで、終える前にやることも | README・報告・`close.md` | 報告・`close.md` |

## 同じ観点で動けたか: 動けた

- **引き継ぎ**: 依頼は「続きです。次は X まで」の一文だけ。`ai/docs/log.md`・`decisions.md`・`ai/work/plan/` から文脈を拾い、前の回を再説明させずに続いた。
- **範囲**: 「その先にはまだ進まない」を 6 回とも守った。
- **記録**: 判断は `decisions.md`、状態は `log.md`、承認は `6r.md` に残った。判断の来歴（誰が決め、AI が何を決めたか）も区別して書かれた。
- **裏取りの観点**: 事実と推測の分離、未確認の明記、実測の撤回が、分割しても保たれた。
- **終わり方**: 依頼文に書かなくても `ai/out/close.md`（完了条件の照合、未解決の振り分け、【汎用】候補、人が行うこと）を書いた。

## 足りなかった点と対応

| # | 点 | 原因 | 対応 |
|---|---|---|---|
| 1 | dev の成果物が `out/csvinfo/`（Project 名と違う）。`room close` が渡すのは `ai/out/<Project 名>/` の下だけなので、渡らない。dev の `report.md` が `ai/out/` 直下に出た | 1 回目の 6R で AI が名前を自由に決め、以後の回が引き継いだ | `project-structure.md` に「複数回に分けて進める」を追加（成果物名は Project 名、`report.md` は成果物の下）。`plan-fields.md` に 1 行 |
| 2 | inv の試験用スクリプトが `out/…/src/`（inv に `src/` は無い。正は `ai/work/scripts/`） | 1 回目の 6R の「変更先の洗い出し」に `src/` が書かれ、引き継がれた | 同上（6R の変更先は type の構成要素の名前で書く） |
| 3 | dev の 6R が承認後に `仮` へ戻った | AI が 6R に進捗を書き、次の `start` が `仮` に戻す仕様に当たった | 同上（承認後は 6R を書き換えない。進捗は `log.md`） |

## 修正の再試験

修正後に新しい Project（`sample_split2inv` `sample_split2dev`）で 1〜3 回目を再実行した。結果:

- inv の試験用スクリプト: `ai/work/scripts/`、計算出力は `findings/` と `work/raw/`。`src/` は作られなかった。点 2 は解消。
- 6R: 承認後も `正式` のまま（3 回目まで）。点 3 は解消。
- 回収の不具合: 前の回の後にマウントが残り、dev の 3 回目が起動しなかった（`room umount --area myenv` で外して再実行した）。点 5 は、並行しなくても起きる。原因は未調査。
