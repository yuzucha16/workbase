# Marp・Slidev・Quarto の実機比較（2026-11-04）

部屋（WSL。Quarto・Chromium・LibreOffice 入り）で、同じ内容（日本語の箇条書き・表・発表者ノート）から pptx を出した。Marp CLI 4.5.1、Slidev CLI 53.0.0、Quarto は部屋の版。導入は root（`/usr/local` は `ai` が書けないため。`npm i -g` を root で）。

| 項目 | Quarto | Marp（既定） | Marp（`--pptx-editable`） | Slidev |
|---|---|---|---|---|
| 出力 | 約 1.7 秒。4 枚 | 約 2 秒。3 枚 | 約 2.5 秒。3 枚 | 約 5.4 秒。3 枚（初回の依存の事前ビルド込み） |
| 編集 | 可（文字・表が本物） | 不可（スライドが画像） | 文字は可 | 不可（スライドが画像。実測） |
| 日本語 | 正常 | 画像なので見た目のみ | 「⽐」「⽇」など康熙部首の互換文字に化ける（検索・置換で当たらない） | 画像なので見た目のみ |
| 表 | 本物の表（`a:tbl`） | 画像 | 表が壊れる（セルが空白区切りの文字に） | 画像 |
| ノート | 入る | 入る | 失われる | 入る |
| Mermaid | 画像で入る（部屋の mmdc） | 今回は入力に入れず | 同左 | 同左 |

## 見立て

- 編集できる pptx を出せるのは Quarto だけ、という eg1 の結論は実機でも成り立った。Marp の編集版は実験的機能で、表・ノート・日本語の字形に問題がある。
- Marp が部屋で動くには、ブラウザの指定が要る: `--browser-path /usr/local/bin/room-chrome`（`--no-sandbox` を付ける薄い包み）。
- Marp は標準入力を読むので、スクリプトから呼ぶときは `</dev/null` を付ける。
- Slidev も pptx は画像（Marp 既定と同じ型）。ノートは入る。編集できる清書は Quarto、という結論は変わらない。
- Slidev を部屋で動かすのに要った準備（root）: ①`@slidev/theme-default@0.25.0` と `playwright-chromium`（1.64.1。ブラウザのリビジョン 1248 が部屋と一致）を作業フォルダに入れる、②Vite のキャッシュ用に `@slidev/cli/node_modules/.vite` を `ai` が書ける形で作る（無いと `EACCES` で、ページが出ず 33 秒で時間切れ）。実行時は `PLAYWRIGHT_BROWSERS_PATH=/opt/ms-playwright`。`init` の道具へ昇格するなら、この 2 点が論点（導入の手間は Marp より大きい）。
- 未確認: pptx の見た目（スライドの絵）。部屋で `soffice` の PDF 化が出力を作らず、原因は未調査。

## Marp 既定と Slidev の見た目・表現幅（画像で見比べた。同日）

同じ内容（表紙・箇条書き・コード・表・Mermaid・まとめ）を PNG にして目で比べた。Marp は組み込みテーマ `gaia`、Slidev は既定テーマ。

| 観点 | Marp | Slidev |
|---|---|---|
| 既定の見た目 | `gaia` などの組み込みテーマ（3 種）で、色・表紙・コードの枠が最初から整う | 既定テーマは白地に黒でほぼ装飾なし。見栄えは別テーマ（追加導入）か CSS 次第 |
| 表 | 既定テーマでは内容の幅に縮み、スライドの左に寄る | 全幅で罫線が細く読みやすい |
| コード | 背景色つきで見やすい（`gaia`） | 薄い灰色の枠。構文の色つき |
| 段組み | CSS・HTML を書けば可（素の Markdown にはない） | `layout: two-cols` が標準（ただし既定では上寄せで余白が大きい） |
| Mermaid | 単体では描けない（画像を貼る） | 標準で描ける（日本語も正常） |
| 表現の幅（HTML で見せる場合） | ディレクティブ・背景画像・CSS テーマ | Vue の部品、クリックの段階表示、書き込み、ライブのコード |
| pptx に残るもの | 見た目のみ（画像） | 見た目のみ（画像）。クリックの段階表示・動く部品は消える |
| 導入の手間 | 低（全体に 1 つ + ブラウザの指定） | 高（テーマ・playwright・Vite のキャッシュ用フォルダ） |

注意: 入力は小さい見本で、Slidev は既定テーマだけ。他のテーマ・実際の資料量では差が変わりうる。

## 示唆（二択の整理）

- pptx が成果物なら、Slidev の強み（段階表示・Vue の部品・ライブ）は pptx で消える。残る優位は「Mermaid が標準」だけで、Quarto も Mermaid を画像で入れられる。Marp 既定と比べて、導入の手間（root の準備 3 点）に見合わない。
- 「お手軽に画像の pptx」なら Marp 既定が合う: 導入が軽く、組み込みテーマで見た目が最初から整い、ノートも入る。
- 「初版を AI が作り、人が微修正」なら Quarto: 文字・表・ノートが本物で編集できる。見た目の自由度は既定テンプレート（`reference-doc`）次第。
- Slidev を選ぶのは、HTML で発表する（クリックの段階表示やライブのコード）が主で、pptx は副産物のとき。
- 未確認: Marp・Slidev のテーマを替えたときの差。Quarto の `reference-doc`（テンプレート）を替えたときの差。

## Quarto の pptx の見た目（LibreOffice で PDF にして見た。同日）

- 部屋の `soffice --headless --convert-to pdf q.pptx` は動いた（先に出力が出なかったのは、最初の実行のプロファイル作成か時間切れとみられる。原因は未特定）。部屋に `pdftoppm` が無いので、PDF はホストへ取り出し、`uv run --with pymupdf` で PNG にして見た。
- 既定テンプレートは素の Office 風: 白地・黒字、タイトルは中央、表は青の見出し行と縞で、本物の表として自然。日本語は正常。
- 弱い点: インライン `コード` の装飾が消える。図のスライドは、タイトルが小さく左上、図が右寄りで、タイトルと図の位置が揃わない（LibreOffice での表示。PowerPoint では差がありうる）。
- 結論: 初版としては読める。見栄えは Marp の組み込みテーマより素朴で、整えるなら `reference-doc` で社内テンプレートを当てるのが筋。人の微修正を前提にする使い方に合う。
