## 3. 活動と成果物の繋がり（提案）

添付の分類（Research → Analysis → Planning → Execution。排他的でなく、反復する）を、**ディレクトリごとの「主に使う活動」**として緩く対応づける。型を縛るのではなく、「この活動をしたら、ここに跡が残る」の表にする。

### `ai/` 直下

| 場所 | 用途 | 主な活動 |
|---|---|---|
| `ai/ctx/` | 前提の写し（Project と Area の README）。読むだけ | （前提） |
| `ai/in/` | 人が渡した入力。調べて得た資料、承認版の計画（`in/plan/`）、マスク済みのデータ、前の Project の成果物。読み取り専用 | Research の結果を受け取る |
| `ai/work/` | 途中の作業。集めた資料、整理、設計の下書き、試行、使い捨てのスクリプト。捨ててよい | Research（集める）、Analysis（整理する）、Planning（案を作る） |
| `ai/out/<成果物名>/` | 成果物 1 つ。基準文書と検証を伴う | Planning の結果と Execution の結果 |
| `ai/docs/` | 作業の記録（`log.md` `decisions.md`）。判断と状況 | 全活動の跡（何を決めたか） |
| `ai/records/` | 機械が書く実行記録。人も AI も読む | Execution の跡 |

### `dev` の成果物（`ai/out/<成果物名>/`）

| 場所 | 用途 | 主な活動 |
|---|---|---|
| `docs/` | 基準文書。何を満たすか（要求）、どう作るか（機能）、どう使うか（運用） | Planning（要求・設計を決める） |
| `src/` | 本体。正本と派生物 | Execution（作る） |
| `env/` | 実行環境の定義。セットアップ、コンテナ、版の固定 | Execution の前提（環境を作る） |
| `tests/` | 基準文書の検証項目に対応する検査 | Execution の確認（要求を満たすか） |
| `tools/` | 変換・生成・実行の補助スクリプト。**成果物を作る・動かす側**（検査は `tests/`） | Execution の補助 |
| `report.md` | 実行の結果（`env/` の確認結果と版、`tests/` の実行結果） | Execution の結果の報告 |

### `inv` の成果物

| 場所 | 用途 | 主な活動 |
|---|---|---|
| `report.md` | 結論、出典、確認できなかった点 | Research と Analysis の結論 |

流れの目安は、`ai/in/`（Research の入力）→ `ai/work/`（Analysis・Planning の途中）→ `docs/`（Planning の結論）→ `src/` `env/`（Execution）→ `tests/` `report.md`（確認）。
