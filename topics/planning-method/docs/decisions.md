- 決めたこと（ユーザー）: トピックを明示する経路が無く、トピックの必要性自体を試行中なので、置き場は案④（`topics/kit-growth/plans/`）と合わせて `planning-method` の昇格のときに決める。それまでは都度ユーザーに聞く（`workflow-kit/start-plan.md` の「置き場」）。

- **2026-10-21 に置き換え**: 仮決め 〜2026-10-28 で、題材ごとのトピックの `records/` に置く運用を先に始めた（workbase 直下 `docs/decisions.md` の同日の項）。

### 【汎用】計画のやり方を、試験運用で `workflow-kit/` に昇格する（2026-10-20）
- 決めたこと（ユーザー）: `review 消化` の3層（待ち行列 → サブエージェントのスクリーニング → 最終判断）を通り、正式化した。`planning-method-draft.md` の骨子を `workflow-kit/` の新ファイルと `methods.md` の新区分「計画」に、試験運用で取り込む。実装は別セッション。
- スクリーニング（型 D: 新ファイル・新区分・`start 計画` の登録を1承認にまとめた。食い違う過去の決定は無し）。覆す可能性は低〜中。
- 見直しの条件と戻し方（AI の提案を承認の対象に含めた）: 取り込み後の品質チェック3回の結果で見直す。使われなければ、新ファイルと `methods.md` の区分を削除して戻す（履歴は git）。
- 同日、振り返り（改善4）に計画を入力として足す案は保留（〜2026-11-11。直下 `docs/log.md` の Open Questions）。

### 【この件】計画のやり方を試した出力は、トピックの `records/` に置く（2026-10-20）
- 決めたこと（ユーザー）: 試行の出力（6R、憲章・WBS・マイルストーン、作り方のメモ）は `topics/planning-method/records/` に置く。最初は `topics/kit-growth/records/` に置いたが、ユーザーが移した。**2026-10-21 に変更**: 題材ごとのトピック（`topics/usage-viz/`、`topics/stock-modes/`、`topics/private-knowledge/`）の `records/` に置く。`planning-method/records/` は空になった。
- 根拠: 直前の決定（進行中の取り組みはトピック直下）に合わせる。測ったことの記録 `planning-method-record.md` は `kit-growth/records/` に残っている（分け方は見直しの対象）。

### 【汎用】計画のやり方を、トピックとして kit-growth の records から切り出した（2026-10-20）
- 決めたこと（ユーザー）: `records/` は測ったこと（確認用）だけにし、進行中の取り組みは `topics/` 直下の Project 型トピックにする。まず計画のやり方だけで様子を見る。kit-growth（Area 型）は残す。
- 根拠: records に下書き・決定・次の一手まで入っていて見通しが悪かった。窓口と `docs/log.md` という既にある仕組みで進捗が1か所で読める。
- 見直しの条件: 様子を見た後、週次・日次・AI 作業部屋の振り返りなど他の取り組みにも広げるかを決める。

### 【汎用】新区分「計画」に、6R からマイルストーンまでの1セットを試験運用で置く（2026-10-19）
