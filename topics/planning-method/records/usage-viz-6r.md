# 6R: セッション別トークン・コスト可視化

計画のやり方の試行（[[planning-method-draft]]）。出力は [[usage-viz-plan]]、作り方のメモは [[usage-viz-plan-notes]]。

要求: 各セッションのトークン使用量・価格($)・キャッシュの利用状況を可視化したい。
条件: ランキング、使用量が多いときの傾向など分析用途。CLIベースの定期確認で十分。

## 前提の表（読みが割れる）

| 読み | 内容 |
|---|---|
| A | 既存ツール（ccusage など）を導入して使う |
| B | ログ（JSONL）を集計する小さなCLIを自作する |
| **C（仮置き）** | 既存ツールで試し、足りない分（ランキング・傾向）だけ自作する |

## 状況

- Claude Code でセッションを重ねているが、トークンと費用の内訳は見ていない。〔資料〕
- セッションのログに、トークン種別の使用量が残っているはず。〔推測〕
- キャッシュが効いているかも見えていない。〔資料〕

## 問題意識

- どのセッションで使用量が膨らむのか分からない。〔資料〕
- 使用量が多くなる条件（モデル、長さ、キャッシュの効き方）に傾向があるか分からない。〔推測〕
- 見えないので、使い方を見直す根拠がない。〔推測〕

## 要求

- セッションごとにトークン・価格($)・キャッシュ利用を可視化したい。〔資料〕
- 用途は分析（ランキング、多い時の傾向）。〔資料〕
- 形はCLIで、定期確認で足りる。〔資料〕

## 意図・裏づけ・仮説

- 意図: 傾向をつかんで使い方を見直す。ツール作りは手段で、定期確認で判断に使えることが目的。
- 仮説: 長いセッションや、キャッシュ作成が多いセッションに費用が偏る。〔推測〕
- 裏づけ（未確認。最初に確かめる）: ログに入力・出力・キャッシュ作成・キャッシュ読取の項目がある。単価表は改定で変わるので、出典と取得日を残す。〔推測〕

## 今回のスコープ（期日: 2026-10-26 月）

- 対象: セッション別の集計（トークン・概算価格・キャッシュ利用率）、ランキング、傾向（日別・モデル別など）、定期確認の手順。
- 対象外: Web画面やグラフ、リアルタイム監視。
- 前提と注意: ログは個人の作業内容を含むので、公開リポジトリには仕組みだけを置き、実データは置かない。

## 期待する成果

- 週1回のコマンド実行で、上位セッションと傾向を確認できる。
- 指標（1つ）: 直近7日分の全セッションを集計でき、既存ツールまたは `/cost` の合計と±5%以内で一致する。〔推測〕
- 未決: 価格の算出に、キャッシュ作成の単価をどう扱うか。
