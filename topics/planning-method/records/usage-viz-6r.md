# 6R: セッション別トークン・コスト可視化

計画のやり方の試行（[[planning-method-draft]]）。出力は [[usage-viz-plan]]、作り方のメモは [[usage-viz-plan-notes]]。

要求: 各セッションのトークン使用量・価格($)・キャッシュの利用状況を可視化したい。
条件: ランキング、使用量が多いときの傾向など分析用途。CLIベースの定期確認で十分。

## 前提の表（読みが割れる）

| 読み | 内容 |
|---|---|
| A | 既存ツール（ccusage など）を導入して使う |
| B | ログ（JSONL）を集計する小さなCLIを自作する |
| **C（確定。ユーザー、2026-10-20）** | 既存ツールで試し、足りない分（ランキング・傾向）だけ自作する |

## 状況

- Claude Code でセッションを重ねているが、トークンと費用の内訳は見ていない。〔資料〕
- セッションのログに、トークン種別の使用量が残っているはず。〔推測〕
- キャッシュが効いているかも見えていない。〔資料〕

## 問題意識

- どのセッションで使用量が膨らむのか分からない。〔資料〕
- 使用量が多くなる条件（モデル、長さ、キャッシュの効き方）に傾向があるか分からない。〔推測〕
- 見えないので、使い方を見直す根拠がない。〔推測〕

## 要求

- セッションごとにトークン・価格($)・キャッシュ利用を可視化したい。〔資料〕
- 用途は分析（ランキング、多い時の傾向）。〔資料〕
- 形はCLIで、定期確認で足りる。〔資料〕

## 意図・裏づけ・仮説

- 意図: 傾向をつかんで使い方を見直す。ツール作りは手段で、定期確認で判断に使えることが目的。
- 仮説: 長いセッションや、キャッシュ作成が多いセッションに費用が偏る。〔推測〕
- 裏づけ（未確認。最初に確かめる）: ログに入力・出力・キャッシュ作成・キャッシュ読取の項目がある。単価表は改定で変わるので、出典と取得日を残す。〔推測〕

## 今回のスコープ（期日: 2026-10-26 月）

- 対象: セッション別の集計（トークン・概算価格・キャッシュ利用率）、ランキング、傾向（日別・モデル別など）、定期確認の手順。
- 対象外: Web画面やグラフ、リアルタイム監視。
- 前提と注意: ログは個人の作業内容を含むので、公開リポジトリには仕組みだけを置き、実データは置かない。

## 期待する成果

- 週1回のコマンド実行で、上位セッションと傾向を確認できる。
- 指標（1つ）: 直近7日分の全セッションを集計でき、既存ツールまたは `/cost` の合計と±5%以内で一致する。〔推測〕
- 未決: 価格の算出に、キャッシュ作成の単価をどう扱うか。

## フィードバック（実行後。2026-10-20）

実際に作って動かした後の振り返り。試行の1題材（ツール開発）の所見で、一般化は昇格の前に判断する。

### あってよかった欄

- **前提の表（読み A/B/C）**: 読みが割れた点をユーザーに確認できた。ただし実行では、既存ツール（ccusage）は「本体」でなく「突合先」になった。A/B/C の選択肢に、既存ツールの役割（本体・突合先・使わない）を分けた行があると、実態に合う。
- **〔資料〕〔推測〕の区別**: 効いた。「ログに入力・出力・キャッシュの項目がある〔推測〕」は、最初に確かめて当たった（確認で、同じ応答が複数行に繰り返される落とし穴も見つかった。重複を数えると使用量が膨らむ）。
- **裏づけ（未確認。最初に確かめる）の欄**: いちばん役に立った。確かめた結果と、見つけた落とし穴を書き戻す場所（結果）が6Rに無かった。
- **指標（1つ、±5%）**: 具体的で、判定できた（実際は完全一致）。突合先を先に決めていたので迷わなかった。

### 足りなかった項目

- **用語の定義**: 「作業当たり」「傾向」が何の単位か書いていなかった。要求（ユーザーの追加の説明）で「月次・週次、ランキング、作業当たり、平均・最大・最小」と具体化されて、初めて作れた。要求の欄に、「見る単位（期間、セッション、プロジェクト）と統計量」を書く行がほしい。
- **対象外の見直し条件**: 対象外に「Web画面やグラフ」と書いたが、翌日に「HTML のレポートがほしい」と言われた。対象外は、理由と、見直す条件を添える。
- **出力の置き場と機微の扱い**: 「公開リポジトリには仕組みだけ」は書けていたが、出力の置き場（HTML はリポジトリの外）は、作る段階で決めた。前提・注意の欄に、「実データ・出力はどこに置くか」を足す。
- **未決の解消先**: 「キャッシュ作成の単価の扱い」は、データを見て解けた（ログが5分と1時間を分けていた）。未決に「何を見れば決まるか」を添えると、最初の調べ物になる。

### 使わなかった・薄かった欄

- **仮説**: 「長いセッション、キャッシュ作成が多いセッションに費用が偏る」は、当たった（上位5件で53%、費用の最大はキャッシュ作成の44%）。ただし作り方は変わらなかった。測る道具の計画では、仮説は「使ってみて確かめること」でよく、独立した欄でなくてよい。
- **状況**: 3項目とも問題意識とほぼ同じ内容。1つにまとめられる。

### 粒度

- 6R は、この題材の大きさに対して適切（約60行）。問題意識の3項目は多く、2項目で足りた。
