# 計画のやり方（`start 計画`）の下書きと記録

状態: **下書き。`workflow-kit/` には入れていない**（承認の前。ユーザーの決定、2026-10-19）。承認の手順は、Open Questions に置いて3層に乗せる（`workflow-kit/approval-screening.md`）。6R 自体は3層に乗せない（ユーザーの決定）。

出どころは、芝本秀徳『誰も教えてくれない計画スキル』の型（6R のブランク、プロジェクトチャーター、成果物の WBS、マイルストーン）。ユーザーが図表と本文の一部をキャプチャで共有した。**本全体は読んでいない。図表は写さず、欄の名前と自分たちの言葉の要約だけを書く**。試行の元のファイル（6R が6本、憲章・WBS・マイルストーンの出力が4題材、作り方のメモ）は、モバイル・クラウドの Project の共有フォルダ（`notes/planning-method/`）にある。リポジトリには入れていない。

## 位置付け

- 目的: ユーザーと AI が、目的とゴールを共有する型を持つ。憲章は、手段の目的化を防ぐ資料（ユーザー）。
- 流れ: 6R（要求の整理）→ プロジェクト憲章（定義）→ 成果物 WBS → マイルストーン。後続に課題ログがある（未作成）。
- 単位: 6R 1セットは、PARA の Project 1つに当たる。Project は期限付き。Area は Project の集まり。長い Project の分割・サブプロジェクト化は後で決め、今は期間の上限を4週にする（ユーザーの決定）。

## 手順の骨子（下書き。`start 計画`）

**A 事前の仕込み**

- 6R: ユーザーが「〜したい」の1文と、任意の「条件:」1行を書く。AI が残りの欄を書く。各欄は、見出し1文と箇条書き3つまで。〔資料〕〔推測〕のタグを文に残す。読みが割れるときだけ、前提の表で読み（A〜C）を出し、ユーザーが選ぶ。
- 6R は、期日を今回のスコープの見出しか条件の行に書く（無ければ予算の1週間から出す）。期待する成果は、題材の成果だけにする（試行の評価は別に書く）。数えられる指標を1つ書く（的外れなら「指標なし」も可）。
- 既定値（6R の欄にしない）: 予算（時間）は1週間。稼働日は平日のみ。バッファは土日2日を最後にまとめて置く。体制はオーナー ユーザー、メンバー ユーザーと AI、リーダーは ユーザー 兼任。

**B プロセス**

1. 6R を作る。ここで止まってよい（小さな再開では6Rだけ）。
2. 憲章を作る。欄は、名前、更新日、使命（What）、ビジネスの目的（Why）、目標（完了時期・予算・品質・指標）、メンバー、リーダー、オーナー、必要なマイルストーン（主要3つまで）。対象外・前提・リスク・未決は、出力に載せず6Rに残す。
3. 成果物 WBS を作る。成果物（名詞）で分解する。親は子の足し算で、モレもダブりも無い（100%ルール）。「プロジェクトマネジメント」のまとまり（憲章・WBS・マイルストーン・課題ログ・使い心地の記録）も置く。止まらなければ空になる成果物は、名前に「（条件付き）」を付ける。
4. マイルストーンを作る。置く基準は4つ（フェーズの開始・完了、成果物の作成完了、外部やオーナーとのレビュー、プロジェクト外のイベント）。期間は1・2・4週から選び、上限は3・5・9。開始の承認と終了の判断は数えない。ゴールから逆算して間隔を見る。
5. 出力と作り方のメモを、別ファイルにする。出力は憲章・WBS・マイルストーンの Markdown だけ。作り方のメモは、迷った点・決めたこと・本との違いを書く。

**置き場**（実務の題材）: AI が `ai/work/` で下書きし、ユーザーが承認したものを人が Project の `ai/in/` に置く。基準文書を次の Project に渡す型と同じで、部屋の AI は読むだけ。実務の中身は workbase に入れない。

## Must と Want（叩き台。1事例からの仮説）

- Must: 上の A・B のとおり。〔本〕〔推測〕のタグ。知らないことは推測で埋めず、聞く。
- Want: WBS から憲章への逆向きの確認、計画と実績の日付、課題ログ、動的な確認、「検査を見せて」の運用。

## 決めたこと（ユーザー、2026-10-19）

新区分「計画」に、6R からマイルストーンまでの1セットを、試験運用で置く。手順の本体は `workflow-kit/` の新ファイル、呼び出しは `start 計画`。`start` のインタビュー、`open`、変更のやり方の基準文書、改善4の振り返りは触らない（基準文書との関係だけ1行書く）。仕組みの決定は Open Questions → 3層。仮決めは使わない。品質チェックは取り込んだ後に PC1 で3回。公開リポジトリには本の図表を写さない。

## 測ったこと（試行の記録）

| 対象 | 回数 | 見えたこと |
|---|---|---|
| 6R（要求1文と条件1行から、AI が残りを書く） | 6本（題材はすべて workbase の kit の改善） | 読みが割れる題材は、前提の表で読みを先に出すと効く。前半5欄は「見出し1文＋箇条書き3つまで」が読める。検査・材料・根拠は、出さずに AI の中で行う形にした |
