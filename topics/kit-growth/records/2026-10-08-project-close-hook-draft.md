# Project を閉じる（close）手順書の下書き

> 2026-10-08: 正本は kit（`resources/workflow-kit` の `start-hook.md` `open-hook.md` `close-hook.md`）に移した。このファイルは、実測の経緯（出どころの ID つきの理由）の記録として残す。改善は kit を直す。

状態: **下書き**。最初の Project（`learn-c-pool-allocator`）を閉じるときの手順を、実測しながら起こす。実測で直し、安定したら kit への昇格を判断する（いまは PoC で、kit は変更しない）。判断基準は `docs/decisions.md`（「PARA の `areas/` `projects/` `archives/` の役割と判断基準を定める」の 4・6・7）。

## 閉じる契機

- 完了条件を達成した、中止を判断した、または見直し日を2回超えて更新が無いとき（基準6）。
- **完了条件を達成したら、見直し日を待たずに閉じる**（2026-10-06 ユーザーの指示。AI が「見直し日まで残す」と提案して、直された）。AI は、完了条件の達成を確認した時点で、close を提案する。

## 手順（順序を固定する）

1. **完了条件を確認する**: `README.md` の完了条件を、実測（コマンドと結果）で確かめる。未達なら、閉じずに、残りを Next Actions に書く。
2. **暫定の見直し**: Project で暫定にしていた決定（制約、数値、方式）を、実測で見直す。結果を `docs/decisions.md` に書き、変更するものはユーザーの承認を得る。
3. **未解決を整理する**: Next Actions と Open Questions の残りを、次の Project、親の Area（`areas/<名>/README.md`）、または破棄に振り分ける。持ち越すものは、移し先に書く。
4. **ナレッジ化の候補を示す**: `docs/decisions.md` の `未仕分け` のうち【汎用】の項目を一覧にして、ユーザーに示す。**「ナレッジ化して」は、ユーザーが言ったときだけ実行する**（自動で実行しない。`knowledge-hook.md`）。実行の有無と時期は、ユーザーが決める。
5. **状態を更新する**: `README.md` の frontmatter を `status: done`（中止は `cancelled`）、`closed: <日付>` にする。完了条件の結果（実測の数字）と、成果物の場所を、`README.md` に1段落で足す。
6. **`archives/` へ移す**: 先に、ビルド成果物を消す（`make clean` など。移したあとに未追跡のファイルが残らないようにする）。`projects/<名>/` を `archives/<名>/` に `git mv` する。**ディレクトリごとの `git mv` が失敗したら（`Permission denied`。2026-10-06 に発生）、`git ls-files` を回して、ファイル単位で移す**（履歴は、リネームとして保たれる）。親の Area の一覧（`areas/<名>/README.md`）を、「完了した Project」に移し、リンクを新しいパスにする。ほかの参照（`docs/log.md`、`docs/decisions.md`、`docs/metrics/events.csv` の `project` 列など）は、パスでなく名前なので、変更は不要か、`grep` で確認する。
7. **指標を確定する**: この Project の `events.csv` の行の `adopted` と `reversed` を確定する。`summarize.ps1` の Project の単位で集計して、`docs/log.md` に結果を書く。
8. **記録してコミットする**: `docs/log.md` に、閉じたことと結果を書く（日報の入力になる形）。パスを指定して `git add` し、コミットする（push はユーザー）。

## 初回の実測（2026-10-06。`learn-c-pool-allocator`）

- 手順 6: **ディレクトリごとの `git mv` は `Permission denied` で失敗した**（原因は未特定。シェルやセッションが、作業ディレクトリを掴んでいた可能性）。ファイル単位の `git mv`（追跡している25件。`git ls-files` を回す）で移せた。履歴は、リネームとして保たれた。移したあとに、旧ディレクトリに、未追跡のビルド成果物（`build/`）だけが残ったので、中身を確認して削除した（`make clean` を、移す前に実行する方がよい）。新しい場所で `make check` が通ることを確認した。実行権限（`check-rules.sh`）は、保たれた。
- 手順 6: 親の Area のリンクは、パス付きの wikilink（`[[archives/<名>/README|…]]`）に直した。リンク先の README は、ファイル名が重複するので、ファイル名だけのリンクは使えない。
- 手順 4: 候補（`未仕分け` の【汎用】）は 7 件で、判断しやすい長さ。ユーザーは「あとでまとめて言う」を選んだ（close とナレッジ化は、切り離せる）。
- 手順 7: `reversed` は、「close の時点で採用済みで、現在も維持されている行」を 0 に確定した（25件）。確認期間は設けず、close を確認の時点とした。撤回された行は、その時点で 1 にしておく（今回は無し）。
- 手順 2 の再検討は、実測が決め手になった（ARM の実測で、M0 の除算の依存が出た。ホストでは出ない）。
- 手順 1 の契機: AI が、完了条件の達成後に「見直し日まで残す」と提案して、ユーザーに直された（修正1）。上の「閉じる契機」に反映した。
