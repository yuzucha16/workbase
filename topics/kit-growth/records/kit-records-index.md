# kit の改善記録

`methods.md` のやり方（解決・改善・変更・調査）や、`start` `review` `init 更新` などのモードについて、**測ったこと**（品質チェックと、実運用の振り返り）を残す場所。やり方・モードを横断して、同じ書式で使う。作り方の型は [[method-creation]]。

## 何をどこに書くか

| 書くこと | 置き場 |
|---|---|
| 測ったこと（比較表、各回の直し、残るブレ） | `records/<名前>-record.md`（この場所） |
| 決めたこと（ユーザーの承認つき） | `docs/decisions.md` |
| 経緯 | `docs/log-history.md` |
| 現在状態と次にやること | `docs/log.md` |
| 使った印象（未選別） | `inbox.md` |

## 書き方

- 1つのやり方・モードにつき1ファイル。名前は `<lesson 名>-record.md`（例: `research-method-record`）。lesson が無いモードは、手順書の名前を使う（例: `init-update-record`）。名前は repo 内で一意にする（`exmem/lessons/` と重ならない）。
- 新しい記録を**先頭に**足す（新しい順）。古い記録は消さない。
- 1回の記録は、次の見出しで書く。該当しない項目は省く。

```
## YYYY-MM-DD 品質チェック | 振り返り（<コミットの範囲>）

- 対象: やり方・モード、版（コミット）
- 方法: 基準、実行者（新しい会話・人）、入力（インタビューの答え）、回数
- 結果: 観点 × 回の表（○ 基準相当 / △ 部分的 / × 欠ける）
- 直し: 回ごとの手順書の変更（コミット）
- 残るブレ・未検証: 効果が分けられないもの、実行が1回のもの
- 成果物の置き場: 基準と各回の成果物の場所（大きいときは repo に入れない）
```

- 観点は、実行の前に基準から決める（後から足さない）。
- 成果物（実行結果）は大きい。repo に入れるかは、記録ごとに決める。入れないときは、場所を「成果物の置き場」に書く。
- 機密、勤務先固有の情報を書かない（公開リポジトリ）。
