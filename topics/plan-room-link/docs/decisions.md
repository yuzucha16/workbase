### 【汎用】【仮 5回まで】トピックで相談するときの型を、3段にする（2026-10-21）
- 決めたこと（ユーザー）: ① 現状の事実を調べて論点を一覧化する。② これを叩き台として潰していく。③ 確認したい事実や前提があれば聞く。これまではやり方がその都度ばらばらだったので、仮決めとして、トピックで相談するときの型にして試す。うまくいけば、トピックを出て、Project 型の相談の型に格上げする。
- 根拠: ユーザーの発言（2026-10-21）「この進め方いいですね。これまでランダムにやり方が出てましたが、今後は仮決めとしてトピックで相談するときの型にして試してみたい。うまくいけばトピックを出て projects 型の相談の型に格上げしていきたい」。最初の実例は `topics/plan-room-link/`（[[plan-room-link-issues]] が①の出力）。
- 見直しの条件: 数回使った後、型として残す・格上げする・やめるを決める。期限は5回使うまで（ユーザー、2026-10-21。5回目で型として残す・格上げする・やめるを決める。使った回は `topics/plan-room-link/docs/log.md` に数える）。格上げする場合は、`methods.md` の新しいやり方として `review 消化` の3段に乗せる（仕組みの決定のため）。
- 未了: `topics/AGENTS.md` や手順書には、まだ書いていない（試して形が見えてから）。

### 【この件】トピックを Project 型で作る（2026-10-21）
- 決めたこと（AI の既定。ユーザーが違えば直す）: 完了条件を1文で書けるので Project 型にした（`topics/AGENTS.md`、`open-hook.md` の判断基準）。名前は `plan-room-link`。
- 根拠: ユーザーの依頼（2026-10-21）「room init, open と start 計画を紐付けたい。areas と projects の readme などに 6R などがリンク・転記どちらでも良いけど関連させたい。紐づくタイミングは init, open より後でも良い。これを新しいトピックとして topics 配下で議論させて欲しい」。
