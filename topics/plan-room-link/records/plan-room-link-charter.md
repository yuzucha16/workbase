# plan-room-link の憲章

6R（[[plan-room-link-6r]]）から作った。実行中に更新する前提。

| 欄 | 内容 |
|---|---|
| 名前 | plan-room-link（計画と部屋の README の紐付け） |
| 更新日 | 2026-10-21 |
| 使命（What） | Project の README から、承認版の計画の場所が分かるようにし、部屋の AI も同じ場所を読む決まりにする（案 D: 固定の1行） |
| ビジネスの目的（Why） | 計画が作られたまま読まれない状態と、承認のたびに README を手で直す漏れを避ける。写さないのでずれない |
| 完了時期 | 2026-10-28（バッファを含まない。平日 6 日以内で収める。土日のバッファは使わない〔推測〕。実機確認が次の `open` 次第で外れうるときは、実機確認だけ期日の外に出す） |
| 予算 | 1 週間（既定）。ユーザーの判断が要る回数 4 回（5 回目の判断を含めても 5 回以内）、AI のセッション 3 回以内〔推測〕 |
| 品質 | 単体テストがパスする。`close` の雛形チェックが新しい行で止まらない。`start-plan.md` が README の決まりと食い違わない |
| 指標 | 次に `open` した Project の README の「計画:」の行が、実機で入っている（1 つ） |
| マイルストーン | [[plan-room-link-milestones]]（3 つ） |

メンバー・リーダー・オーナー（ユーザー、AI の作業）は、全員がユーザーの 1 人の題材として省いた。対象外・前提・リスク・未決は 6R に残す。
