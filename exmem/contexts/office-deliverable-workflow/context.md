# Office成果物を繰り返し作る手順の構想 Project Context

## Current State

- 2026-10-07 に、Vault の外（Claude のプロジェクトのスレッド）で、xlsx / pptx など繰り返し作る成果物を AI で作る手順の構想を、ユーザーとの壁打ちで固めた。kit にはまだ反映していない（構想の段階）。
- 既存の決定（[[office-ai-workspace]]）は、一方向フロー（骨子・データを Markdown / CSV → テンプレ → エージェントでファイル化 → 最後の微調整は人か Office 内 AI）と案件フォルダ案まで。本件は、その中の「骨子 → ファイル化」の間（誰が、どの段階で、何を決めるか）を詰めた。
- ユーザーが合意したこと（2026-10-07）:
  - ラリーが重いのは、正の版が中間物と最終成果物の2つあり、決める場所が最終成果物の上にしか無いため。手順の最適化で減らす。直す場所を、変換前の文章（Markdown）の段階に前倒しする。
  - 直しは、中身 → 仕様、見た目 → テンプレ、その回だけ → 最終成果物だけ（AI に戻さない）、の3種類に分けて戻す先を変える。
  - 層を分ける: 中身、型（必ず入れる要素の一覧）、読み手（構成の順序・具体度・粒度）、文体。型と表現を分ける。
  - 分担: 読み手と目的の設定、中身の確定は ee が決める。構成案と本文は AI が書き、ee が承認する（承認ゲート2つ）。文体の点検、変換、検証は AI。
  - 確認範囲は、繰り返し利用率で切り替える。初期は全体を見る。直しがゼロの回が続いたら、要点と異常値だけにする。この考えは他の作業にも横展開し、メトリクス（[[ai-work-metrics]]）と合わせたい。
- 今日の実践で、ee が最終成果物に入れた直しは、ほぼすべて内容だった（日本語の表現、読み手に合わせた言葉選び、論理展開）。見た目はほぼ無かった。この種の知識は、まだナレッジ化も改善フックもしていない。
- 設計の詳細と根拠は、`exmem/inbox/2026-10-07-office-deliverable-ai-workflow.md` に書いた。統合の前は、プロジェクトの共有フォルダに下書き（`notes/office-deliverable-workflow/2026-10-07-design-draft.md`）がある。

## Next Actions

1. 最初の1回を、今日の読み手1人分の設定と、その成果物の型だけで回す。直しを、仕様・テンプレ・読み手・文体のどれに戻したかを、1行ずつ記録する（2026-10-07 時点）。
2. 実行の記録の書式と置き場所（各作業ディレクトリの `docs/` のどこか）を決める。
3. 再利用率の一般的な定義を、別スレッドのメトリクスの結論と合わせて、[[ai-work-metrics]] に足すか決める。
4. 文体の機械点検の範囲（一文の長さ、読点の数、接続詞の重なりなど）を決める。
5. inbox のメモを、「inboxを整理して」で `knowledge/` へ統合する（新規1ファイル。[[office-ai-workspace]] と相互にリンクする）。

## Open Questions

- 直しを「仕様・テンプレ・読み手・文体」のどれに戻すかの判断を、誰が（AI が提案し ee が承認する、など）どの時点で行うか。
