# AI リテラシー・スキルの指標化 Project Context

## Current State

- 2026-10-07 に、Vault の外（Claude のプロジェクトのスレッド）で、指標化の進捗をリポジトリから調べた。リポジトリに記録があるのは、方針と設計までで、試行の結果は無い。
- 決定済みの方針は [[ai-work-metrics]] と [[para-operations]] の Decisions にある（2026-10-06、ユーザーの承認）。要点: 用途は本人の自己改善だけ。会話履歴から自動で抽出する。指標は5群（規模・分割、自走、品質、リテラシー、無駄の合図）。リテラシー群は、最初の依頼の完備度（0〜4）、批判的レビューの件数、仕組み化の件数。総合スコアと AI の印象評価は使わない。
- 開始の形は `bare`（「作業を始めて」だけ）と `briefed`（最初の依頼に、ゴール・完了条件・制約・やらないことを添える）に分け、`bare` → `briefed` の順に試す（決定済み）。**どちらの試行も、実施した記録がリポジトリに無い**。実データは、PC 側の作業ディレクトリの `docs/metrics/events.csv` にあるはずだが、ここからは見えない（未確認）。
- 2026-10-06 に、AI がリポジトリを読んで 10 指標を 0〜5 で採点した暫定評価（64/100、幅 60〜68）がある。ファイルは Claude プロジェクトの共有フォルダ（`notes/ai-literacy-assessment/`）にあり、リポジトリには無い。この採点を、今後の定点観測の型にするかは未決。承認の記録も無い。
- 暫定評価の改善点6件は、2026-10-07 時点で、ほぼ未着手。改善案を毎回出させる規定（`knowledge-hook.md`）は残り、kit は約 190 KB に増えた。点検スクリプトの試験ケースはリポジトリに無く、`handson/tasks/` は 1 件のまま。承認の質を見る `fix` と `reversed` の記録は、始めた。
- 2026-10-07 に、`briefed` で始めるときの依頼の雛形を作った（AI の提案。ユーザーは未使用）。下の「briefed の雛形」。

## Next Actions

- 1. `bare` を試す（PC 側で済んでいなければ）: 適当なタスクで、新しい会話に「作業を始めて」だけを言って始める。終了処理で、抽出と1行の記録を回す。
- 2. `briefed` を試す: 別のタスクで、下の雛形の4項目をすべて埋めて始める。記録には、開始の形を `briefed` と書く。
- 3. 2回分を比べる。見るのは、完備度、開始インタビューの質問数と冗長率、修正の件数と起因、ターン長。
- 前提: 2つの試行を同時に走らせない。終了時に、別の会話を選ぶ事故が起きる（[[ai-work-metrics]] の Gotchas）。
- 試行の後に決める: 10 指標の採点を定点観測に使い続けるか、作業指標のリテラシー群に寄せるか。作業指標を終了処理（`closing-hook.md`）へ昇格する条件。
- 2026-10-07 のクラウドのセッションの終了処理で、ユーザーが出した指示（原文）: 「改善はなしでお願いします。やった分はそのままで構いません。ブランチの扱いは別途決めます。終了処理して」。改善案は出さない。ブランチ `claude/project-thread-0b5nue` の `main` への取り込みは、ユーザーが別途決める（未決）。

## briefed の雛形

新しい会話の最初に貼る。`<…>` を埋める。4項目はすべて必須（空欄があると、背景の有無の差と区別できない）。

```
作業を始めて。開始の形は briefed（背景あり）です。

- ゴール: <この作業で何ができた状態にしたいか>
- 完了条件: <終わったと判断できる1文。例: ○○が△△で動き、□□に記録されている>
- 制約: <守ること。時間、触ってよい範囲、使う道具、優先順位>
- やらないこと: <今回は対象外にすること>

（任意）対象の Project: <名前またはパス>
（任意）読んでほしい資料: <ファイルやリンク>

上に書いてあることは質問せず、要約して確認だけしてください。足りない前提があれば聞いてください。
```

## Goal

AI の活用スキルとリテラシーを、観測できる行動と件数で測り、自己改善に使える形にする。
