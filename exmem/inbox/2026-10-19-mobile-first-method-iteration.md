# やり方をモバイル・クラウドで反復して絞ってから PC 環境へ移す

## Goal
新しいやり方（手順書）を、モバイル・クラウドの会話で反復して試し、無駄を落としてから PC 環境（kit のあるリポジトリ）へ移す進め方と、その間のノウハウの置き場を整理したかった。
統合先の候補: lessons/method-creation.md（キーワード: 反復, 試行, モバイル, 共有フォルダ, method-creation）

## Principles
- やり方は、モバイル・クラウドで反復して試し、迷いが減ってから PC 環境へ移す。理由: PC 環境は、反映のたびに承認と登録の作業が要り、直しの単価が高い。
- 試行の間の元データ（決定、比較表、迷った点）は、共有フォルダの notes に貯め、PC 環境に入れるのは骨子と決定だけにする。理由: 元データは量が多く、確定するまで揺れる。
- 出力（成果物）と作り方のメモを、別ファイルにする。理由: 本番でも、README や AGENTS に置く作り方と、出力の Markdown は別物で、混ぜると出力の見本を使い回せない。
- 別の会話に「作り方のメモと見本」から複数の題材を作らせ、「迷った点」の重なりを数えて、作り方か既定値に戻す。理由: 同じ迷いが毎回出るのは、作り方の欠けのサインで、題材ごとに聞くと手数が増える。
- 毎回出る迷い（予算、体制、稼働日など）は、既定値にして、題材ごとには聞かない。理由: 聞く数が減り、題材どうしを横に並べて比べやすくなる。
- 数の上限で粒度をそろえるときは、何を数えるかを先に決める。理由: 数え方が曖昧だと、上限を守るために成果物を束ねる歪みが出る。
- ブレが減ったことを、再現性の根拠にしない。題材と期間を変え、見本を見せない回を足して確かめる。理由: 型の効果と、見本への寄せや既定値の効果を分けられない。

## Decisions
- **試行の元ファイルはクラウドの共有フォルダに残し、PC 環境に運ぶ骨子と決定は、リポジトリの `topics/kit-growth/records/` に置く**（2026-10-19）
  - 根拠: 共有フォルダは PC 環境から読めないため、PC 側で使う内容は、リポジトリに無いと届かない。
  - 却下案: 下書きも決定も共有フォルダだけに置く（PC 環境から見えず、移行の入力にならない）。
- **憲章・WBS・マイルストーンの出力と、作り方のメモを、別ファイルにする**（2026-10-19）
  - 根拠: ユーザーの指示。本番で README や AGENTS に置く作り方と、出力の Markdown が別になるのと同じ。
  - 却下案: 1枚のファイルに作り方と出力を混ぜる（最初の試行はそうだったが、他の題材に見本として渡しにくい）。

## Facts
- ユーザーは、モバイル・クラウドで反復して絞ってから PC 環境へ移す進め方と、共有フォルダにノウハウを貯める進め方を「非常に良かった」と評価した（確認: 2026-10-19、根拠: ユーザーの発言）。
- 4題材の出力と作り方のメモで、迷った点が重なった: 測り方の指標が元の要求に無い（3/3）、戦略にあたる上位が未確認（4/4）、リーダー兼任が仮（4/4）、課題ログの置き先が揺れた（4/4）、日付が推測（4/4）（確認: 2026-10-19、根拠: 共有フォルダの `notes/planning-method/` にある論点の記録）。
- 出力に載せる項目（対象外・前提・リスク・未決）が、1題材だけ他の3つと違った（確認: 2026-10-19、根拠: 4題材の作り方のメモ）。
- 節目の数に上限3つを置いたところ、早く終わる直しを遅い節目に束ねた題材があった（確認: 2026-10-19、根拠: その題材の作り方のメモ）。
- 4題材とも1週間で、すべてリポジトリ自身の改善の題材だった。2週・4週の上限は、まだ使っていない（確認: 2026-10-19、根拠: 4題材の出力）。
- 共有フォルダ（モバイル・クラウド）の notes は、PC 環境から見えない（確認: 2026-10-19、根拠: ユーザーの発言）。

## Gotchas
- 状況: 最初の試行で、位置付け・作り方・出力を1枚のファイルに書いた
  - 原因: 型が固まる前で、見本と作り方の境目が決まっていなかった
  - 解決: 出力と作り方のメモに分け、元のファイルは両方を指す入り口だけにした
- 状況: 試行の下書きを共有フォルダにだけ置いたまま、PC 環境への取り込みの話を進めようとした
  - 原因: 共有フォルダは PC 環境から読めない
  - 解決: 骨子と決定をリポジトリに書いて push した
