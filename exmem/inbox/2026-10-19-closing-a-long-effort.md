# 長い取り組みを閉じるときの移管と二重管理の解消

## Goal
複数日にわたる取り組みのノートを、閉じるときに、どこへ何を移し、何を消すかの型を残したかった。取り組みの置き場を消す前に、知識が失われず、二重管理が残らないようにする。
統合先の候補: lessons/workflow-kit.md（キーワード: トピック, 終了, 移管, 二重管理）

## Principles
- 閉じるときは、内容の種類ごとに行き先を決める。設計と理由は理解ガイド、決定は決定の記録、仕様は実装の隣、原則は lessons、経緯は git に任せる。理由: 種類で行き先が決まれば、移し忘れと二重管理を避けられる。
- 移し終えたノートは、元を削除する。理由: 正本が 2 か所にあると、片方が古くなり、読む人が誤る。
- 移す前に、消えるファイルを指す参照を grep で洗い、先に直す。理由: ノートの名前で参照するコードや文書が、削除でリンク切れになる。
- 閉じてよいかの確認は、取り組みの状態表だけを根拠にしない。上位の経緯の最新の記録とも突き合わせる。理由: 状態表の更新が漏れていることがあり、未達と誤判断する。
- 閉じる前に、残件を上位の Next Actions に移し、確認項目の漏れを各引き継ぎから拾う。理由: 削除すると、PC で確認するはずの項目が失われる。
- 実装前の設計を移すときは、実装されていない部分に「未実装」と注記する。理由: 設計として書いた内容が、実装済みと読まれないようにする。

## Decisions
- **マスク仕様を、実装の隣（`workflow-kit/room/mask-spec.md`）に置く**（2026-10-18）
  - 根拠: ユーザーが、README の隣に置く案を選んだ。仕様は詳細で長く、README は概要と使い方にとどめられる。
  - 却下案: README に統合する（README が 11KB から 17KB ほどになる）。
- **移管が済んだ分は元を削除し、二重管理を減らす**（2026-10-18）
  - 根拠: ユーザーが「不要になったらこちらの分は削除でよい。二重管理を減らす」と述べた。
  - 却下案: 経緯のログ全体を root に統合する（39KB あり、経緯は git の履歴で足りる）。

## Facts
- 24 ファイルの削除と移管（設計ノート、引き継ぎ 6 本、窓口、経緯）の前に、トピックのノートを指す参照を洗うと、`room/README.md` 1 か所、`maskkit.py` 1 か所、`room.py` のコメント 2 か所、トピック索引の 1 行だった。履歴の記述にも名前が残った（確認: 2026-10-18、根拠: grep でノート名とトピック名を検索）。
- 設計の要点を理解ガイドに移すと、23KB が 35KB になった（確認: 2026-10-18、根拠: ファイルサイズを測った）。
- 既存の `topics/AGENTS.md` の「トピックを終わらせるとき」は、4 手順（汎用の決定の反映確認、削除、grep、wrap）で、内容の種類ごとの行き先は書かれていない（確認: 2026-10-19、根拠: ファイルを読んだ）。

## Gotchas
- 状況: 設計文書の「reap が会話履歴を記録に写す」を移したが、実装は未対応だった
  - 原因: 設計ノートが、実装前の叩き台の記述だった
  - 解決: 移した文書に「未実装」と注記し、実装の README と食い違わないようにした
