# 組込み C の制約を機械で検査する

## Purpose

組込み向けの C の実装（固定長のメモリプール）で、制約（動的確保なし、グローバル変数なし、初期値つき `.data` を減らす、libc 非依存、再帰なし）を、`nm` と呼び出しグラフで機械検査する方法と、検査そのものを検証する方法、ターゲット（Cortex-M）で初めて出る問題をまとめる。実装は、Makefile と検査スクリプト（`check-rules.sh`）で回した。

## Principles

- 安全性と起動速度を比べるなら、安全性を取る。起動速度に効く設計要素は、チューニング要素として扱い、最初の設計の根拠にしない。速度の最適化は、測ってから後で足せるが、安全性の不足は設計に埋まる。
- 実行時の不正の検出（二重解放など）より、不正を起こさないことを、テストで確かめる。呼び出し側の責務は、呼び出し側が果たす。実行時に検知しても、組込みでは復帰の処理が難しい。
- 検査は、意図した違反が検出されること（と、許可される例が通ること）を確かめて、初めて信頼する。違反例のプログラムは、終了コードが検出の有無だけで決まる形にする。違反の有無と無関係に非ゼロで終わる試験は、検出できていなくても成功に見える。
- 組込みの制約は、製品の実装コードにだけ適用し、テストコードは、実現のしやすさを優先する。テストはホストで動き、`malloc` やグローバル変数を使えた方が書きやすい。
- libc 非依存の検査は、ホストのコンパイルだけで済ませず、ターゲット（ARM など）向けにもコンパイルして、未定義シンボルを見る。ホストには出ない依存（除算の補助関数など）が、ターゲットでは出る。
- 失敗を検出する検査のループは、最初の失敗で止めず、全体を回して集計し、最後に終了コードで返す（下の Gotchas）。

## Decisions

すべて 2026-10-06。

- **制約の適用範囲は、製品の実装（`src/`）だけにする**。根拠: 制約は組込み用途のためで、テストコードは実現のしやすさを優先する、というユーザーの指示。却下案: テストコードも対象にする（AI の当初の解釈。ASan の試験が `malloc` を使うなど、テストの書きやすさを損なう）。
- **初期値つきの `.data` を禁止し、グローバルでないゼロ初期化の `.bss` は許可する**。根拠: 目的は、初期値つき `.data` を減らしてフットプリントを削減すること。「グローバルでなければ、`.bss` はとりあえず許可」というユーザーの回答。却下案: `.data` と `.bss` の変数をすべて禁止する（AI の当初の読みで、強すぎた）。
- **`src/` は libc に依存しない。検査は、`-ffreestanding` でコンパイルし、未定義シンボルが無いこと（`-O0` と `-Os` の両方）とする**。根拠: 組込みでは、libc がリンクされない・使えない構成がある。却下案: libc を許可する（ターゲットによって使えない）。
- **侵入型リストのため、`src/` のビルドに `-fno-strict-aliasing` を付ける**。根拠: 空きブロックの先頭に `void *` を書く実装は、呼び出し側の `unsigned char` 配列に対して、規格上の有効型の問題がある。実装が素直で、Linux カーネルなども採用している。却下案: `memcpy` で書く（libc 非依存の検査と衝突しうる）、`__attribute__((may_alias))`（可搬性が低い）、何もしない（`-O2` 以降で意図しない動作になる可能性）。

## Facts

- `nm --defined-only` の型で、変数を分類できる。`D` と `d` は初期値つきの `.data`、`B` と `b` は `.bss`、大文字は外部リンケージ（グローバル）、小文字はファイル内。関数内の `static` 変数は、`n.0` のような名前の小文字で出る。`static const` は `.rodata` なので、変数として出ない（確認: 2026-10-06、根拠: gcc 13.3 でコンパイルした違反例の `nm` の出力）。
- ホストの gcc の既定（PIE の GOT、スタック保護）は、`nm -u` の結果に `_GLOBAL_OFFSET_TABLE_` や `__stack_chk_fail` を出す。ターゲットの依存ではないので、検査のコンパイルでは `-ffreestanding -fno-pic -fno-stack-protector` を付ける（確認: 2026-10-06、根拠: `__stack_chk_fail` が呼び出しグラフに出た）。
- `-Os` では、`memset` の呼び出しが展開されて未定義シンボルに出ないが、`strlen` は残る。`-O0` では両方出る。libc 非依存の検査は、2つの最適化レベルで見る（確認: 2026-10-06、根拠: 違反例の `nm -u` の出力）。
- Cortex-M0 / M0+（ARMv6-M）には除算命令が無く、`/` と `%` が、libgcc の補助関数 `__aeabi_uidiv` `__aeabi_uidivmod` を呼ぶ。Cortex-M3 / M4 は出ない。ホストの検査には出ず、ARM 向けにコンパイルして初めて出る（確認: 2026-10-06、根拠: `arm-none-eabi-gcc` 13.2.1 で、同じソースを `-mcpu=cortex-m0` と `cortex-m3` でコンパイルして `nm -u`）。
- 同じコードの `.text`（`-Os`、バイト）: Cortex-M3 / M4 は 288、Cortex-M0 は自分のコードだけで 332、libgcc をリンクすると 612（`__udivsi3` が 266 バイト）。2進の筆算に置き換えた試作は、M0 で 378、M3 で 358、未定義シンボルなし（確認: 2026-10-06、根拠: `arm-none-eabi-size`、`-nostdlib -lgcc` でのリンク）。
- 再帰は、`gcc -fcallgraph-info`（gcc 10 以降）が出す呼び出しグラフ（`.ci`、VCG 形式）から、閉路を探して機械検査できる。直接の再帰、相互再帰、ファイルをまたぐ再帰を検出した。関数ポインタなどの間接呼び出しは、呼び出し先が分からないので検査できない（`.ci` に `indirect` を含むノードが出るので、警告にできる）（確認: 2026-10-06、根拠: gcc 13.3、違反例 3 種と間接呼び出しの例）。
- `-fno-sanitize-recover=undefined` を付けないと、UBSan は警告を出して終了コード 0 で続行する。サニタイザなしも 0（確認: 2026-10-06、根拠: 3つの設定で同じ違反例を実行）。
- `-fno-strict-aliasing` の有無、`-O1` `-O2` `-O3` のどれでも、侵入型リストのテストは通った。strict aliasing の問題は再現していない。フラグは予防の位置づけ（確認: 2026-10-06、根拠: gcc 13.3、同じテストを 6 通りでビルドして実行）。
- `nm -u` でファイルごとに未定義シンボルを検査すると、ファイル間の参照（`a.c` から `b.c` の関数）を、外部シンボルへの依存として誤検出する（確認: 2026-10-06、根拠: 2ファイルが相互に呼ぶ例で、`a` と `b` が未定義シンボルとして出た）。
- 複数ファイルの `src/` は、`ld -r` で結合したオブジェクトを `nm -u` で検査すれば、ファイル間の参照が解決される（仮説）。結合した検査は未実施。

## Gotchas

- **UBSan の検出を確認するプローブが、検出されなくても「検出した」と判定された**: プローブの `main` が、オーバーフローした値で終了コードを決めていて、検出の有無と無関係に非ゼロで終わった。通常は終了コード 0 で終わる形にし、サニタイザなしと `recover` 許可（どちらも 0）、`-fno-sanitize-recover=undefined`（非ゼロ）を対照して確認した。
- **ARM 向けの検査のスクリプトが、Cortex-M0 の失敗で止まり、M3 / M4 の結果が見えなかった**: シェルの `set -e` で、CPU のループの途中で終了した。全 CPU を回して失敗を集計し、最後に終了コードを返す形に直した。CPU ごとに `OK` / `FAIL` を出す。
- Make のレシピ内のシェル変数（`$$cpu_` が空になる）は [[windows-cli-pitfalls]] の Make の節。

## Open Questions

- Cortex-M0 に対応する場合、2進の筆算（`size_t` のビット数で打ち切る）で、除算の補助関数への依存をなくせる。速度（ハードウェア除算より遅い）の影響は未測定。
- 複数ファイルの `src/` で、未定義シンボルの検査を、結合したオブジェクトに対して行う形にする方法。
- ファイルスコープの `static` 変数（ゼロ初期化）は、`nm` で関数内の `static` と区別できず、許可になる。検査できる方法があるか。
