# 人間とAIの意思決定ループ（Decision Loop）

## Purpose

キーボード購入を題材に、人間とAIの工程界面・インターフェースを可視化する。単発の質問と回答ではなく、意思決定の状態が反復的に変わる汎用モデル「Decision Loop（仮称）」を小さく設計する。目的は製品選定そのものより、AI活用の工程設計を学ぶこと（題材は [[keyboard-switches]]）。

## Principles

- 直線的な「目的 → 調査 → 比較 → 購入」ではなく、目的・評価関数・候補・情報・評価を反復するループとして扱う。
- 評価関数や制約は最初から完成させない。暫定版で始め、調査・評価で得た論点に応じて更新する。
- AIは探索、情報収集、整理、比較、反証、不明点・矛盾の抽出、制約候補の提示を担う。
- 人間は目的・価値判断、制約の採用/却下、探索範囲、収束・継続、最終判断を担う。AIは制約を提案できるが、採用は人間が行う。
- 探索と収束を区別する。区別しないと、AIが早期に総合順位や購入結論を出してしまう。
- 情報整理・分析と、価値判断・制約採用を混同しない。AIの提案を自動的に採用しない。

## Decisions

### 最初の実験ケースはキーボード購入（2026-10-02）

- 根拠: 通常業務でも、少ない制約から始めて選択肢の排除や実行可能な部分から制約を足す傾向がある。この傾向をなくすより、探索モードから収束モードへ切り替える能力を訓練対象にする。
- 想定: 候補一覧を作る前に評価関数を仮置きし、①目的・要件と⑤信頼性評価を含む工程を複数回回して購入品を決める。

### 初期モデルは小さく作る

- 「人間が意思決定状態を提示 → AIが分析 → 人間が状態を更新 → 次のループ」の構造。最初から厳密な完成設計を目指さない。

## Facts（仮説を含む）

- AIは対話を「答えを求められている」と解釈しやすい。探索中・未決定・結論不要など、現在のモードと依頼する処理を明示するインターフェースが有用、という仮説。

## Gotchas

- 直線工程として設計すると、評価関数や制約を最初から確定させようとして過剰設計になる。

## Open Questions

- 最小の入力・出力インターフェースをどこまで簡略化できるか。
- 探索継続と収束への切替条件をどう定義するか。
- 評価関数の更新履歴や判断状態を、対話の中でどう保持・可視化するか。
- AIに任せる処理と人間が承認する処理の境界を、どの粒度で定義するか。

## Next Actions

- キーボード購入を題材に、最小のDecision Loopを試作する。
  - 入力: 目的 / 現在の制約 / 候補 / 既知情報 / 不明点
  - AI出力: 情報整理 / 不明点 / 矛盾 / 制約候補 / 次に調べる価値が高い事項 / 収束可能性
  - 人間の操作（記録対象）: 制約候補の採用・却下 / 評価軸変更 / 探索範囲決定 / 継続・収束判断
- 各イテレーションで、意思決定状態がどう変化したかを観測する。
