# 調査の出力の型2（手順書）: 実行できる手順書の章立てと作り方の Must

[[research-method-2]]（調査2）の、応答の形だけを切り出したノート。技術的なインストール・導入や、ルール・仕組みに沿ってやることを、そのまま実行できる手順書にまとめるときに読む。やり方の全体は元のノートにあり、必要なときだけ読む(2026-10-28 に切り出した。`topics/token-cap/records/2026-10-28-brief-mode-load.md`)。主題の説明は [[research-explain-output]]。

## 作り方の Must（4つ）

1. 最初に宣言する: ゴール(完了の状態を3つ以内)、環境の前提、使う道具と使わない道具(使わない道具は本編に出さない)、コマンドを打つ場所(1か所で完結できるなら本編にする)、読者と分量。答えが依頼にあるものは聞かず、既定を置いて宣言する。
2. 関連する既存の決定を確認する。手順は一次情報で確認する(コマンド、オプション、前提、版)。出典と未確認を書く。
3. 秘密情報はプレースホルダにする。
4. 章は下の固定にし、各手順は 目的 → コマンド → 確認 の型にする。

あれば良い(Want): 試せる環境での実行、参考ページの候補、出力先、文字数の確認、付録、順序の理由。置いたあと記録する(配置と記録)。

## 章立て（章は固定。各手順は同じ型）

| 章 | 内容 |
|---|---|
| 冒頭 | 版の行(改訂日、読む時間、対象)、プレースホルダの断り、コマンドの打ち場所の断り |
| 0 クイックスタート | 最短の手順を表に(#、やること、コマンド) |
| 1 ゴールと全体像 | 完了の状態を3つ以内。構成図(mermaid。図は全部で4つまで) |
| 2 前提 | 必要な環境・権限・事前準備。既定として置いたものは章 8 に |
| 3 手順 | `3.1`〜。目的 → コマンド → 確認。順序は 作る・使う → 日常の使い方 → 移行元を外す |
| 4 管理 | バックアップ、失効、紛失、棚卸し |
| 5 関連する既存の決定 | 方針・境界が手順のどこに効くか(参照つき)。無ければ省く |
| 6 トラブル対応 | 症状と見るところ(4〜6件) |
| 7 チェックリスト | 3グループ程度の `- [ ]` |
| 8 確認できていない点・環境差 | 未確認、既定として置いたもの、参考ページの選定、読み解き |
| 9 参考ページ | 一次と二次を分けた表(3〜6件。開いたものだけを確認済みとして載せる) |
| 付録 | 別の場所で打つ手順があるときだけ |
