# 調査の出力の型1（説明）: 主題を調べてまとめるときの章立てと作り方の Must

[[research-method]]（調査1）の、応答の形だけを切り出したノート。依頼の言葉（「調べて」「調査」など）で、このノートだけを読み、この形で返す。やり方の全体（背景、事例、落とし穴）は元のノートにあり、必要なときだけ読む（2026-10-28 に切り出した。`brief` の引数をやめる試験。`topics/token-cap/records/2026-10-28-brief-mode-load.md`）。

実行できる手順書にまとめるとき（インストール、導入、設定）は、[[research-procedure-output]] の形にする。

## 作り方の Must（3つ）

1. 想定読者を決める（既定は依頼した本人。他の人・組織に渡すなら、読者と範囲を先に聞く）。品質条件を宣言する: 一次情報を優先、出典に日付と URL（日付が無い資料は取得日）、推測と未確認を明記。
2. 調べる前に、題材に一次情報があるか確認する(無ければ二次中心と明記)。問いごとに調べ、事実を述べる各問いに一次の出典を1件以上付ける（無ければ「一次情報なし」と書く）。事実・推測（筆者の見立て）・第三者の意見、一次と二次を分ける。
3. 確認できなかった点を、末尾に書く。成果物は Markdown のファイル1つにする（置き場の候補を、下書きは `notes/`、確定は `guides/explain/<主題>.md`〔`checked` つき〕、業務・機密は部屋の `ai/out/` とし、聞けないときは会話の中に出す）。

あれば良い(Want): 具体例の要否と条件(指標・対象の種類・件数)を最初に決める、類似ワードの候補(依頼者が挙げるもの)、結論の用途、出力先と形式、変わる値の取得日と手段、範囲を絞った基準の明記、章を足すときの番号と参照の点検。

## 章立て

### 依頼が単一の問いのとき

問いを冒頭に1行置き、章は **結論 / 確認できなかった点 / 出典** にする。

### 主題を説明するとき（章は問いに1対1。全部採用が既定。省く・足すのは最初に宣言する）

0. 3行で表すと: 何であるか、どう動くか、使う上の注意の3行(冒頭)
1. 生まれた経緯: 日付・出来事・出典の表。第三者の動き(他社の採用、標準化、批判)も入れる(二次は二次と明記)
2. 解決したかった問題: 公式が述べた課題。数値(費用、時間、量)があれば添える
3. 与えた影響: 事実と、第三者の評価(肯定と懸念を各1件以上探す。見つからなければ「見つからなかった」と書く。意見と明記)を分ける
4. 現在の役割: 位置づけと、製品・場面ごとの違い(表)。公式資料どうしの食い違いは、寄せずに書く
5. 具体例: 条件(指標、対象の種類、件数)を最初に宣言し、それに従う。定番・著名なもの、人気の上位5(指標、取得日、取得手段つき)、ジャンル別の代表例。選び方の基準と、除いたものを書く。中身を読んでいないものは、そう書く(取り方の詳細は [[research-method]] の Facts)
6. 今後の展望: 公式が述べたことと、筆者の見立て【推測】(根拠つき)を分ける
7. リスクと懸念点: 安全面・運用面・標準化(普及)面の3観点。公式の警告(一次)と実態の調査(第三者)を分ける
8. 使い方(題材が道具・手法のときだけ。短く): 作り方、置き場、呼ばれ方
9. 類似ワードと関連ワード: 「同じものの別名」と「似て非なるもの」の2表。各行に、何か・いつ働くか・主題との違い
- 末尾: 確認できなかった点・注意、出典。出典は一次と二次の2つの見出しに分け、本文は番号で参照する(一次・二次を通した連番、欠番なし)
