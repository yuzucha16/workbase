# Quarto/revealjs スライドの出力の型（図解レイアウト）

状態: 土台（確定ではない。拡張していく。2026-11-06 ユーザーの決定）。社内の勉強会・LT 向けの簡易スライド用。正式な pptx は別（`topics/office-output-types`）。部品は、トピックの `records/`（`topics/revealjs-slides/records/`）に置く: `gen_layouts.py`（生成スクリプト。型と文言から qmd を出す。`python -I gen_layouts.py -o out.qmd`）、`revealjs-diagram-layouts.qmd`（10 型の見本。スクリプトの出力で、手で直さず作り直す）、`revealjs-diagram-theme.scss`（CSS）、`revealjs-diagram-icons.html`（アイコン定義）。作業の状態は [[revealjs-slides-start-here]]。

## Goal

Markdown（Quarto）から revealjs のスライドを作るとき、図解を入れた資料を同じ型で返せるようにする。章立ては変えず、各章に図を足す作業の型（レイアウトの種類、箱の中の配置、配色、記号）を決めた。

## Principles

- 1 つの箱の中は、左に図、右に文字を置く。理由: 目が左から右へ動くので、図で見せてから短い文字で言い切る順になる。
- 比較は横に並べる（左右）。理由: 人の目は Z の形に動くので、横の対比が最も読み取りやすい。上下は「比較の下に共通・結論」「全体の下に内訳」を置くときに使う。
- 図は 3 ブロック程度にし、関係はブロックの位置と矢印だけで表す。理由: 凡例や説明文が要らなくなる。
- 強調色は 1 色（青）にし、ほかはグレーと黒にする。理由: 色の数が増えると意味の対応を覚える負担が出る。禁止と許可のような対立も、色相でなくアイコンと濃淡で示す。
- 箱が何のカテゴリかは、箱の上辺に貼る「札」（アイコン + 短い名前）で示す。文章中の見出しを札へ移すので、文字は増えない。色だけに頼らないので、投影で色が飛んでも読める。
- アイコンの意味は資料全体で固定する。フォルダ=ディレクトリ、人型=アクセスする側（AI を含む）、ロック=保護された領域、目に斜線=見えない、PC=普段の環境、家=隔離した環境、盾=境界。理由: 同じ形が違う意味になると、図を読み直すことになる。

状態の記号: 〇=反映済み、△=一部、×=未反映、─=不採用（理由を書く）。値の正は `revealjs-diagram-theme.scss`。

### 基本デザイン（DADS: /dads/foundations/）

#### カラー（/foundations/color/）

- DADS: 文字のコントラスト比 4.5:1 以上、非文字（枠線・アイコン）3:1 以上。Blue と solid-gray の階調。意味色（緑・赤・黄）は成功・エラー・警告用。
- 現行: モノトーン + 強調 1 色。強調 `#0017c1`（Blue-900）、強調の濃い側 `#00118f`（Blue-1000）、強調の薄い地 `#e8f1fe`（Blue-50）、文字 `#1a1a1a`（Gray-900）、補助文字 `#4d4d4d`（Gray-700）、灰の枠 `#767676`（Gray-536）、罫線 `#949494`（白に約 3:1。11-06 に `#b3b3b3` から変更）、濃灰の枠 `#333`（Gray-800）。意味色は使わず、札のアイコンと文字で伝える。
- 状態: 〇 値。─ 意味色（モノトーン方針、2026-11-06 ユーザー）。〇 罫線は `#949494`（約 3:1。11-06 ユーザーが 3 色の見本から選んだ。旧 `#b3b3b3` は 2.1:1）。強調に使う線は `#767676` 以上。コードブロックの地 `#f5f5f5` は Gray-50 `#f2f2f2` と不一致（未修正）。

#### タイポグラフィ（/foundations/typography/）

- DADS: Noto Sans JP、太さは 400 と 700、14px 未満は原則不可、本文の行高 150% 以上、見出し 140%。
- 現行: Noto Sans JP、400 と 700。基準 28px（`$presentation-font-size-root`）。本文 0.9em、h3 1.1em、h2 1.5em、総評 0.8em、表・格子 0.72em、箱の文字 0.66em。行高は見出し 1.4、本文 1.5、表 1.5、箱 1.5（11-06 に 1.4 から）。字間は本文・表・箱 2%、h2・h3 1%、コードと番号札 0（11-06）。
- 状態: 〇 フォント・太さ・下限（最小は箱の文字約 18.5px、札 約 17px、レイアウト番号 14px）。〇 行高（箱も 1.5 に。11-06）。〇 字間（DADS は 16〜26px で 2%、28px 以上で 1%。見本を目視してユーザーが採用、「広げた方が見やすい」。11-06）。

#### 余白（/foundations/spacing/）

- DADS: 基準 8px、3〜5 段階（例 8・24・64）。一貫性、階層（下がるほど小さく）、関連性（関連が強いほど近く）。
- 現行: px の部分は 8 の倍数。セル間 `--gap: 8px`、セルの内側 `--pad: 16px 24px`、インデント `--ind: 40px`、格子の高さ `--h: 560px`。図表の高さは内容なりを既定にし、下は lead・notes の場所にする。
- 状態: 〇 箱（`.cell`）の余白は px（`gap: 8px`、`padding: 12px 16px`。縦の 12px は 4 の倍数。11-06）。△ 表題まわりの余白などに em が残る。h2 の縦棒 6px も 8 の倍数でない。

#### レイアウト（/foundations/layout/）

- DADS: 12 カラム、ガターは本文文字サイズの 2 倍、ブレークポイント 768px。2 分割 6+6、3 分割 4+4+4。
- 現行: 1280×720 固定。型ごとの `grid-template-areas`（`gen_layouts.py` の `PRESETS`）。2 分割は 1:1、3 分割は等分。
- 状態: △ 割りの目安（6+6、4+4+4）だけ採用。─ ガター 2 倍（28px で 56px になり、箱が狭くなる）、ブレークポイント（固定サイズ）。

#### アイコン（/foundations/icon/）

- DADS: 配置は 4 種（フロント、リード、テール、エンド）。
- 現行: 自作 SVG 9 種を `revealjs-diagram-icons.html` に定義。札の左に置く（リード相当の 1 種だけ）。意味は資料全体で固定（Principles）。
- 状態: △ 配置は 1 種。─ DADS 素材（Material Symbols など）は、素材規約が未確認のため使わない。

### コンポーネント（DADS: /dads/components/。49 件）

#### 箇条書きリスト（/components/list/）

- DADS: 常に `<ul>`。`<ol>` と CSS カウンタは使わない（番号が内容になる法令・規約などは、番号を本文の文字で書く＝項番タイプ）。行頭記号は 1 段目が黒の塗り丸、入れ子は白抜きの丸。項目に補足・リンク・選択がいるときは「リソースリスト」、名前と値は「説明リスト」。
- 現行: 本文と同じ 1 段（`--ind`）から、記号は本文の左へ 1.1em はみ出す。2 段まで。項目の間隔 0.15em、行高 1.5、本文 0.9em。目次（型 C）の `ol.toc` は記号を消し、番号を `.n` の文字で書いている。
- 状態: 〇 `ul` の使い方、番号を文字で書く目次。〇 行頭の `1.` は生成が止まる（T の `items` と `p`。番号は「1」と文字で書く。11-06）。△ 入れ子の記号は reveal 既定（白抜きの丸）で、見た目を目視で確かめていない。× リソースリスト・説明リスト。

#### 画像（/components/image/）

- DADS: `<img>` に任意でキャプションを付ける。重要な情報を画像だけで伝えない（本文にも書く）。フォント指定のために文字を画像にしない（ロゴなど必須のものを除く）。画像そのものをリンクにしてもよい。サイズ・余白の数値はこのページに無い。
- 現行: 図は自作 SVG（`.fig`）。T の `side` の画像は幅 100%・高さ 480px まで。
- 状態: △ 図の要点は箱の `.txt`・lead・notes に文字で書く（Principles「図で見せてから短い文字で言い切る」と一致）。〇 `side` の画像は `alt` 必須（生成が止まる。11-06）。〇 図の SVG は `role="img"` と `aria-label`（箱の `alt`、無ければ `tab`、どちらも無ければ `aria-hidden`）。〇 `side` の画像は `caption` を渡すと `figure` + `figcaption`（11-06）。

#### 見出し（/components/heading/）

- DADS: 見出しのレベル（h1〜h6）と文字サイズは別に決める。h1 はページの主題、h2 以下は節の主題。飾りは任意で 3 種（リードアイコン、チップ＝青い縦棒、飾り罫）。肩書き・サブタイトルは `hgroup` の `p`（見出しにしない）。見出しと段落で項目を並べず、箇条書きにする。見出しの代わりに入れ子のリストを使わない。数値（サイズ・余白）はこのページに無い。
- 現行: スライドのタイトル=h2（1.5em、太字、行高 1.4、左に 6px の濃青の縦棒＝チップ相当）。小見出し=h3（1.1em、太字、1 段インデント）。装飾はこれだけ。表紙は h1。
- 状態: 〇 チップ（縦棒）、箇条書きで項目を並べる（型 T の `items`）、見出しの階層を飛ばさない。─ リードアイコン・飾り罫（軽さを優先）。× `hgroup` の肩書き。

#### テーブル（/components/table/）— 型 H・J

- DADS: 情報を見せるテーブルと、大量データを操作するデータテーブルの 2 種。比較に使う。名前と値の組は「説明リスト」にする。レイアウト目的で使わない。概要ページに罫線・余白の数値は無い（使い方・アクセシビリティのページ `/components/table/usage/` `/accessibility/` は未取得）。
- 現行: 背景なし・罫線だけ。見出しの下は黒の太線、行の間は灰の細線、強調列は薄青の地と太字（Decisions 2026-11-06、下の Facts）。
- 状態: 〇 比較に使う。△ 罫線・余白の見た目は DADS 流の参考画像に合わせた（ユーザー指示）。型 H は表でなく格子としても使うため、レイアウト目的の禁止とは緊張がある（未決）。× 名前と値の組（説明リスト）の型は無い。

#### ステップナビゲーション（/components/step-navigation/）— 型 I

- DADS: 複数画面にわたる手順の全体と現在位置を見せる。横と縦の 2 配置。状態は完了（灰の丸に✓）・現在（黒の二重丸）・未（白い丸）。一時的な待ち（プログレスインジケーター）や、ページ間の移動（ページナビゲーション）には使わない。
- 現行: 工程の列見出しを右向きの帯（シェブロン）にし、強調列（現在の工程）を濃青の塗りにする。
- 状態: △ 現在位置を濃い色で示す点は一致。完了・未の区別と丸の記号は無い（スライドは全工程を見せる用途のため、必要になるまで足さない）。

#### 目次（/components/toc/）— 型 C

- DADS: 見出しを抜き出した一覧。入れ子のリストで 2 段（1 段目は黒丸、2 段目は白抜きの丸）。ラベルは見出しの文言をそのまま使い、言い換えない。複雑なら見出しのレベルを絞る。見出し「このページの目次」を消さない。現在位置の表示は規定に無い。
- 現行: 罫線だけの番号付き一覧。現在の章だけ薄青の地・太字。小項目は章名の下に 1 段。
- 状態: △ 章名は後続スライドの見出しと同じ文言にする〔ルール案。未強制〕。─ 行頭記号（番号と罫線で代える）と現在位置の強調（スライドの目次は進行の目印として必要）。「このページの目次」の見出しは、スライドでは h2 のタイトル（目次）で代える。

#### カード（/components/card/）— 型 A〜G の箱

- DADS: 1 つの主題の内容をまとめる容器（メディア・テキスト・アクションを罫線で区切る）。灰の外枠、白地。似た項目の一覧・比較に使う。詳細なデータ比較には使わず、表にする。枠の太さ・余白の数値は概要ページに無い（使い方のページは未取得）。
- 現行: 白地・2px の細枠・角丸 8px。上辺の札（アイコン + 短い名前）。青の箱だけ薄青の地。
- 状態: △ 白地・細枠は一致。箱は図 + 文字の容器で、メディア・アクションの区切りは無い。数値比較の箱は表（H・J）にする（Principles の「比較は横に並べる」と整合）。

#### 角の形状・エレベーション（/foundations/corner-shapes/、/foundations/elevation/）— 箱の角と影

- DADS: 角丸は 5 段階（なし 0、スモール 8、ミディアム 正方形 16・長方形 12、ラージ 32・16、フル）。小さい図形ほど同じ半径が強く見えるので、部品の大きさごとに決める。影は Style 1〜8、ほとんどの部品はレベル 0（影なし）。影はコントラストを与えないので、3:1 以上の枠線が要る。
- 現行: 箱は角丸 8px（スモール）、格子・表に角丸は無い（`border-radius` は `.cell` の 8px だけ。11-06 に SCSS で確認。以前の「4px」の記述は誤り）。影なし。枠は 2px。
- 状態: 〇 箱の 8px はスモールと一致、影なし（レベル 0）。〇 格子・表は角丸なし（罫線だけの設計）。〇 箱の枠は 3:1 以上（青・`#333`・`#767676`）。

## Decisions

- **レイアウトは 6 型にする**（のち 9 型に拡張。下の H・I・J）（2026-11-05）
  - 根拠: 比較の基本形と、その変形で、構造の説明がほぼ収まった。型は A=左右二分割、B=上は左右・下は全幅（共通・結論を下に）、D=左は一本・右は上下 2 ブロック（1 つの元から 2 つに分かれる）、E=1 スライド 1 ブロック（図が約 7 割・文字が約 3 割の大きな構造図）、F=2×2（2 軸の比較。Z に読む）、G=上が全幅・下は左右（全体→内訳）。分割なしの章扉・コード・まとめは共通（C）として図解の箱を使わない。
  - 却下案: 型を増やし続ける（選ぶ負担が増え、1 枚ごとに作り方が揺れる）。
- **図は SVG を自作し、箱は CSS の grid で作る**（2026-11-05）
  - 根拠: 日本語フォントが崩れず、色・記号を一括で変えられる。外部のアイコン素材に依存しない。
  - 却下案: pptx で作る（見せるのは revealjs のため）。
- **アイコンは SVG の `symbol` で 1 か所に定義し、`use` で参照する**（2026-11-05）
  - 根拠: 意味の固定と色替えが 1 か所で済む。
  - 却下案: 図ごとにアイコンを埋め込む（色や形を変えるとき、全図を直すことになる）。
- **H・I・J を足し、全体で 9 型にする**（2026-11-06）
  - ユーザーの発言: 「ここでのポイントは表現方法として、行列を増やすとか余白をきれいに使うとかそういう点を抑えてほしいです。」
  - 根拠: pptx のレイアウト例 33 枚（棚卸しは `topics/revealjs-slides/records/2026-11-06-pptx-layout-inventory.md`）の多くが、行ラベルと工程見出しを軸にした格子だった。H=行ラベル × 列、I=工程（シェブロン）× 行、J=表。行・列の数は文言の数で決まり、余白は `--gap` `--pad`、高さは `--h` で統一する。
  - 却下案: 階段・3 要素・ガント・グラフ・関係図は型にしない（H・I で足りるか見る。作図は SVG を .fig に置く）。
- **図解なしの型 T（見出し + 段落 + 箇条書き）を型に含め、全体で 10 型にする**（2026-11-06）
  - ユーザーの発言: 「全部レイアウトはむりがあるので、p13 まとめ のような質素だけど、文字が箇条書きで並ぶものもレイアウトに含めます。」
  - 根拠: 実スライド（room 導入の LT。12 枚）で、まとめ・前置きは図解にしづらく、T で足りた。T は `gen_layouts.py` の `"type": "T"`（`blocks` に `h`・`p`・`items`。入れ子はリストの中のリスト）。
  - 実スライドで A〜G を使うときは、spec の `"height"`（例 `"500px"`）で下の空きを埋める。図が無い箱は文字が 0.9em になる（2026-11-06）。
  - 追記（2026-11-06）: T は `side` で右にコード・画像を置ける。全型（A〜J）が `lead`/`notes` の箇条書きを持てる。仕様の正は `topics/revealjs-slides/records/gen_layouts.py` の docstring。箇条書きは 2 段まで。
  - 追記（2026-11-06）: 型は `split` で 2 つを左右に組み合わせられる。**落とし穴**: 見出し（`###`）で始まる `:::` の div は、Pandoc が `<section>` にし、reveal が縦スライドにして後続のスライドが見えなくなる。見出しで始まる div の先頭に空の印（`gen_layouts.py` の `NOSEC`）を置いて防ぐ。Quarto のコードブロックは、行番号の位置ずれで左が欠けるため、素の `<pre>` にした。
- **文章化全体のルール: フォントは Noto Sans JP、階層ごとにインデントを入れる**（2026-11-06）
  - ユーザーの発言: 「フォントはNoto Sans JPにする。…インデントを追加する。2 shift相当で、スライドタイトルから見出し、箇条書きとインデントを入れて見やすさを追加してください。」「微修正は今後していきます。」

## Gotchas

- 状況: 箱のクラス指定を `{.lay lay-a}` と書いた
  - 原因: 2 つ目の語の `.` が抜け、`lay-a` が属性名として扱われる。Quarto が「:::」の fenced div の警告を大量に出し、レイアウトも崩れる
  - 解決: `{.lay .lay-a}` のように、すべてのクラスに `.` を付ける。クラスが空のときは `{.cell}`（`{.cell .}` は文字としてそのまま出る）
- 状況: SVG の矢じりに `marker` を使い、定義を表紙スライドの非表示 SVG に置いた
  - 原因: スライドによって矢じりが消えた。reveal.js が現在以外のスライドを `display:none` にするため（仮説）
  - 解決: 矢じりは `polygon` で直接描く。`marker` を使うなら、図ごとの SVG の中に定義する。アイコンの `symbol` と `use` は、同じ非表示 SVG に置いてもすべてのスライドで表示できた（確認: 2026-11-05。根拠: 全スライドのスクリーンショット）
- 状況: 先頭の見出しの前に、非表示 SVG の raw HTML ブロックを置いた
  - 原因: 内容が 1 つの空のスライドになり、枚数が 1 枚増えた
  - 解決: 定義のブロックは、最初の見出しのスライドの内側（notes の前）に置く。見本はこの形で 7 枚になる（確認: 2026-11-06）
  - 別案（確認: 2026-11-06。Windows の Quarto 1.11.9）: 定義を HTML ファイルに出し、`format.revealjs.include-before-body` で読む。先頭スライドを消してもアイコンは残り、空スライドも増えない。先頭スライドに依存しないので、スライドの並べ替えに強い。採用済み（2026-11-06）。見本は `records/revealjs-diagram-icons.html` を読み、15 枚（表紙 + 14 型）でも空スライドは出ない（Windows の Quarto 1.11.9。確認: 2026-11-06）
- 状況: SCSS に `$presentation-font-size-main: 32px;` を書いて render したが、文字が小さくならず、5 行の格子が下にはみ出した
  - 原因: 変数名が違った。文字サイズの基準は `$presentation-font-size-root`（既定 40px）。`main` を指定しても 40px のまま描画された
  - 解決: `$presentation-font-size-root: 28px;` に直し、撮影して本文が小さくなったことを確かめた。SCSS が通って render が成功しても値が効いていないことがあるので、文字サイズを変えたら描画を撮って確かめる
- 状況: 格子と表の高さを `--h: 22.5em` などの em で指定して、文字サイズを変えても思った高さにならなかった。インデントも em だと、見出し（大きい文字）の下の箇条書きが見出しより左に出た
  - 原因: em は要素ごとの文字サイズに引きずられる。高さが効かなかった理由は不明（指定の `0.72em` が効いていなかったと見られる。仮説）
  - 解決: インデント（`--ind`）と `--h` を px の固定値にした（`40px`、`560px`）
- 状況: 行の枠（`stroke-width` 3〜4）を、`viewBox` の端いっぱいに描いた
  - 原因: 線の太さの半分が `viewBox` の外に出て、右端の枠が削れて見える
  - 解決: 未対応。`viewBox` を左右に数 px 広げる、または `.fig svg` に `overflow: visible` を付ける案がある（未確認）
