# Quarto/revealjs スライドの出力の型（図解レイアウト）

状態: 土台（確定ではない。拡張していく。2026-11-06 ユーザーの決定）。社内の勉強会・LT 向けの簡易スライド用。正式な pptx は別（`topics/office-output-types`）。部品は、トピックの `records/`（`topics/revealjs-slides/records/`）に置く: `gen_layouts.py`（生成スクリプト。型と文言から qmd を出す。`python -I gen_layouts.py -o out.qmd`）、`revealjs-diagram-layouts.qmd`（9 型の見本。スクリプトの出力で、手で直さず作り直す）、`revealjs-diagram-theme.scss`（CSS）、`revealjs-diagram-icons.html`（アイコン定義）。作業の状態は [[revealjs-slides-start-here]]。

## Goal

Markdown（Quarto）から revealjs のスライドを作るとき、図解を入れた資料を同じ型で返せるようにする。章立ては変えず、各章に図を足す作業の型（レイアウトの種類、箱の中の配置、配色、記号）を決めた。

## Principles

- 1 つの箱の中は、左に図、右に文字を置く。理由: 目が左から右へ動くので、図で見せてから短い文字で言い切る順になる。
- 比較は横に並べる（左右）。理由: 人の目は Z の形に動くので、横の対比が最も読み取りやすい。上下は「比較の下に共通・結論」「全体の下に内訳」を置くときに使う。
- 図は 3 ブロック程度にし、関係はブロックの位置と矢印だけで表す。理由: 凡例や説明文が要らなくなる。
- 強調色は 1 色（青）にし、ほかはグレーと黒にする。理由: 色の数が増えると意味の対応を覚える負担が出る。禁止と許可のような対立も、色相でなくアイコンと濃淡で示す。
- 箱が何のカテゴリかは、箱の上辺に貼る「札」（アイコン + 短い名前）で示す。文章中の見出しを札へ移すので、文字は増えない。色だけに頼らないので、投影で色が飛んでも読める。
- アイコンの意味は資料全体で固定する。フォルダ=ディレクトリ、人型=アクセスする側（AI を含む）、ロック=保護された領域、目に斜線=見えない、PC=普段の環境、家=隔離した環境、盾=境界。理由: 同じ形が違う意味になると、図を読み直すことになる。

## Decisions

- **レイアウトは 6 型にする**（のち 9 型に拡張。下の H・I・J）（2026-11-05）
  - 根拠: 比較の基本形と、その変形で、構造の説明がほぼ収まった。型は A=左右二分割、B=上は左右・下は全幅（共通・結論を下に）、D=左は一本・右は上下 2 ブロック（1 つの元から 2 つに分かれる）、E=1 スライド 1 ブロック（図が約 7 割・文字が約 3 割の大きな構造図）、F=2×2（2 軸の比較。Z に読む）、G=上が全幅・下は左右（全体→内訳）。分割なしの章扉・コード・まとめは共通（C）として図解の箱を使わない。
  - 却下案: 型を増やし続ける（選ぶ負担が増え、1 枚ごとに作り方が揺れる）。
- **図は SVG を自作し、箱は CSS の grid で作る**（2026-11-05）
  - 根拠: 日本語フォントが崩れず、色・記号を一括で変えられる。外部のアイコン素材に依存しない。
  - 却下案: pptx で作る（見せるのは revealjs のため）。
- **アイコンは SVG の `symbol` で 1 か所に定義し、`use` で参照する**（2026-11-05）
  - 根拠: 意味の固定と色替えが 1 か所で済む。
  - 却下案: 図ごとにアイコンを埋め込む（色や形を変えるとき、全図を直すことになる）。
- **H・I・J を足し、全体で 9 型にする**（2026-11-06）
  - ユーザーの発言: 「ここでのポイントは表現方法として、行列を増やすとか余白をきれいに使うとかそういう点を抑えてほしいです。」
  - 根拠: pptx のレイアウト例 33 枚（棚卸しは `topics/revealjs-slides/records/2026-11-06-pptx-layout-inventory.md`）の多くが、行ラベルと工程見出しを軸にした格子だった。H=行ラベル × 列、I=工程（シェブロン）× 行、J=表。行・列の数は文言の数で決まり、余白は `--gap` `--pad`、高さは `--h` で統一する。
  - 却下案: 階段・3 要素・ガント・グラフ・関係図は型にしない（H・I で足りるか見る。作図は SVG を .fig に置く）。
- **文章化全体のルール: フォントは Noto Sans JP、階層ごとにインデントを入れる**（2026-11-06）
  - ユーザーの発言: 「フォントはNoto Sans JPにする。…インデントを追加する。2 shift相当で、スライドタイトルから見出し、箇条書きとインデントを入れて見やすさを追加してください。」「微修正は今後していきます。」
  - 内容: `revealjs-diagram-theme.scss` の `$font-family-sans-serif` を Noto Sans JP にした（BIZ UDPゴシックは pptx の棚卸しの値で、revealjs の指定ではなかった）。インデントは `--ind`（1em = 全角 2 字ぶん）を 1 段とし、h2（タイトル）を 0、h3/h4 と本文段落を 1 段、箇条書きを 2 段、入れ子の箇条書きを +1 段にした。
  - 追加（同日）: タイトル（h2）と次の行の間は半行ぶん空ける（`h2` の `margin-bottom: 0.5em`）。図解・格子・表も本文と同じ 1 段ぶん右から始める（`.lay` `.mx` `.tb` の `margin-left`）。
  - **実際に作るときのルール**: 下部と右側に余白を作らない。スライドの上下左右の余白が等分に近くなるよう、`--h`（高さ）、行・列の数、箱の大きさで埋める。型 A〜G は下が空きやすいので、実スライドでは `--h` 相当で調整する。
  - 注意: Noto Sans JP は閲覧する PC に入っていないと代替フォントになる（埋め込みは未対応。Open Questions ①）。値の微修正は今後。
- **基本形を確定: 基準の文字サイズ 28px、インデントは px 固定、H・J の見本は 3 行まで**（2026-11-06）
  - 根拠: 40px（Quarto の既定）では文字や図形が大きく、下がはみ出すため、ユーザーが下げるよう指示した。28px で「読める。これで fix」と確認した。H（格子）と J（表）は、3 要素を超える内容は再分割するので、見本は 3 行までとする指示があった（4 行 × 4 列の表は残してよい）。
  - 内容: 文字サイズは SCSS の `$presentation-font-size-root: 28px`。インデントは `--ind: 40px`（px 固定）を基準に、見出し（h3/h4）と段落を 1 段、箇条書きを 2.5 段（行頭記号が見出しの文字より右に来る）。タイトル（h2）の下は `margin-bottom: 0.8em`（上の 0.5em を置き換え）。格子・表の高さ `--h: 560px`（1280×720 で、タイトルの下からほぼ下端まで埋まる）。上の「1em = 全角 2 字ぶん」の `--ind` と、段数（箇条書き 2 段）はこれで置き換わった。
  - 却下案: 32px、40px の 20% 減（ユーザーが、もう少し下げたいと言った）。5 行・4 行の見本（文字サイズを下げると下が余る。実用でも再分割になる）。
- **置き場: 型・原則・落とし穴はこのノート、見本と CSS はトピックの `records/`**（2026-11-06）
  - ユーザーの発言: 「その案にします。」
  - 根拠: lessons に 20KB の見本を入れると読み込みが重くなる。拡張の作業はトピックの `docs/` が持つ。
  - 却下案: 見本と CSS を lessons のノートの本文にだけ置く。`guides/` に置く（人が見る手順書の扱いになる）。

## Facts

- 箱の骨格（Quarto の fenced div）。型ごとに `.lay` に `.lay-a` `.lay-b` `.lay-d` `.lay-e` `.lay-f` `.lay-g` を付ける。1 つの箱は `.cell`（色は `.red` `.gray` `.green`。`.red` は濃いグレーの枠）。箱の中は、札 `.tab`（raw HTML の `div`）、図 `.fig`（SVG）、文字 `.txt`（2〜3 行）の順（確認: 2026-11-05、2026-11-06。根拠: quarto render と全スライドのスクリーンショット）。

  ```markdown
  ::: {.lay .lay-a}
  ::: {.cell .gray}
  ```{=html}
  <div class="tab"><svg viewBox="0 0 24 24"><use href="#i-pc"/></svg>普段の PC</div>
  ```

  ::: {.fig}
  ```{=html}
  <svg viewBox="0 0 280 250">…</svg>
  ```
  :::
  ::: {.txt}
  短い文字（2〜3行）
  :::
  :::
  :::
  ```

- B の上段は 3 列（左・矢印・右）で、矢印は `::: {.link}` に置く。下段の全幅は `.cell.wide`。D の左の一本は `.cell.tall`（2 行ぶん）（確認: 2026-11-05、2026-11-06。根拠: 見本スライドの目視）。
- 配色は強調 `#1f5fd1`（青）、文字 `#1f2933`、枠・補助は `#9aa5b1` `#374151`、面は `#eaf1fd` `#f3f4f6`（確認: 2026-11-05。根拠: スクリーンショットで全スライドを目視）。
- 見本は 1280×720、`transition: none`、`embed-resources: true`（自己完結の HTML）。7 枚（表紙 + 6 型）で、Windows の Quarto 1.11.9 で描画できた（確認: 2026-11-06。Edge ヘッドレス）。この PC の room（`room-myenv`、Quarto 1.11.9、Chromium 1248）でも 7 枚で、同じ見え方だった（B・D・F を目視。確認: 2026-11-06。エージェント経由。PC1 の room 実機は未確認）。
- 描画の確認は Edge の headless 撮影でできる: `msedge --headless --disable-gpu --window-size=1280,720 --virtual-time-budget=4000 --screenshot=<out.png> "file:///<html のパス>#/<スライド番号 − 1>"`。スライド番号は 0 始まり（確認: 2026-11-06。H の 3 行の画像を得て目視）。
- 各スライドの目視は、Chromium のヘッドレスで撮る。`--screenshot` を付け、URL の末尾を `#/<スライド番号>`（0 始まり。0 は表紙）にする（確認: 2026-11-05。2026-11-06 は Edge で再現）。

## Gotchas

- 状況: 箱のクラス指定を `{.lay lay-a}` と書いた
  - 原因: 2 つ目の語の `.` が抜け、`lay-a` が属性名として扱われる。Quarto が「:::」の fenced div の警告を大量に出し、レイアウトも崩れる
  - 解決: `{.lay .lay-a}` のように、すべてのクラスに `.` を付ける。クラスが空のときは `{.cell}`（`{.cell .}` は文字としてそのまま出る）
- 状況: SVG の矢じりに `marker` を使い、定義を表紙スライドの非表示 SVG に置いた
  - 原因: スライドによって矢じりが消えた。reveal.js が現在以外のスライドを `display:none` にするため（仮説）
  - 解決: 矢じりは `polygon` で直接描く。`marker` を使うなら、図ごとの SVG の中に定義する。アイコンの `symbol` と `use` は、同じ非表示 SVG に置いてもすべてのスライドで表示できた（確認: 2026-11-05。根拠: 全スライドのスクリーンショット）
- 状況: 先頭の見出しの前に、非表示 SVG の raw HTML ブロックを置いた
  - 原因: 内容が 1 つの空のスライドになり、枚数が 1 枚増えた
  - 解決: 定義のブロックは、最初の見出しのスライドの内側（notes の前）に置く。見本はこの形で 7 枚になる（確認: 2026-11-06）
  - 別案（確認: 2026-11-06。Windows の Quarto 1.11.9）: 定義を HTML ファイルに出し、`format.revealjs.include-before-body` で読む。先頭スライドを消してもアイコンは残り、空スライドも増えない。先頭スライドに依存しないので、スライドの並べ替えに強い。採用済み（2026-11-06）。見本は `records/revealjs-diagram-icons.html` を読み、15 枚（表紙 + 14 型）でも空スライドは出ない（Windows の Quarto 1.11.9。確認: 2026-11-06）
- 状況: SCSS に `$presentation-font-size-main: 32px;` を書いて render したが、文字が小さくならず、5 行の格子が下にはみ出した
  - 原因: 変数名が違った。文字サイズの基準は `$presentation-font-size-root`（既定 40px）。`main` を指定しても 40px のまま描画された
  - 解決: `$presentation-font-size-root: 28px;` に直し、撮影して本文が小さくなったことを確かめた。SCSS が通って render が成功しても値が効いていないことがあるので、文字サイズを変えたら描画を撮って確かめる
- 状況: 格子と表の高さを `--h: 22.5em` などの em で指定して、文字サイズを変えても思った高さにならなかった。インデントも em だと、見出し（大きい文字）の下の箇条書きが見出しより左に出た
  - 原因: em は要素ごとの文字サイズに引きずられる。高さが効かなかった理由は不明（指定の `0.72em` が効いていなかったと見られる。仮説）
  - 解決: インデント（`--ind`）と `--h` を px の固定値にした（`40px`、`560px`）
- 状況: 行の枠（`stroke-width` 3〜4）を、`viewBox` の端いっぱいに描いた
  - 原因: 線の太さの半分が `viewBox` の外に出て、右端の枠が削れて見える
  - 解決: 未対応。`viewBox` を左右に数 px 広げる、または `.fig svg` に `overflow: visible` を付ける案がある（未確認）

## Open Questions

- 札に使うアイコンの語彙（PC、家、盾など）は、題材が変わったときにどこまで流用できるか。
- H・I・J は、見本のダミー文言で、行・列の数を変えて描画を確かめた（確認: 2026-11-06。Windows、Edge）。room と PC1 は未確認。
- 型 D・E・F・G を使った実スライドは、まだ作っていない（見本のダミーで配置だけ確かめた）。
- 見本は、PC1 の room 実機でも同じ見え方か（Windows と、この PC の room では確認済み）。
- 見本の SVG は、写真から書き起こした（アイコンの path の一部は推測で補った）。元の PC1 のファイルと差分がないか。

- 型 A〜G は、基準を 28px にしても下が空く。H・I・J と同じように高さを埋めるか。

## Next Actions

- 枠の削れの対処を実測して、Gotchas の「解決」を確定する。
- 型 D・E・F・G を 1 枚ずつ実スライドに適用して、文字量とはみ出しを確かめる（トピック `revealjs-slides` の Next Actions と同じ。作業はトピック側で行う）。

- pptx のレイアウト例は、1 本目を棚卸しして H・I・J を足した。ほかの pptx が渡されたら、同じ手順で足りない型を探す。
- PC1 の生成スクリプトがあれば、`gen_layouts.py` と見比べて取り込む（運ぶかどうかはユーザーが決める）。
- 基準を 28px にしても、型 A〜G は下が空く（H・I・J は `--h` で埋めた）。A〜G も高さを埋めるか決める（Open Questions）。
- 閲覧側の PC にフォントが無いときの崩れ（フォントの埋め込みと指定）を確かめる。
