# 計画の出力の型: 6R・憲章・成果物 WBS・マイルストーンの形と作り方の Must

[[planning-method]] の、応答の形だけを切り出したノート。これから始める取り組みの目的とゴールを共有する計画を作るときに読む。欄の詳しい定義、置き場の表、既定値は `workflow-kit/brief-plan.md`(計画を作るときだけ読む。全文は11KB)。背景は元のノート(2026-10-28 に切り出した。`topics/token-cap/records/2026-10-28-brief-mode-load.md`)。

## 作り方の Must（4つ）

1. ユーザーの「〜したい」1文(と任意の「条件:」1行)から、AI が6Rの欄を〔資料〕〔推測〕のタグつきで書く。知らないことは推測で埋めず、聞く。聞くのは依頼から決まらないものだけ(選択式。最後に「ほかに前提はありますか」の自由記述)。
2. 先に要約を返して承認を得る: **ゴール・期日・読みの分かれ目・置き場**の4点。
3. 承認後、6R → 憲章 → 成果物 WBS → マイルストーンの順に作る。6Rで止まってよい(小さな再開)。
4. 出力(憲章・WBS・マイルストーンの Markdown)と、作り方のメモ(迷った点・決めたこと)を、別ファイルにする。

## 形

- **6R**(6欄): 状況、問題意識、要求、意図・裏づけ・仮説、今回のスコープ、期待する成果。各欄は見出し1文と箇条書き3つまで。裏づけには「確かめる方法」と「確かめる時期」を添える。
- **憲章**: 名前、更新日、使命(What)、ビジネスの目的(Why)、目標(完了時期・予算・品質)、メンバー、リーダー、オーナー、必要なマイルストーン(主要3つまで)。ユーザー1人の題材ではメンバー等の欄は省いてよい。
- **成果物 WBS**: 成果物(名詞)で分解。親は子の足し算(100%ルール)。葉は1ファイルに対応させ、置き場を書く。変更の記録(日付・葉・理由)の場所を置く。
- **マイルストーン**: 置く基準は、フェーズの開始・完了、成果物の作成完了、外部やオーナーとのレビュー、プロジェクト外のイベント。日付はユーザーの待ちがあるゲートだけに置く。各確認に「確認する物(置き場と番号つきの項目)」を添える。
