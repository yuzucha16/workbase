# 抽象と具体の手順書群を、横並びの表で整理し、揃える範囲を決める

## Purpose

共通規則（抽象）と、それに従う複数の手順書（具体）を持つ体系を整理するときの、論点の出し方・分類・一貫性の揃え方を、一般化して残す。例は、8つの手順書（init / open / start / wrap / close など）と、その共通規則を持つ体系の整理。他の分類・整理作業（コマンド群、テンプレート群、規約群など）にも使える型にする。この体系の章立てへの適用は [[workflow-kit]] の「フック手順書の章立て」。

## Principles

- 抽象と具体の整理は、「項目 × 対象」の横並びの表（○ あり、△ 表現が違う・部分的、— なし）から始める。理由: 抜けとばらつきが一目で分かり、追加・削除の波及先も表の行と列で見える。
- 表の行は、現状の事実で Must と Want に分ける。Must は全対象に ○ か △ がある行、Want は — がある対象を含む行。理由: 「揃えるべきか」の線引きを、主観でなく事実で決められ、争点が減る。
- 共通部を先頭に固め、固有部は後ろに置く。例外は名前を挙げて理由を残す。理由: 読む順が揃い、「上の」「下の」の位置参照が並べ替えで反転する事故を防げる。
- 抽象側（契約・共通規則）は、具体側の事情（列名、保存先、パス）を定めず、意味と名前だけを使う。詳細は呼び出し元が定義する。理由: 契約が呼び出し元の変更で壊れ、共有物に固有の情報が混ざる。
- 手順や章への参照は、番号や「上の／下の」でなく、名前で書く。名前の実在は機械で点検する。理由: 追加・削除・並べ替えで、番号と位置がずれる。
- 点検は、機械で判定できる行（存在、順序、参照の実在、表との一致）と、人が判断する行（内容の質）に分ける。前者はスクリプトに任せ、後者は定期の見直しで事例を見る。理由: 判断が要る行まで機械化すると、誤検知で運用が止まる。
- 区分や状態のラベルは、付けることで手順や実施内容に差が出るかを根拠で確認し、差が無ければ外す。期限や判定日を伴う決定は、ラベルとは別に残す。理由: 差が無いラベルは、点検と説明の負担だけを増やす。
- 整理に入る前に、抽象側と具体側（呼び出し元）の記述の食い違いを洗い出す。理由: 前提が矛盾したままでは、揃えても食い違いが残る。
- 内容の移動や言い換えを伴う整理は、実施前に、影響する箇所（位置参照の反転、言い換える文）をユーザーに示す。実施後は、変更前後の文を文単位で機械照合し、増減が意図した差分だけであることを確認する。理由: 文脈のデグレを減らせる。
- 論点は、「現状の事実（表）→ ズレの一覧 → 選択肢・推奨・判断材料 → ユーザーの決定 → 実施 → 点検」の順で進める。ズレの一覧は毎回同じ表で再出力し、解消したものを消す。理由: 進捗が見え、決定の根拠が残る。
- 同じ規則を2か所に書かない。正本1つの原則は [[ai-output-consistency]] にあり、抽象側と具体側の関係では、具体側は正本を参照する。

## Decisions

- **一覧の肥大化は、字数の目安と「Want の行を増やさない」ルールで抑える**（2026-10-08）
  - 根拠: ユーザーが選んだ。目安は数値で判断でき、Want の行の凍結は「足すなら畳む」（[[accretion-without-pruning]]）と同じ考えで、運用が簡単。
  - 却下案: 点検済みの行を表から外してスクリプトに任せる（一覧性が下がる）。「残っているズレ」を表に置かず報告にだけ出す（経緯が残らない）。

## Facts

- 8つの手順書 × 約16項目の横並びの表を作ると、共通の章の点検では見えなかったズレ（自発実行の例外の書き方、前提の有無、記録の扱いの食い違いなど）が見つかった（確認: 2026-10-08、根拠: 表の作成と、各手順書を読んだ結果）。
- 共通規則（記録する）と、呼び出し元の運用（その種類の行は足さない）が食い違っていた（確認: 2026-10-08、根拠: 共通規則の文と、呼び出し元の記録の定義を読んだ）。
- 他のファイルからの手順参照を機械で点検すると、手順書のファイル名が無い参照が2件見つかった（確認: 2026-10-08、根拠: 点検スクリプトの出力）。
- 手順を1つ削除すると、別ファイルの「手順 5」という番号参照が、実際に1つずれた（確認: 2026-10-08、根拠: 点検スクリプトの説明文を読んだ）。
- ユーザーの指示で、全対象に ○ か △ が付いた行を Must、— がある行を Want とした（確認: 2026-10-08、根拠: ユーザーの発言）。
- 字数の目安は 5,000 字とし、例外は理由つきで表に列挙した（確認: 2026-10-08、根拠: ユーザーの決定）。
- 実物（2026-10-08 に照合）: workflow-kit の `hook-matrix.md` が、8 フック × 区分（Must / Want）の表として存在し、`tools/check-hook-outline.ps1` の実行結果は全フック OK（表と全フックの一致、他のファイルからの手順参照の実在を含む）。

## Gotchas

- **表の行の値で Must を機械判定しようとしたが、判定できなかった**: 行の値が「なし」「見本のみ」など自由な語で、○△— に揃っていなかった。値を ○△— に統一し、詳細（何を書くか）は別の表に一本化した。

## Open Questions
