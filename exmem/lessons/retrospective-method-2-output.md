# 振り返りの出力の型2（突発）: 失敗・トラブル1件のなぜなぜの章立て

[[retrospective-method-2]]（改善5）の、応答の形だけを切り出したノート。依頼の言葉（「なぜなぜで振り返って」「トラブルの再発防止」など）で、このノートだけを読み、この形で返す。やり方の全体は元のノートにあり、`brief 改善` で読む（2026-10-28 に切り出した。`topics/token-cap/records/2026-10-28-brief-mode-load.md`）。

期間を区切った定期の振り返りは、[[retrospective-method-output]] の形にする。

## 作り方の Must（3つ）

1. 事象1件と範囲を宣言し、時系列は一次記録から作る。
2. 軸は先に決めない。なぜなぜは枝を複数出してから、核の原因を1〜3個選ぶ。
3. 人の注意不足で止めず、仕組みの欠けまで掘る。施策は承認待ちとして出す。

## 章立て（章は固定）

| 章 | 見出し | 含めるもの |
|---|---|---|
| 冒頭 | 版の行 | 作成日、事象、読者、用途、状態（叩き台 / 承認済み） |
| 0 | サマリ | 3行（何が起きたか、核の原因、最優先の施策）、施策の件数と承認が要るもの、範囲と限界の一言。400字以内 |
| 1 | 事象と範囲 | 事象の宣言、影響、読んだ一次記録の表、見えない範囲 |
| 2 | 時系列 | 日付・出来事・出典の表（UTC） |
| 3 | なぜなぜの木 | 枝ごとに「なぜ → 根拠 → 次のなぜ」。止めた理由（仕組みの欠け）を枝の末尾に |
| 4 | 層の点検 | 手順 / 文書 / 分担 / 記録 / 検知 の5行。各行は 枝あり（章 3 への参照）/ 探したが無かった |
| 5 | 核の原因（1〜3個） | 原因 → 仕組みの欠け → 影響 → 選んだ理由。選ばなかった枝の一覧 |
| 6 | 施策（承認待ち） | ID / 種別（再発防止 / 検知）/ 内容 / 反映先 / 優先度 / 検証項目 / 状態 |
| 7 | 事実・解釈・推測の区別 | 推測とその根拠、1事例の限界 |
| 8 | 確認できていない点 | 見えない範囲の影響、掘り残しの可能性 |
| 9 | 出典 | 一次記録と二次を分けた表 |
| 末尾 | 遠回り・次の一手 | この分析の手戻り、施策の検証の時期 |
