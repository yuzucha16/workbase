# 作業の種別の統合と、手順書の分け方

設計の背景は [[workflow-kit]]（2026-10-27 に、追記の節を切り出した）。

`room open` の作業の種別（type）を少ない数に集約したときと、その後に種別ごとの手順書を見直したときに分かったこと。

### Principles（種別と手順書）

- 種別を統合する前に、コードがその種別を読んで分岐しているかを調べる。理由: ラベルを書くだけなら、違いは手順書だけにあり、統合の影響範囲は手順書とテストに絞れる。
- 種別の違いは、成果物の構成（サブディレクトリの組み合わせ）に落として表にしてから、統合の可否を決める。理由: 「違いは構成だけ」が事実かどうかを、基準文書の正の向き、立ち上げで聞くこと、固有の制約の3つで確かめられる。
- 種別の線は、活動（調べる、計画する、実行する）ではなく、成果物で引く。理由: 活動の分類は排他的でなく、1つの作業に複数の活動が混ざるので、作業の単位の分類には使えない。
- 曖昧な作業は、成果物の名前で種別を決め、種別をまたぐ流れは作業を分けて、前の成果物を次の入力に渡す。理由: 1つの作業の途中で種別を変えると、置き場と基準文書が途中で変わる。
- 設定や種別を廃止するときは、コードだけでなく、手順書のコマンド例と説明も同じ変更で検索して消す。理由: 廃止から3日たっても、使えないオプションの例が手順書に残っていた。
- 手順書は、読む条件が同じ内容ごとに1ファイルにする。理由: 「特定の種別のときだけ読む」と宣言した手順書に全種別共通の規約が混ざっていると、他の種別では規約が読まれず、漏れる。
- 題名と読む条件は、本文の過半の内容に合わせる。理由: 本文の約6割が別の読者向けなのに、題名と読む条件が一部の読者向けのままだと、題名を信じた読者が必要な規約を見落とす。
- 置き場の用途（どのディレクトリに何を置くか）は、構造を扱う1つの文書に置き、手順書は選び方と守ることだけを書く。理由: 用途の表と構成の図を手順書にも置くと、変更のたびに2か所を直すことになり、ずれる。
- 活動（調べる、整理する、計画する、作る、確かめる）と置き場の対応は、「目安」として表の1列に載せ、拘束しない。理由: 活動は反復して混ざるので、置き場を活動で決めると、守れない規則になる。
- 活動の分類名は、日本語の一般語で書き、暫定の概念モデルの英語名を手順書に固定しない。理由: モデルが変わったとき、手順書の直す箇所が増える。
- 検査と補助のスクリプトを別の置き場に分けるときは、「基準文書の要求・検証項目に対応するか」で分ける。理由: 「検査」という語だけでは境目が人によって変わり、同じ種類のスクリプトが両方の置き場に出る。

### Facts（種別と手順書）

- 統合前のコードは、種別を `--type` の選択肢と frontmatter への書き込みに使うだけで、種別による分岐が無かった（確認: 2026-10-24、根拠: `room.py` を検索した）。
- 外部の分類（調査と開発の2区分）は、活動の整理で排他的でないと明記されていた（確認: 2026-10-24、根拠: ユーザーが持ち込んだ分類メモを読んだ）。
- 種別の列挙は、手順書・雛形・テスト・案内の表の10か所以上に散らばっていた（確認: 2026-10-24、根拠: `grep` で一覧した）。
- 分割前の手順書は約30KBで、約19KB（63%）が全種別共通のスクリプトの規約だったが、冒頭は「`type: dev` のときだけ読む」だった（確認: 2026-10-24、根拠: 節ごとのバイト数を数えた）。
- 分割後は、種別ごとの手順書が約11KB、共通の規約が約19KBになった（確認: 2026-10-24、根拠: `wc -c`）。

### Gotchas（種別と手順書）

- 状況: 設定 `data:` を廃止して3日後、手順書にまだ `--data` 付きのコマンド例が残っていた
  - 原因: 廃止の変更が、コードとテストだけで、手順書の検索を含んでいなかった
  - 解決: 廃止したオプション名で手順書全体を検索し、例と説明を状態で決まる動きに書き直した
- 状況: 手順書の節を別ファイルへ移した後、`grep` で旧ファイル名を探すと、節名を指す参照が見つかった（案内文を生成するコード、点検スクリプトのコメント、手順書の索引、知識のノートの4種類。確認: 2026-10-24、根拠: ファイル名で `grep` した）
  - 原因: 節名の参照は、ファイル名だけでなく「節の見出し」で書かれており、移動で見出しの位置が変わった
  - 解決: 旧ファイル名で検索して参照を新しいファイルに直し、見出しの名前を変えた節は、見出しでも検索して直した。規則の経路を洗い出す方法は、[[workflow-kit-default-rules]] の Gotchas と同じ

### Open Questions（種別と手順書）

- 文書だけを成果物にする作業（`docs/` だけ）の基準文書の形は、まだ決まっていない。
