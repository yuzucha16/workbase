# AI 作業部屋: 変換の道具と room run の設計

原則と全体の判断は [[ai-isolated-work-room]]（2026-10-27 に、2026-10-21 追記の節を切り出した）。

## Principles

- 部屋の道具は、root が版を固定して入れ、AI には入れさせない。理由: 取得元と版を AI が選ぶと部屋の中身が実行ごとに変わり、AI が書き換えることもできてしまう。
- Linux の道具で完結する変換は、部屋の中で完結させ、Windows が要る範囲を狭く保つ。理由: 人の操作が残るほど、忘れて未実行になりやすい。
- 日本語の PDF や画像を作る部屋では、フォントの優先を明示する。理由: CJK のフォントは日本語・簡体字・繁体字・韓国語を同居させ、既定では簡体字が選ばれて漢字が中国式の字形になる。
- 大きな取得物は、版と SHA-256 を固定し、必要な部分だけを置き、入っていれば取り直さない。理由: 部屋の再実行のたびに数百 MB を取り直さずに済み、取得物の差し替えも検出できる。
- 人が実行する処理を AI に任せる設計では、依頼と実行の記録を、書く側で分ける。依頼は AI が書き、実行の記録は AI が書けない側だけが書く。理由: AI が「実行済み」を偽れず、実行後のスクリプトの書き換えをハッシュで検出できる。
- 実行しなかったことへの気づきは、人が思い出すことに頼らず、次に必ず使う操作に置く（作業の開始時の表示、作業を閉じるときの停止）。理由: 操作を覚えていなくても検出できる。限界: 次にその操作を使うまで分からない。
- 人が承認して実行する範囲は、1件ずつ、名前で指定し、全文を見せてから実行し、承認なしの自動実行を作らない。理由: 全体実行は成果物が変わりうる。関門が人の目だけになるので、範囲を狭めて見る量を減らす。
- AI が書いたコードを実データに対して実行する設計は、環境の保証（AI は実データを見ず、Windows に触れない）からの後退として、条件を言葉で固定する（実行前の静的検査、入力のコピーに実行、書き出しとログは AI に見えない側）。理由: 条件を固定しないと、保証が崩れる範囲が静かに広がる。
- 構造が複雑になったら、最小の版（道具を入れるだけ）を先に実装し、価値の判定で次の版に上げる。理由: 設計の議論を重ねるほど、使いこなせなくなる。今回の例は1つだけで、型にするには早いかもしれない。
- 隔離環境の Windows 向けスクリプトの作り方と検査は [[windows-script-isolated-linux]]。AI が読める場所へ自動で出すログはマスクを通らない（その節の Principles）。

## Decisions

- **部屋の変換の道具は、部屋を作る `init` で root が入れる**（2026-10-20）
  - 根拠: 証明書や Node.js と同じ扱いになり、AI が書き換えられず、同じ Area の部屋で版がそろう。
  - 却下案: AI がホームに入れる（取得元と版を AI が選ぶ）、入れない（HTML 化は Python、実行は人が毎回操作を覚える）。
- **mermaid の画像化は部屋で完結させる。Chromium は Playwright 版を使う**（2026-10-20）
  - 根拠: 作る側が最後まで持つ、というユーザーの方針。Ubuntu 26.04 の apt の chromium は使えなかった。
  - 却下案: 画像化だけ Windows で人が実行する（人の操作が残る）。
- **等幅フォント PlemolJP の取得は、使い捨ての部屋での試験が安定するまで `init` から外す**（2026-10-20）
  - 根拠: zip が約 220 MB で、試験のたびに待つ。手順は残してあり、コメントを外せば戻せる。
  - 却下案: 入れたまま試験する（毎回の待ち時間が長い）。
- **`room run` の版を3つに分ける: v1 = 道具だけを入れる、v2 = 実行を1件指定で行う `room run`（実データに使わない）、v3 = v2 に実データへの実行を足す。v1 に価値がなければ v2 に上げる**（2026-10-20）
  - 根拠: 変換と mermaid の画像化は部屋の中で完結でき、Windows が要る範囲は VBA の確認とピボットの作成に狭まる見込み。複雑になるのでユーザーが「もっと絞って」と指示した。
  - 却下案: 最初から v3 まで作る（構造が複雑になり、使いこなせない）。
- **`room run` のスコープは、1回に1件、Project 内の成果物を名前で指定する。全体実行と Area 単位の実行は作らない**（2026-10-20）
  - 根拠: 全体実行は成果物が変わりうる。
  - 却下案: Project 全体の一括実行、Area 単位の実行（成果物が変わる）。
- **スクリプトは `ai/work/run/`（使い捨てのスクリプトの置き場）、成果物は `ai/out/<成果物名>/dist/`（実データ由来は `_noai/final/<成果物名>/dist/`）に置く**（2026-10-20）
  - 根拠: 使い捨てのスクリプトは `ai/work/`、成果物は `ai/out/<成果物名>/` に一式、という既存の置き場の規則に合う。`dist/` は全 type 共通の派生物置き場で、1成果物1フォルダを保てる。
  - 却下案: 予約名のディレクトリ `ai/out/run/`（成果物が2か所に分かれる）、type ごとの構造に従う（AI が毎回判断し、上書きの事故が起きうる）。
- **v3（実データへの実行）は、静的検査・入力のコピーに実行・書き出しは AI に見えない側・ログも同じ、の条件で許す**（2026-10-20）
  - 根拠: 条件つきなら、保証の後退を許容できるとユーザーが判断した。
  - 却下案: v3 を作らず、実データは人が手で操作する（実データの Excel 処理を AI に任せられない）。

## Facts

<!-- 版依存: 一方向 / 確認: 2026-10-21 -->

- Ubuntu 26.04（resolute）の apt に `chromium` の候補は無く、`chromium-browser` は snap への移行パッケージ（`2:1snap1-0ubuntu4`）だった（確認: 2026-10-20、根拠: `apt-cache policy` の出力をユーザーが報告）。
- Playwright 1.64.1 の Chromium は、部屋で `libasound2t64` を apt で足すだけで起動した。`ldd` の `not found` は `libasound.so.2` だけだった（確認: 2026-10-20、根拠: ユーザーが貼った `ldd` と `--dump-dom` の出力）。
- `/etc/fonts/local.conf` で Noto Sans CJK JP を優先すると、Chromium の PDF に埋め込まれたフォントが `NotoSansCJKjp` になった。優先なしの LibreOffice の PDF には `NotoSansCJKsc` が埋め込まれていた（確認: 2026-10-20、根拠: ユーザーが貼った `strings` の出力）。
- LibreOffice 26.2 は、headless で xlsx の再計算（`=B2*3` が 6）と PDF 変換が通った（確認: 2026-10-20、根拠: ユーザーが貼った出力）。
- mermaid-cli 12.0.0 で作った PNG に、日本語ラベルが四角にならず出た（確認: 2026-10-20、根拠: ユーザーが画像を目で確認）。
- PlemolJP v3.1.0 の zip は約 220 MB で無圧縮、各書体は約 5.6 MB。ライセンスのファイルは zip に入っていない（確認: 2026-10-20、根拠: zip を取得して `unzip -l` で一覧した）。`room.py` は PlemolJP の取得を、コメントアウトして残している（確認: 2026-10-21、根拠: `room.py` を読んだ）。
- 部屋を作る `init` は、LibreOffice・Chromium・mermaid-cli を含めて3分27秒で通った（確認: 2026-10-20、根拠: ユーザーが貼った画面）。
- TLS 検査のある環境でも、Chromium と mermaid-cli の取得が通る（仮説）。補足: 勤務先の証明書を `--ca-cert` で入れ、Node の取得には `NODE_EXTRA_CA_CERTS` でシステムのバンドルを指しているが、その環境では試していない。
- Windows 側の実行環境（pwsh 7）は、勤務先の PC で使える（確認: 2026-10-20、根拠: ユーザーの発言）。
- LibreOffice に寄せても残る範囲は、VBA の実行確認、ピボットの作成、見た目の完全な再現（仮説）。補足: LibreOffice のピボットや VBA は Excel と結果が違う、という一般的な認識に基づく。
- 静的検査は、難読化したコードを防げず、最後の関門は人が全文を読むことになる（仮説）。補足: 実装がまだ無く、検査の実効性は試していない。`room run` は、`room.py` に実装が無い（確認: 2026-10-21、根拠: `room.py` に `cmd_run` が無いことを検索した）。

## Gotchas

- 状況: Ubuntu 26.04 の部屋で、apt で chromium を入れようとした
  - 原因: apt の chromium が snap への移行パッケージで、部屋では snap を使えない
  - 解決: Playwright の Chromium を、root が `/opt` に入れた
- 状況: `chrome --headless --dump-dom 'data:text/html,<p>日本語</p>'` の出力が文字化けした
  - 原因: `data:` URL に文字コードの指定が無く、Latin-1 として読まれた（Chromium の不具合ではない）
  - 解決: `data:text/html;charset=utf-8,…` と指定した
- 状況: Chromium の実行で `dbus ... Failed to call method` の ERROR 行が出た
  - 原因: 部屋に dbus が無い
  - 解決: 無害な警告なので無視した
- 状況: 叩き台で、スクリプトの置き場を `ai/out/win/` にした
  - 原因: Project の置き場の規則（`ai/work/` は使い捨てのスクリプト）を確かめずに決めた
  - 解決: ユーザーの指摘で `ai/work/run/` に直した

## Open Questions

- TLS 検査のある環境（勤務先の PC）で、`init` を通して Chromium と mermaid-cli の取得が通るか。
- 画像・PDF は、マスク後の語が絵になり、復元の対象にならない。マスクして復元する Project（復元の対象は `ai/out/`）では、画像・PDF をどこに置くか（`ai/work/` に置く、または復元の対象外の派生物置き場を作る）。
- PlemolJP を `init` に戻す時期。
- `room run` の `dist/` を、復元（`restore`）の対象外にする実装と、`dist/` の中の docx などの扱い。
- `room run` v2 の実装時期（v1 の価値の判定の後）。
- `room run` v3 で、静的検査をすり抜ける難読化に、どこまで備えるか。

## Next Actions

- `room run` を実装するときに、この型（依頼と記録の分離、気づく場所）を実測で見直す（2026-10-21 時点）。
