# `close` フック

呼び出し名は `close`（Project の終了）。別名は無い。呼び出し表の正本は `hooks.md`（体系の経緯は `README.md` の「フックの体系」）。

状態: **試験運用**。実測で直して育てる。

## 目的と契機

- **目的**: Project の終了であり、セッションの終了（`wrap`）ではない。
- **契機**: Project を閉じるときに、ユーザーが言う、または AI が完了条件の達成を確認して提案する。
  - 完了条件を達成した、中止を判断した、または見直し日を2回超えて更新が無いとき。
  - **完了条件を達成したら、見直し日を待たずに閉じる**。AI は、完了条件の達成を確認した時点で、`close` を提案する（「見直し日まで残す」とは提案しない）。
- **前提**: ワークスペース（PARA 構成）がある。

## 場所と書き込みの制約

- 書き込み先は、対象の Project（`projects/<名>/` から `archives/<名>/` へ移す。手順「`archives/` へ移す」）、親の Area の `README.md`（手順「未解決を整理する」「`archives/` へ移す」）、呼び出し元の記録（`docs/log.md`、`docs/decisions.md`。手順「暫定の見直し」「記録してコミットする」）だけ。
- `exmem/` は触らない。`stock` は、ユーザーが言ったときだけ実行する（手順「ナレッジ化の候補を示す」）。
- コミットは手順「記録してコミットする」に従う。push はユーザーが行う。

## 手順（順序を固定する）

1. **完了条件を確認する**: `README.md` の完了条件を、実測（コマンドと結果）で確かめる。未達なら、閉じずに、残りを Next Actions に書く。
2. **暫定の見直し**: Project で暫定にしていた決定（制約、数値、方式）を、実測で見直す。結果を `docs/decisions.md` に書き、変更するものはユーザーの承認を得る。
3. **未解決を整理する**: Next Actions と Open Questions の残りを、次の Project、親の Area（`areas/<名>/README.md`）、または破棄に振り分ける。持ち越すものは、移し先に書く。
4. **ナレッジ化の候補を示す**: `docs/decisions.md` の `未仕分け` のうち【汎用】の項目を一覧にして、ユーザーに示す。**`stock` は、ユーザーが言ったときだけ実行する**（自動で実行しない。`stock-hook.md`）。実行の有無と時期は、ユーザーが決める。
5. **状態を更新する**: `README.md` の frontmatter を `status: done`（中止は `cancelled`）、`closed: <日付>` にする。完了条件の結果（実測の数字）と、成果物の場所を、`README.md` に1段落で足す。
6. **`archives/` へ移す**: 先に、ビルド成果物を消す（`make clean` など。移したあとに未追跡のファイルが残らないようにする）。`projects/<名>/` を `archives/<名>/` に `git mv` する。**ディレクトリごとの `git mv` が失敗したら（`Permission denied`）、`git ls-files` を回して、ファイル単位で移す**（履歴は、リネームとして保たれる）。空のディレクトリが残ったら削除する。親の Area の一覧を、「完了した Project」に移し、リンクをパス付きの wikilink（`[[archives/<名>/README|…]]`）にする。ほかの参照（`docs/log.md`、`docs/decisions.md`、`events` の `project` 列など）は、パスでなく名前なので、変更は不要か、`grep` で確認する。
7. **記録してコミットする**: `docs/log.md` に、閉じたことと結果を書く（日報の入力になる形）。パスを指定して `git add` し、コミットする（push はユーザー）。

## 報告の型

1. **完了条件**: 実測（コマンドと結果）。未達なら、残りと Next Actions。
2. **暫定の見直し**: 変更した決定と、承認の有無。
3. **振り分け**: 未解決の移し先（次の Project、Area、破棄）。
4. **ナレッジ化の候補**: 【汎用】の一覧（`stock` は実行していない）。
5. **移動とコミット**: `archives/` への移動先、ハッシュと内容。
6. **改善案**（あったときだけ）: `hook-common.md` の「改善」に従う。

## 実測から分かっていること

- 手順「`archives/` へ移す」: ディレクトリごとの `git mv` は、`Permission denied` で2回失敗した（原因は未特定。シェルやセッションが作業ディレクトリを掴んでいた可能性は、2回目には無かった）。ファイル単位で移せる。
- 手順「ナレッジ化の候補を示す」: `stock` を「あとでまとめて言う」ことも多い。`close` と `stock` は切り離せる。
- 手順「暫定の見直し」: 実測が決め手になることがある（ホストでは出ず、実機の条件で依存が出た例）。
