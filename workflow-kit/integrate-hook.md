# integrate フック（別名「inboxを整理して」）

呼び出し名は integrate（随時。exmem 側）。別名は「inboxを整理して」。呼び出し表の正本は `hooks.md`。以下の「inboxを整理して」は、integrate と読み替える。

## 目的と契機

- **目的**: `exmem/inbox/` のメモを `exmem/knowledge/` に統合するためのフック。
- **契機**: ユーザーが「inboxを整理して」と言ったときだけ実行する（自発的には実行しない）。exmem 側の作業で、ソース側の `wrap` とは独立している。未統合のメモが 5 件以上たまったら、`review` の警告の目安として、このフックを勧める。

## 場所と書き込みの制約

- exmem: `$HOME\works\resources\exmem`（WSL: `/mnt/c/Users/<Windows のユーザー名>/works/resources/exmem`）。
- 書き込み先: `exmem/knowledge/`、`exmem/contexts/`、`exmem/README.md`（索引）、`exmem/tags.md`、統合したメモの削除。作業ディレクトリの `docs/` は書き換えない。
- コミットは `docs-rules.md` の「コミットと push」に従う。push はしない（使い捨ての環境は、`docs-rules.md` の「使い捨ての環境での緩和」）。コミット済みのメモ（使い捨ての環境で作られたもの）は、`git rm` で削除してコミットする。

## 手順

1. **統合する。** 下の「統合そのものの手順」に従う（実物との照合、タグの正規化、統合先の選択、`README.md` の更新、メモの削除）。照合で、実物と食い違ったものは、実物を正として、`Open Questions` に残す。環境変数や WSL への受け渡しなど、起動の経路で結果が変わるものは、エージェント経由の確認だとその旨を書き、ユーザーの通常のターミナルでの確認を `Next Actions` に残す（確定とは言い切らない）。**統合先の Decisions に写す根拠と却下案は、メモ（と元の決定）に書かれたものだけにする。** 却下案が元に無い（「未検討」など）ときは、AI が案を補わず、「却下案: 未検討（<承認の経緯>）」と書く（Decisions は、ユーザーが明示または承認したものだけ。補った却下案は、ユーザーが選んでいない案を、決定の記録に混ぜる）。
2. **メモと統合先の照合を、報告に載せる。** 統合したメモごとに、メモと統合先（`knowledge/` の該当箇所）を比べ、次の2つを挙げる。見出しの一致だけで済ませない。混入と欠落は、報告の前に、統合先を直す。
   - **メモに無い記述**（統合先に混ざった、AI が補った記述。却下案など）。
   - **メモから落ちた記述**（根拠、却下案、確認の日付と根拠）。
3. **コミットする（統合・メモの削除を1コミットにする）。** 統合先の `knowledge/`、`README.md`（索引）などの変更と、コミット済みのメモの `git rm` を、1回のコミットにする（途中までの状態が push されないようにする）。`exmem/inbox/` の未追跡のメモは、ファイルを削除する（コミットの対象外）。
4. **報告する**（下の「報告の型」）。

## 報告の型

1. **統合**: 統合したメモと、統合先のファイル。新規に作ったファイル。
2. **食い違い**: 実物と食い違ったもの（`Open Questions` に残したもの）。
3. **照合**: メモごとの「メモに無い記述」「メモから落ちた記述」と、直したもの。
4. **コミット**: ハッシュと内容。push のコマンド（実行しない）。
5. **改善案**（あったときだけ）: `hook-common.md` の「改善」に従う。

## 統合そのものの手順

`exmem/AGENTS.md` から移した（2026-10-08）。

1. inbox のメモから Principles / Decisions / Gotchas / 事実 / Open Questions を抜き出す。
2. **実物と照合する。** メモの内容は会話から生まれたもので、実物と食い違うことがある。設定ファイル・コード・コマンド出力など確認できるものは実際に見て、一致すれば「確認済み」、食い違えば実物を正として記録し、食い違いを `Open Questions` に残す。確認できないものは仮説として書く。
3. タグを `tags.md` の語彙に正規化する。
4. 該当する `knowledge/*.md` に統合する。該当がなければ新しいファイルを作る。
5. `context.md` の `Current State` / `Next Actions` / `Open Questions` を更新する。
6. 新しいファイルを作ったら `README.md` の「知識の索引」に1行足す。
7. 統合したメモを inbox から削除する。削除の前に、上の「手順」の「メモと統合先の照合」を行う。
