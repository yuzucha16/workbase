# frame フック（別名「論点出し」「課題設定」）

呼び出し名は frame。別名は「論点出し」「課題設定」。呼び出し表の正本は `hooks.md`。ユーザーが言ったときだけ実行する（自発的には実行しない）。型の正本は `exmem/lessons/issue-extraction-output.md`（貼り付け用プロンプト）。

## 目的と契機

- **目的**: 作業の前に、決めておくべき論点だけを洗い出し、判断（決・任・後・確・聞）を付けて決定メモにする。作業はしない。毎回プロンプトを貼る手間を省くための合言葉。
- **契機**: ユーザーが「論点出し」「課題設定」または `frame` と言ったときだけ。合言葉の後ろの文は、型の「私の入力」に当てる。`plan` の手順 B の論点出しも、同じ型を使う。
- **前提**: 型のノートが読める（読めないときは、記憶で代用せず、ユーザーに伝えて止まる）。

## 場所と書き込みの制約

- 起動できる領域は `hooks.md` の「領域とフックの権限」に従う。
- ファイルは書かない。出力は会話に出すだけ。決定メモを置く場所は、ユーザーが決める（部屋では `ai/docs/decisions.md` などに人が運ぶ）。

## 手順

1. **型を読む**: `exmem/lessons/issue-extraction-output.md` の「## 貼り付け用プロンプト」から「## 関連」の手前までを読む（`Grep` で行を探し、`offset` と `limit` で読む。全文は読まない）。
2. **入力を当てる**: 合言葉の後ろの文を、型の「私の入力」の欄に当てる。分からない欄は空のままにし、聞き返さない（空欄も論点にする）。`plan` から呼ばれたときは、6R の未決・裏づけを入力にする。
3. **論点を出す**: 型の「やってほしいこと」「守ること」「出力の型」（A〜D）に従う。作業・解決策の設計はしない。
4. **決定メモにする**: ユーザーが判断（決・任・後・確・聞）を返したら、型の「私が判断を返したら」に従って決定メモを作る。確・聞が 0 なら、そのまま作業セッションへ貼れると伝える。
5. **フィードバック**: 「フィードバック」と言われたら、型の「フィードバックを求められたとき」に従い、1 行だけ出す。

## 報告の型

共通の項目（`hook-common.md` の「報告の型」の節だけ読む。コミット、次にやること、固有の項目、ユーザーに求めることの順）を報告する。このフックでの追記:

- **ユーザーに求めること**: 各 ID への判断（決・任・後・確・聞）。決定メモのあとは、メモを貼る作業セッションの開始。
- **コミット**: このフックはコミットしないので、「なし」と書く。
- **次にやること**: 確・聞があれば別セッションで確かめる。無ければ作業（`brief` または作業の依頼）。

固有の項目（「次にやること」の後、「ユーザーに求めること」の前）:

1. **論点の表**: 型の A〜D（入力の読み、論点の表、その他、判断の返し方）。判断を受けたあとは、決定メモ。
