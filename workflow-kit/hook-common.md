# フック共通の規則

全フック（`*-hook.md`）に共通する規則の正本。各フックには書き写さず、ここを指す。章立ての共通部（`目的と契機` → `場所と書き込みの制約` → `手順` → `報告の型`）と、以下の規則は、`tools/check-hook-outline.ps1` が点検する。

## 冒頭の定型

各フックの先頭（最初の H2 の前）に置く。

- 呼び出し名と別名。**呼び出し表の正本は `hooks.md`**（フックの側に表の写しを作らない）。
- ユーザーが言ったときだけ実行する（自発的には実行しない）。例外（`open` を `start` が案内する、`close` を AI が提案する、`review` を勧めるなど）は、そのフックに書く。

## 目的と契機

最初の共通章。次の3項目を、この順で書く。既存の文を移すだけで、書かれていないことは書かない（該当が無い項目は、置かない）。項目の順（目的 → 契機 → 前提）は点検スクリプトが見る。

- **目的**: このフックが何のためにあるか（3文まで）。運用の方針（出力を固定してある、見本に合わせる）や経緯は、目的に書かず、`手順` の冒頭に書く。
- **契機**: いつ実行するか（誰が言う、いつ提案・案内する、頻度）。
- **前提**: 動くために必要な状態（例: ワークスペースがある）。

## 章の並び

共通4章（`目的と契機` → `場所と書き込みの制約` → `手順` → `報告の型`）を、この順で、先に置く。**固有の章は、`報告の型` より後ろに置く。** 例外は2つ: `入力`（手順の入力。制約と手順の間）と、init の `導入項目の一覧`（目次を兼ねる。`目的と契機` の直後）。固有の章のうち、「改善」の固有の確認項目を書く `このフックの改善` の章は、あるフックだけが持ち、固有の章の先頭に置く（次の「改善」）。

## 見出し

H2 の見出しは名前だけにする（括弧の注記を付けない）。日付、決定者、出典、状態は、本文の1行目に書く。見出しの名前で他から参照するため。H3 の括弧は、範囲を示す名前の一部なので許す。

## 報告の型

番号つきのリストにし、各項目を太字のラベルで始める。番号は連番にし、最後の項目を「改善案」にする（形式は点検スクリプトが見る）。リストの前に、1行の導入文を置いてよい。

## 手順の参照

手順を指すときは、番号でなく、手順の太字の見出しの名前で書く（例: 手順「記録する」）。手順を足す・消す・入れ替えても、参照が壊れないようにするため。名前は見出しの先頭と一致させる。番号参照が無いことと、名前が同じファイルの手順に実在することは、点検スクリプトが見る。他のファイル（README、`tools/` など）から指すときは、フックのファイル名を添えて `stock-hook.md` の手順「…」の形で書く（ファイル名が無い、または手順が無いと、点検スクリプトが検出する）。この表の「手順」列も、行のフックの手順を指す。

## 改善

報告の型の末尾に「改善案（あったときだけ）」を置き、次の流れに従う。無ければ何も書かない（「改善案なし」とは書かない）。そのフック固有の確認項目（誤検知を見るなど）がある場合だけ、`このフックの改善` の章を置き、固有の確認項目だけを書く（章の先頭で、この節を指す）。

1. **提案**: 実行後に、手順で曖昧だった点・迷った点があれば、1〜3点を `場所 / 問題 / 案` の形で提案する。迷った点があったときだけ出す。
2. **承認と修正**: ユーザーが承認したら、kit の該当ファイル（`tools/` を含む）を直し、`improvements.md` に1行足す（却下も理由つきで残す）。理由はコミットメッセージにも書く。呼び出し元の `AGENTS.md` にコピーを作らない。
3. **記録**: 改善案を記録するかは、呼び出し元の定義に従う（`hooks.md` の「任意の記録」。定められていなければ記録しない）。

## 承認

**ユーザーの承認なしに、kit（`tools/` を含む）を書き換えない。** 例外は `wrap-hook.md` の「自動採用の規則」の節の項目だけ（範囲と手順は同ファイルの「自動採用の範囲」。安全規則は対象外）。`review` は、週1回のその場の承認が、改善案の個別の承認に代わる（`review-hook.md`）。

## 記録

フックが書く「任意の記録」（`events` `sessions` `reviews`。名前と契約は `hooks.md`）の一覧。保存先と列は、呼び出し元が定める。定められていなければ記録しない（存在を確かめてから書く）。詳細（時機、種別）は、各フックの手順に書く。ここは、どのフックが何を書くかの索引で、フックを足す・消すときの更新先。

| フック | 書く記録 | 手順 |
|---|---|---|
| `init` | なし | |
| `open` | `events`: 質問ごとの行 | 手順「記録する」 |
| `start` | `events`: 質問ごとの行（`kind=interview`）、後から出た前提（`kind=gap`） | 手順「記録する」 |
| `wrap` | 終了時の1問の答え（記録先は呼び出し元の `AGENTS.md` が定める）。自動採用の記録は、呼び出し元の定義に従う（停止中） | 報告の型の「終了時の1問」、「自動採用の範囲」 |
| `close` | なし | |
| `stock` | なし | |
| `integrate` | なし | |
| `review` | `reviews`: 1回につき1行。入力として `events` と `sessions` を読む | 手順「指標を足す」 |

再伝達（`again`）は、フックでなく呼び出し元の規則で足す。

## フックを足す・消すとき

1. `hooks.md` の呼び出し表に行を足す・消す。
2. `README.md` のファイル表の行と、連鎖・体系の記述を合わせる。
3. 冒頭の定型と、共通の4章を置く（足すとき）。参照している手順書（`wrap-hook.md` の自動採用の範囲、`init-hook.md` の導入項目の一覧、`templates/` の `AGENTS.md` など）を `grep` で探して合わせる（消すとき）。
4. 上の「記録」の表に行を足す・消す。
5. `hook-matrix.md` の列（フック名）と、各行の値、字数を更新する。章や方針を変えたときも同じ。
6. `improvements.md` に1行足す。
7. `pwsh -NoProfile -File tools/check-hook-outline.ps1` を実行する。1〜4 のうち、表の過不足、章立て、冒頭の定型、記録の表の行、`hook-matrix.md` の列は、ここで漏れが分かる。
