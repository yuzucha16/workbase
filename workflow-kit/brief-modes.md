# brief の引数つきモード

`brief-hook.md` の「引数つきモード」の本体。`brief 解決` `brief 改善` `brief 変更` `brief 調査` `brief 計画` と言われたときだけ読む（引数なしの `brief` では読まない。2026-10-26 に `brief-hook.md` から切り出した。読み込みを抑えるため。`topics/token-cap/`）。以下の「手順『事前確認』」は、`brief-hook.md` の手順 1。

## 解決・改善・変更

`brief 解決`（別名「解決で始めて」）、`brief 改善`（「改善で始めて」）、`brief 変更`（「変更で始めて」）は、インタビューの代わりに、進め方（exmem の `lessons/`）を選んで始める。試験運用（実測してから、インタビューとの関係を決める）。

1. `brief-hook.md` の手順「事前確認」を行う（`log.md` の読み込み、期日、`review` と `review 消化` の提案）。
2. ゴールを1文で聞く（Next Actions の候補つき。`変更` は、変更する成果物と内容）。「触ってよい範囲」は既定（この Project の中だけ）を宣言し、広げる必要があるときだけ聞く。
3. `methods.md` の該当の表を読み、「選ぶ基準」から Recommended を決めて、やり方を1問で選ばせる。`変更` はやり方が変更1だけなので選ばせず、前提チェック（基準文書の有無）から始める。
4. 選んだやり方の骨子（`methods.md`）と、右端のノート（`exmem/lessons/`）を読み、その手順で作業する。要約は、ゴール・やり方・触ってよい範囲の3点を返す（`変更` は基準文書の有無も）。
5. `brief-hook.md` の手順「記録する」は、通常の `brief` と同じ。

## `brief 調査`

`brief 調査`（別名「調査で始めて」）は、調べて Markdown にまとめるときの進め方。試験運用。

1. `brief-hook.md` の手順「事前確認」を行う（`review` と `review 消化` の提案は省く）。
2. 主題または依頼を1文で聞く（Next Actions の候補があれば添える）。`methods.md` の「調査」の「選ぶ基準」から Recommended を決め、やり方（調査1: 説明する／調査2: 実行できる手順書）を1問で選ばせる（言われていれば聞かず、宣言する）。想定読者は既定（依頼した本人）を宣言する。読者が他にいる、または業務の調査のときだけ、読者と範囲を聞く（Project にするなら `inv` type）。
3. `methods.md` の「調査」と、選んだやり方のノート（`research-method` または `research-method-2`）を読む。**A 仕込み**: ノートの Facts のひな形を当てはめて宣言し（依頼が単一の問いなら、ひな形でなく 結論 / 確認できなかった点 / 出典 の章立てでよい）、聞くのは、`methods.md` の A の Must のうち依頼から決まらないものと、出力先だけ（選択式、最後に「ほかに前提はありますか」の自由記述。選択肢は `methods.md` の置き場。聞けないときは、呼び出し元が指定した場所。無ければ会話の中に出し、判断の記録に書く）。品質条件、前提・制約、触ってよい範囲（既定: 成果物1ファイルだけ）は聞かずに宣言する。
4. 要約は、主題・読者・章立て・品質条件の4点を返す（宣言した前提・制約、触ってよい範囲を添える）。承認されたら **B 調査プロセス**に進む（依頼者が主題・問い・成果物の形・完了条件・範囲を先に渡し、止めずに進めるよう言ったときは、要約を返さずに進めてよい。要約の4点は成果物の冒頭に書き、宣言した前提を明記する。対話の相手がいないときは、要約を成果物の末尾に「判断の記録」として書き、承認を待たずに進む）。成果物は Markdown のファイルにする。
5. `brief-hook.md` の手順「記録する」は、通常の `brief` と同じ。

## `brief 計画`

`brief 計画`（別名「計画で始めて」）は、取り組みの目的とゴールを共有する計画（6R → 憲章 → 成果物 WBS → マイルストーン）を作るときの進め方。試験運用。

1. `brief-hook.md` の手順「事前確認」を行う（`review` と `review 消化` の提案は省く）。
2. 「〜したい」の1文（と、任意の「条件:」1行）を聞く。`methods.md` の「計画」と、`brief-plan.md`、`planning-method`（`exmem/lessons/`）を読む。
3. `brief-plan.md` の A を宣言し、依頼から決まらないものだけ聞く。要約は、ゴール・期日・読みの分かれ目・置き場の4点を返す。承認されたら B に進む。
4. `brief-hook.md` の手順「記録する」は、通常の `brief` と同じ。
