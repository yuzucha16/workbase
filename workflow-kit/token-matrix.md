# トークン消費の星取り表（review の自己採点）

kit と exmem のルール・仕組みが、トークン消費を抑える4つの観点をどれだけ押さえているかの表。週1回の `review` が、`review-hook.md` の入力「トークン消費の自己採点」で採点し直す。考え方は exmem の `lessons/improvement-coverage-matrix.md`（改善のやり方3）。

- **切る**: 会話を短く切り、新しい会話で始める（履歴は毎ターン再送される）。
- **絞る**: ツール出力を絞り、ファイルを丸ごと読まない。
- **予算**: 毎回読むもの（常駐）に字数の予算を置く。
- **外部化**: 状態をファイルに書き出し、引継ぎはそこだけ読む。

記号: ◎ 直接効く（数値・手順・スクリプトで具体的）、○ 効く（方針として書いてある）、△ 部分的・間接的、空欄 該当なし。
効き方: **強制** = スクリプトや起動の仕組みが行う。**手順** = 合言葉のフックの手順にある。**常駐** = 毎回読む規約にある。**知識** = `exmem/lessons/` にあるだけ。

## 採点のしかた

- 点: ◎ = 3、○ = 2、△ = 1。列ごとに合計し、4列の合計も出す。
- 前回の点（呼び出し元の `reviews` の前回の行。無ければ下の「点の履歴」の最終行）より、どれかの列が下がったら、見直しの対象にする。
- 採点し直すのは、前回の採点のコミットから変わったファイルの行と、新しく足されたルール・仕組みだけ（`git diff --stat <前回のコミット>..HEAD -- workflow-kit exmem` で確かめる）。全行を読み直さない。
- 行が消えた・記号が下がったときは、理由（畳んだ、書き換えた）を、点の履歴のメモに書く。
