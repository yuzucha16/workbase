## 区分（Must と Want）

- **Must**: 全フックに ○ か △ が付いている行（— が無い行）。満たさないフックがあれば、欠陥として直す案を出す。点検スクリプトが見る行は、`review` が実行して確認する。
- **Want**: — のフックがある行。足すかどうかは、重さ（字数の増え方）と複雑性（影響する参照・点検の数）で決める。足さなくてよい（フック固有の行を含む）。
- Must の行は、新しいフックにも求める。行が全フックで ○ か △ になったら、Must に上げる（表の「区分」を直す）。

## 肥大化の抑制（2026-10-08 ユーザーの決定）

- **字数の目安**: 各フックの本体（`*-hook.md`）は 5,000 字までを目安にする。超えるフックは、Want として畳む候補にする（`review` が測る）。
- **字数の例外**: stock（8.8k。手順の例外の細則と書き方が、頻繁に使うために同居している）、init（6.3k。任意の2章は別ファイルに分離済み）。例外を増やすときは、理由をここに書く。
- **Want の行は増やさない**: 表に Want の行を足すときは、既存の Want の行を1つ畳む（規模の凍結と同じ考え方）。Must の行は、足してよい。

2. **「前提」項目**: open と close だけが書く。書かれていないことは書かない約束なので、未記載のまま。
3. **承認が要る操作の明記**: 制約に書くフックと、書かないか部分的なフックが混在。
4. **自己点検**: init と stock だけ。
5. **実測・未決**: open、close、start に偏る。
6. **wrap の自動採用**: 停止中の節が残る。呼び出し元の記録の定義に、自動採用の行を足す記述と、改善案の行を足さない記述の矛盾がある。11-08 の判定で整理する。
7. **自発実行の例外の書き方**: open、close、review、start の例外が、契機の文に散在。点検対象外。
8. **点検対象外**: 承認の明記、前提、自己点検の有無は、フック固有か未記載かの区別がつかないため、点検していない。
