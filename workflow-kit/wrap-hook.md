# wrap フック（別名「終了処理して」）

呼び出し名は wrap。別名は「終了処理して」。呼び出し表の正本は `hooks.md`。以下の「終了処理して」は、wrap と読み替える。

## 目的と契機

- **目的**: 作業の終わりに行う処理を、順序を固定して1つにまとめたフック。次のセッション（別の端末やクラウドを含む）が、言い直しなしに再開できるようにする。
- **契機**: ユーザーが「終了処理して」と言ったときだけ実行する（自発的には実行しない）。ソース側（作業ディレクトリ）の終了処理で、exmem 側の統合（`integrate-hook.md`）とは独立している。

## 場所と書き込みの制約

- 起動できる領域は `hooks.md` の「領域とフックの権限」に従う（部屋での扱いは `room-context.md`）。
- 書き込み先: `docs/`（`docs-rules.md`）と、作業ディレクトリのコミットだけ。`exmem/lessons/` などは触らない（統合は `integrate-hook.md`）。`exmem/inbox/` のメモを作るのは `stock-hook.md`（このフックは作らない）。
- 既存のファイル: `docs/log.md` は現在状態に上書きする。経緯の記録先と `decisions.md` は追記する。
- コミットと push は `hook-common.md` の「コミットと push」に従う（部屋では、コミットと push は人が行う）。
- 手順の途中で承認が要るもの（既存ファイルの差分、リスクや制約が生まれる変更）は、`docs-rules.md` に従って、先にユーザーへ確認する。

## 手順

手順は 3 段階（現在状態の更新、昇格の案、コミットと push）と報告に絞ってある。各手順の中身は、既存の正本（`docs-rules.md`）を参照し、ここに複製しない。

1. **対象を特定する。** 既定は、このセッションで作業した単位（起動した単位、または「<名前> の続き」で読みに行った単位。`hooks.md` の「起動する場所」）の `docs/` と、この作業で変更したリポジトリの `docs/`。複数のリポジトリにまたがるときは、すべてを対象にする（`hooks.md` の「領域とフックの権限」の型2）。Project・Area が自分の `docs/` を持つとき（`projects/` `areas/` `archives/` 配下）は、それも別の対象に数える。変更したリポジトリに `docs/` が無く、そのリポジトリの `AGENTS.md` が `wrap` の既定の対象を定めていれば、それを対象にする。リポジトリの外だけを変えたとき、または変更したリポジトリに `docs/` も既定の対象も無いときは、親の works の `docs/`、それも無ければ、Claude Code を開いた作業ディレクトリの `docs/` を対象にする（別のリポジトリなので、そのリポジトリでコミットする）。exmem だけで進めた作業は、該当する `exmem/lessons/` のノートの `Open Questions` / `Next Actions` を更新する。どれも無ければ、この手順を省略して、報告に書く。
2. **現在状態を更新する。** `docs/log.md` を、次のセッションが読むだけで再開できる現在状態に**上書き**する（Next Actions、Open Questions）。経緯を残す場所が、呼び出し元の `AGENTS.md` にあれば、そこへ追記する。`decisions.md` は、ユーザーが明示または承認した決定があったときだけ書く（`docs-rules.md`）。呼び出し元の `AGENTS.md` が定める追加の手順（指標の記録など）は、続けて行う。
3. **昇格の案を出す。** このセッションで、ユーザーが同じことを言い直した、または新しい恒久的な前提が出たなら、`AGENTS.md` か知識への昇格の案を、1行で出す（承認制）。まとまった知識化は、ユーザーが「ナレッジ化して」と言ったときに `stock-hook.md` で行う。部屋の中の扱いは `room-context.md`。
4. **コミットする。** `hook-common.md` の「コミットと push」に従う（コミットの後、許可リストにあれば push する）。
5. **報告する**（下の「報告の型」）。

## 報告の型

共通の項目（`hook-common.md` の「報告の型」。ユーザーに求めること、コミットを先に、次にやることを最後に）を報告する。このフックでの追記:

- **ユーザーに求めること**: 昇格の案があれば1行（承認制。手順「昇格の案を出す」）。`review` を勧める条件を満たすときは、勧める（`hook-common.md` の「他のフックを勧める条件」）。
- **次にやること**: `wrap` は作業の区切りなので、切るを既定の推奨にする（続ける条件を満たすときを除く）。

続けて、固有の項目を次の順で報告する。

1. **更新した `docs/`**: パスと、変更の要点（2〜3行）。

## このフックの改善

流れと承認は `hook-common.md` の「改善」「承認」。このフックでは、次も対象にする。

- 順序で迷った点。
- 手順の間で重複した作業。
- コンテキストが膨らんだ箇所。
